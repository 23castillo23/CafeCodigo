Canalizaciones — Pipes |
1:11:52 — Conectar comandos para crear cadenas de procesamiento poderosas

El pipe | (barra vertical) conecta la salida de un comando con la entrada del siguiente. Es una de las ideas más poderosas de Unix: cada comando hace una cosa pequeña y bien, y los pipes los encadenan para hacer cosas complejas.

Cómo fluye la información

ls -la
genera listado
|
grep ".html"
filtra líneas
|
sort
ordena
|
head -5
primeros 5
pipes en acción
# Listar y filtrar solo archivos HTML $ ls | grep ".html" index.html contacto.html # Contar cuántos archivos hay en la carpeta $ ls | wc -l 42 # Ver los procesos y filtrar por nombre $ ps aux | grep node hugo 12345 0.5 1.2 /usr/bin/node server.js # Ver el historial y buscar un comando específico $ history | grep git # Los 10 archivos más pesados en la carpeta $ du -sh * | sort -rh | head -10 # Contar líneas de todos los archivos .js $ cat *.js | wc -l 1847 # Ver errores del sistema en tiempo real $ tail -f /var/log/syslog | grep ERROR

Comandos más usados con pipes

wc
Word Count
Cuenta líneas, palabras o caracteres
ls | wc -l → cuenta archivos cat file.txt | wc -w → cuenta palabras
sort
Sort
Ordena líneas alfabéticamente o numéricamente
cat nombres.txt | sort cat nombres.txt | sort -r (inverso)
uniq
Unique
Elimina líneas duplicadas consecutivas
cat lista.txt | sort | uniq cat lista.txt | sort | uniq -c (cuenta)
cut
Cut
Extrae columnas o caracteres de cada línea
cat data.csv | cut -d',' -f1 (extrae la primera columna)
tr
TRanslate
Traduce o elimina caracteres
echo "hola" | tr 'a-z' 'A-Z' → HOLA
tee
Tee
Divide la salida: va a pantalla Y a un archivo
ls | tee lista.txt (muestra en pantalla y guarda)
🔍
grep — El comando de búsqueda más poderoso
Filtrar líneas que coincidan con un patrón — imprescindible con pipes

grep busca texto dentro de archivos o en la entrada que le llega por pipe. Filtra solo las líneas que contienen el patrón que le dices. Es el compañero inseparable del pipe.

grep — usos fundamentales
# Buscar en un archivo $ grep "error" app.log 2025-06-15 10:32:01 ERROR: conexión fallida 2025-06-15 11:05:44 ERROR: timeout en la base de datos # Ignorar mayúsculas/minúsculas $ grep -i "error" app.log # encuentra Error, ERROR, error # Mostrar el número de línea $ grep -n "function" app.js # muestra: 42: function saludar() # Buscar recursivamente en todas las subcarpetas $ grep -r "TODO" ./src # busca en todos los archivos de src/ # Invertir: mostrar líneas que NO contienen el patrón $ grep -v "DEBUG" app.log # todo excepto las líneas con DEBUG # Contar cuántas líneas coinciden $ grep -c "error" app.log 2 # Mostrar contexto: 2 líneas antes y después $ grep -C 2 "error" app.log # Con pipe: filtrar salida de otro comando $ ps aux | grep nginx $ history | grep docker $ cat /etc/hosts | grep localhost

🟢 grep -r es el buscador de código más rápido

Cuando necesitas encontrar dónde está definida una función o dónde se usa una variable en un proyecto: grep -rn "nombreFuncion" ./src. Te dice el archivo y la línea exacta. Más rápido que buscar en el editor para proyectos grandes.

Redirección de entrada y salida
Controlar de dónde vienen y a dónde van los datos

Cada proceso en Linux tiene tres canales de comunicación: stdin (entrada), stdout (salida estándar) y stderr (salida de errores). Los operadores de redirección te permiten controlarlos.

redirección completa
# stdout (salida normal) → archivo $ ls > lista.txt # sobreescribe lista.txt $ ls >> lista.txt # agrega al final de lista.txt # stderr (errores) → archivo $ ls carpeta-falsa 2> errores.txt # guarda el error, no se muestra en pantalla # stdout Y stderr → mismo archivo $ comando > todo.txt 2>&1 # todo junto en un archivo $ comando &> todo.txt # forma abreviada (bash moderno) # stdin (entrada) ← desde archivo $ sort < nombres.txt # sort lee del archivo en vez de teclado # /dev/null — el agujero negro de Linux $ comando > /dev/null 2>&1 # descarta TODO (stdout y stderr) # Útil para ejecutar comandos silenciosos en scripts
OperadorQué hace
>Redirige stdout a un archivo (sobreescribe)
>>Redirige stdout a un archivo (agrega al final)
2>Redirige stderr (errores) a un archivo
2>>Agrega stderr al final de un archivo
> archivo 2>&1Redirige stdout Y stderr al mismo archivo
&>Shortcut de lo anterior (bash moderno)
<Lee stdin desde un archivo en vez del teclado
/dev/nullArchivo especial que descarta todo lo que recibe

Comodines — Wildcards
1:27:03 — Patrones para referenciar múltiples archivos a la vez

Los comodines son caracteres especiales que la shell expande antes de ejecutar el comando. Permiten referenciar múltiples archivos con un solo patrón sin tener que escribirlos uno a uno.

Los 3 comodines fundamentales

comodines * ? [ ]
# * — cualquier cosa (0 o más caracteres) $ ls *.html # todos los archivos .html index.html contacto.html about.html $ ls img* # todo lo que empieza con "img" img img-backup img2024 $ rm *.log # elimina todos los .log $ cp *.css backup/ # copia todos los .css a backup/ # ? — exactamente un carácter cualquiera $ ls archivo?.txt # archivo1.txt, archivoa.txt... (1 carácter) archivo1.txt archivoa.txt $ ls ????.html # archivos .html con nombre de 4 letras home.html main.html # [ ] — uno de los caracteres dentro de los corchetes $ ls archivo[123].txt # archivo1.txt, archivo2.txt, archivo3.txt archivo1.txt archivo2.txt archivo3.txt $ ls [aeiou]* # archivos que empiezan con vocal $ ls [a-z]* # archivos que empiezan con letra minúscula $ ls [!0-9]* # archivos que NO empiezan con número (! niega)

Patrones visuales de los comodines

*.html → index.html, about.html, contacto.html
foto?.jpg → foto1.jpg, fotoa.jpg (no foto12.jpg)
img[0-9].png → img0.png, img5.png, img9.png
guia-parte-* → guia-parte-A.html, guia-parte-B.html, guia-parte-C.html
*[!.html] → todo lo que NO termina en .html

⚡ Cuidado con rm + comodines

Antes de ejecutar rm *.txt, prueba primero con ls *.txt para ver exactamente qué archivos van a ser afectados. El comodín * a veces coincide con más archivos de los que esperas — y con rm no hay papelera.

Expansiones — Bash expande antes de ejecutar
1:31:09 — La shell transforma lo que escribes antes de ejecutarlo

Las expansiones ocurren antes de que la shell ejecute cualquier comando. Bash ve lo que escribiste, lo transforma (expande) y luego ejecuta el resultado. Entender esto explica muchos comportamientos "mágicos" de la terminal.

1. Expansión de llaves { } — Brace Expansion

expansión de llaves
# Genera múltiples strings de una vez $ echo {a,b,c} a b c $ echo archivo{1,2,3}.txt archivo1.txt archivo2.txt archivo3.txt # Crear múltiples archivos de una sola vez $ touch {index,about,contacto}.html # Crea: index.html about.html contacto.html # Crear estructura de carpetas compleja $ mkdir -p proyecto/{src/{css,js,img},docs,tests} # Crea: proyecto/src/css proyecto/src/js proyecto/src/img # proyecto/docs proyecto/tests # Rango numérico $ echo {1..5} 1 2 3 4 5 $ echo {01..10} 01 02 03 04 05 06 07 08 09 10 # Rango de letras $ echo {a..z} a b c d e f g h i j k l m n o p q r s t u v w x y z # Crear 10 archivos de log numerados $ touch log-{001..010}.txt

2. Expansión de variables $ — Parameter Expansion

expansión de variables
# Variables de entorno del sistema $ echo $HOME # tu directorio home /home/hugo $ echo $USER # tu nombre de usuario hugo $ echo $PWD # directorio actual (igual que pwd) /home/hugo/proyectos $ echo $PATH # rutas donde la shell busca ejecutables $ echo $SHELL # tu shell activa /bin/bash # Crear y usar tus propias variables $ NOMBRE="Hugo" $ echo "Hola $NOMBRE" Hola Hugo $ PROYECTO="/home/hugo/mi-web" $ cd $PROYECTO # usa la variable como ruta $ ls $PROYECTO/src

3. Sustitución de comandos $( ) — Command Substitution

sustitución de comandos
# $() ejecuta el comando adentro y usa su resultado $ echo "Hoy es $(date)" Hoy es lun jun 15 10:30:00 CST 2025 $ echo "Estoy en: $(pwd)" Estoy en: /home/hugo/proyectos # Guardar resultado en una variable $ ARCHIVOS=$(ls | wc -l) $ echo "Hay $ARCHIVOS archivos aquí" Hay 12 archivos aquí # Usar en nombres de archivo (útil en scripts) $ cp backup.sql backup-$(date +%Y%m%d).sql # Crea: backup-20250615.sql

4. Expansión aritmética $(( ))

aritmética en bash
$ echo $((10 + 5)) 15 $ echo $((100 / 4)) 25 $ PRECIO=150 $ echo "Con descuento: $((PRECIO * 80 / 100))" Con descuento: 120

Cancelar Expansiones — Quoting
1:39:01 — Cómo decirle a bash que NO expanda ciertos caracteres

A veces quieres que la shell trate un carácter especial como texto literal y no como instrucción. Los mecanismos de quoting (comillas) controlan exactamente esto.

comillas dobles, simples y backslash
############################################ # COMILLAS DOBLES " " — protegen parcialmente # Evitan: * ? {} expansión de palabras # Permiten: $VAR $() $(()) (expansiones de variable) ############################################ $ NOMBRE="Hugo" $ echo "Hola $NOMBRE, tienes $(ls | wc -l) archivos" Hola Hugo, tienes 5 archivos # Los * no se expanden dentro de comillas dobles $ echo "*.html" *.html # literal, no lista archivos ############################################ # COMILLAS SIMPLES ' ' — protección total # Todo adentro es literal — sin excepciones ############################################ $ echo 'Hola $NOMBRE, tienes $(ls) archivos' Hola $NOMBRE, tienes $(ls) archivos # todo literal ############################################ # BACKSLASH \ — escapa el siguiente carácter ############################################ $ echo El precio es \$100 El precio es $100 # el $ no se expande $ echo Línea1\ > Línea2 # \ al final continúa el comando en la línea siguiente Línea1Línea2 # Útil para comandos muy largos: $ curl -X POST \ > -H "Content-Type: application/json" \ > -d '{"nombre": "Hugo"}' \ > https://api.ejemplo.com/datos
MecanismoQué protegeQué permite
"comillas dobles"Espacios, *, ?, {}, división de palabras$VAR, $(), $(()) — expansiones de variables
'comillas simples'TODO — protección absolutaNada — todo es literal
\ backslashEl siguiente carácter únicoTodo lo demás sigue expandiéndose

🟢 Regla práctica

  • Usa comillas dobles cuando quieras incluir variables en un string: "Hola $NOMBRE"
  • Usa comillas simples cuando todo deba ser literal: contraseñas, regex, texto con $ o !
  • Usa backslash para continuar comandos largos en varias líneas o escapar un carácter puntual

Trucos de teclado — Readline
1:45:05 — Los atajos que multiplican tu velocidad en la terminal

La mayoría de shells usan la librería Readline para manejar la entrada de texto. Sus atajos de teclado son los mismos en bash, zsh y muchos otros programas de terminal. Aprenderlos transforma tu flujo de trabajo.

Movimiento en la línea de comandos

Ctrl+AIr al inicio de la línea
Ctrl+EIr al final de la línea
Alt+FAvanzar una palabra hacia adelante
Alt+BRetroceder una palabra hacia atrás
Ctrl+FAvanzar un carácter (→)
Ctrl+BRetroceder un carácter (←)

Edición en la línea de comandos

Ctrl+UBorrar desde el cursor hasta el inicio
Ctrl+KBorrar desde el cursor hasta el final
Ctrl+WBorrar la palabra anterior al cursor
Alt+DBorrar la palabra siguiente al cursor
Ctrl+YPegar lo último que se borró (yank)
Ctrl+TIntercambiar el carácter actual con el anterior
Alt+UPoner en MAYÚSCULAS hasta el final de la palabra
Alt+LPoner en minúsculas hasta el final de la palabra

Historial de comandos

↑ / ↓Navegar el historial de comandos
Ctrl+RBúsqueda incremental en el historial (el más útil)
Ctrl+PComando anterior (igual que ↑)
Ctrl+NComando siguiente (igual que ↓)
!!Repite el último comando ejecutado
!textoRepite el último comando que empieza con "texto"
!$El último argumento del comando anterior
Alt+.Inserta el último argumento del comando anterior

Control de la terminal

TabAutocompletar comando, ruta o argumento
Tab TabMuestra todas las opciones de autocompletado
Ctrl+CInterrumpir/cancelar el proceso en ejecución
Ctrl+ZSuspender el proceso (mandarlo al background)
Ctrl+DEOF — fin de entrada / cerrar la terminal
Ctrl+LLimpiar pantalla (igual que clear)
Ctrl+SPausar la salida en pantalla

El truco más poderoso: Ctrl+R para buscar en el historial

Ctrl+R — búsqueda en historial
# Presiona Ctrl+R y empieza a escribir parte del comando # La shell busca en tiempo real en tu historial (reverse-i-search)`git': git commit -m "primera versión" # Ctrl+R de nuevo para ir al resultado anterior # Enter para ejecutar el comando encontrado # Ctrl+C para cancelar la búsqueda # → o Ctrl+E para editar el comando antes de ejecutar # Truco: sudo !! — repite el último comando con sudo $ apt update E: Could not open lock file... Permission denied $ sudo !! # Ejecuta: sudo apt update # Truco: !$ — usa el último argumento $ mkdir nueva-carpeta $ cd !$ # cd nueva-carpeta

🟢 Los 5 atajos que más van a cambiar tu velocidad

  • Ctrl+R — busca cualquier comando en tu historial en tiempo real
  • Ctrl+A / Ctrl+E — inicio y fin de línea sin usar el ratón
  • Ctrl+U — borra toda la línea instantáneamente
  • Tab — autocompletado de rutas y comandos (úsalo siempre)
  • !! + sudo !! — repite el último comando (especialmente útil con sudo)

🟢 Resumen de la Parte C

  • | (pipe) — conecta la salida de un comando a la entrada del siguiente
  • Comandos clave con pipes: grep, wc -l, sort, uniq, cut, tr, tee, head, tail
  • grep -i -n -r -v -c -C — el filtrador más versátil de la terminal
  • Redirección: > sobreescribe, >> agrega, 2> errores, /dev/null descarta
  • Comodines: * cualquier cosa, ? un carácter, [abc] uno de esos caracteres
  • Expansión de llaves: {a,b,c} y rangos {1..10} — muy útil para crear múltiples archivos
  • Variables: $VAR, $HOME, $USER, $PWD, $PATH, $SHELL
  • Sustitución: $(comando) — usa la salida de un comando como argumento
  • Aritmética: $((expr)) — operaciones matemáticas en bash
  • Comillas dobles " ": protegen espacios pero permiten $VAR. Simples ' ': todo literal.
  • Atajos clave: Ctrl+R historial, Ctrl+A/E inicio/fin, Ctrl+U borra línea, Tab autocompleta
