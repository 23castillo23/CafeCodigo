Introducción a los Permisos
1:52:50 — Cómo Linux controla quién puede hacer qué con cada archivo

En Linux, cada archivo y directorio tiene permisos que controlan quién puede leerlo, modificarlo o ejecutarlo. Es el sistema de seguridad fundamental de Linux y lo que permite que múltiples usuarios compartan un sistema de forma segura.

Leer los permisos con ls -l

ls -l — leer permisos
$ ls -l -rwxr-xr-- 2 hugo devs 4096 jun 15 10:30 script.sh drwxr-xr-x 5 hugo hugo 4096 jun 15 10:30 proyectos/ -rw-r--r-- 1 root root 220 jun 1 12:00 config.txt # │ │ │ │ │ fecha nombre # │ │ │ │ └── tamaño en bytes # │ │ │ └─────── grupo propietario # │ │ └──────────── usuario propietario # │ └────────────── número de hard links # └───────────────────────── bloque de permisos (10 chars)

Anatomía del bloque de permisos

d rwx r-x r-- ← así se ve en ls -l
tipo propietario (owner) grupo (group) otros (other)
CarácterTipo de archivo
-Archivo normal
dDirectorio
lEnlace simbólico (symlink)
cDispositivo de caracteres
bDispositivo de bloques

Los 3 permisos básicos — rwx

r

Read — Lectura

Archivo: ver su contenido.
Directorio: listar su contenido con ls.

w

Write — Escritura

Archivo: modificar su contenido.
Directorio: crear y borrar archivos dentro.

x

Execute — Ejecución

Archivo: ejecutarlo como programa.
Directorio: entrar en él con cd.

Los 3 grupos de usuarios

GrupoQuién esPosición en el bloque
owner (u)El usuario propietario del archivoCaracteres 2–4
group (g)Los miembros del grupo propietarioCaracteres 5–7
other (o)Todos los demás usuarios del sistemaCaracteres 8–10

💡 Ejemplo real: -rwxr-xr--

  • - → es un archivo (no directorio)
  • rwx → el propietario puede: leer, escribir y ejecutar
  • r-x → el grupo puede: leer y ejecutar, pero NO escribir
  • r-- → otros solo pueden: leer. No escribir, no ejecutar.

chmod — Cambiar permisos
1:58:48 — El comando para modificar quién puede hacer qué

chmod (CHange MODe) cambia los permisos de archivos y directorios. Tiene dos formas de uso: simbólica (letras) y octal (números). Ambas hacen lo mismo.

Forma simbólica — letras

chmod simbólico
# Estructura: chmod [quién][operador][permiso] archivo # quién: u=owner, g=group, o=other, a=all (todos) # operador: +=agregar, -=quitar, ==establecer exacto # permiso: r, w, x # Dar permiso de ejecución al propietario $ chmod u+x script.sh # Quitar permiso de escritura al grupo $ chmod g-w archivo.txt # Dar lectura a todos (owner, group, other) $ chmod a+r readme.md # Quitar todos los permisos a otros $ chmod o-rwx privado.txt # Establecer permisos exactos para grupo $ chmod g=rx script.sh # Múltiples cambios a la vez $ chmod u+x,g-w,o-rwx archivo.sh # Aplicar recursivamente a toda una carpeta $ chmod -R 755 mi-proyecto/

Forma octal — números (la más usada en la práctica)

Cada permiso tiene un valor numérico: r=4, w=2, x=1. Se suman los valores para cada grupo. Es la forma que más verás en documentación y tutoriales de servidores.

7
rwx
4+2+1 = todo
6

4+2 = leer y escribir
5
r-x
4+1 = leer y ejecutar
4

4 = solo leer
3

2+1 = escribir y ejecutar
2
-w-
2 = solo escribir
1

1 = solo ejecutar
0
---
sin permisos
chmod octal — los más comunes
# chmod [owner][group][other] archivo $ chmod 755 script.sh # owner: rwx (7) | group: r-x (5) | other: r-x (5) # Estándar para scripts y carpetas públicas $ chmod 644 archivo.txt # owner: rw- (6) | group: r-- (4) | other: r-- (4) # Estándar para archivos de texto y configuración $ chmod 600 clave-privada.pem # owner: rw- (6) | group: --- (0) | other: --- (0) # Para claves SSH y archivos muy privados $ chmod 777 archivo # Todos pueden hacer todo — EVITAR en producción $ chmod 000 archivo # Nadie tiene permisos (ni el propietario)

644rw-r--r--Archivos de texto, HTML, CSS, imágenes
600rw-------Claves SSH, archivos con contraseñas
700rwx------Scripts privados, solo el propietario

umask — La máscara de permisos por defecto
2:05:44 — Controla los permisos con los que se crean nuevos archivos

El umask es una máscara que se resta a los permisos máximos al crear un archivo nuevo. Define cuáles permisos se eliminan por defecto. Los archivos se crean con 666 (máximo) y los directorios con 777, y el umask quita los bits que indica.

umask
# Ver el umask actual $ umask 0022 # Con umask 022: # archivo nuevo: 666 - 022 = 644 (rw-r--r--) # directorio nuevo: 777 - 022 = 755 (rwxr-xr-x) # Ver en formato simbólico $ umask -S u=rwx,g=rx,o=rx # Cambiar el umask temporalmente (hasta cerrar la terminal) $ umask 077 # solo el propietario tiene acceso a nuevos archivos # archivo: 666 - 077 = 600 (rw-------) # directorio: 777 - 077 = 700 (rwx------) # Para hacerlo permanente, agrega en ~/.bashrc: # umask 022

🟢 El umask más común: 022

La mayoría de sistemas usan umask 022 por defecto — crea archivos con 644 y directorios con 755. Es el balance correcto entre seguridad y usabilidad para la mayoría de casos. Solo cambia el umask si tienes una razón específica.

Permisos especiales — SUID, SGID y Sticky bit
2:11:43 — Los permisos avanzados que controlan comportamientos especiales

Además de rwx, existen tres bits especiales de permisos con comportamientos específicos.

SUID — Set User ID (4xxx)

El archivo se ejecuta con los permisos del propietario, no del usuario que lo ejecuta.

Ejemplo: passwd necesita escribir en /etc/shadow (solo root puede), pero cualquier usuario puede ejecutarlo gracias al SUID.

Se ve como "s" en la posición x del owner: -rwsr-xr-x

SGID — Set Group ID (2xxx)

En archivos: se ejecuta con el grupo del propietario. En directorios: los archivos nuevos heredan el grupo del directorio.

Útil en carpetas compartidas por un equipo — todos los archivos creados pertenecen al mismo grupo.

Se ve como "s" en la posición x del grupo: -rwxr-sr-x

Sticky bit (1xxx)

En un directorio compartido, solo el propietario del archivo puede borrarlo, aunque otros tengan permiso de escritura.

Ejemplo clásico: /tmp — todos pueden crear archivos ahí, pero nadie puede borrar los archivos de otros.

Se ve como "t" en la posición x de others: drwxrwxrwt

configurar permisos especiales
# SUID — el cuarto dígito octal es 4 $ chmod 4755 ejecutable # -rwsr-xr-x # SGID — el cuarto dígito es 2 $ chmod 2775 carpeta-equipo/ # drwxrwsr-x # Sticky bit — el cuarto dígito es 1 $ chmod 1777 carpeta-publica/ # drwxrwxrwt # Verificar que /tmp tiene sticky bit $ ls -ld /tmp drwxrwxrwt 15 root root 4096 jun 15 /tmp # ^ la t al final = sticky bit activo

Cambiar de identidad — su y sudo
2:15:31 — Ejecutar comandos como otro usuario o como root

A veces necesitas ejecutar un comando con más privilegios. sudo y su son los dos mecanismos para hacerlo.

sudo y su
# sudo — ejecuta UN comando como root (pide TU contraseña) $ sudo apt update # actualiza paquetes como root $ sudo nano /etc/hosts # edita archivo del sistema $ sudo mkdir /var/mi-app # crea carpeta en área del sistema $ sudo -l # lista qué puedes hacer con sudo # sudo -i — abre una shell de root completa $ sudo -i root@ubuntu:~# # ahora eres root (el # indica root) root@ubuntu:~# exit # vuelve a tu usuario # su — cambia de usuario (pide la contraseña DEL usuario destino) $ su otro-usuario # cambia a otro-usuario $ su - otro-usuario # cambia y carga el entorno completo $ su # sin usuario = cambiar a root $ exit # volver al usuario anterior # sudo su — forma común de ser root en Ubuntu $ sudo su root@ubuntu:/home/hugo#
ComandoCuándo usarlo
sudo comandoEjecutar un solo comando con privilegios de root
sudo -iAbrir una sesión completa de root (shell interactiva)
su usuarioCambiar al usuario especificado (pide su contraseña)
su - usuarioIgual pero carga el entorno completo del usuario destino

⚡ No trabajes como root por defecto

Hacer todo como root es peligroso — un comando equivocado puede dañar el sistema sin pedir confirmación. Usa sudo solo para los comandos que realmente lo necesitan. El prompt # indica que eres root; $ indica usuario normal.

chown y chgrp — Cambiar propietario y grupo
2:20:51 — Cambiar quién es el dueño de un archivo o carpeta
chown y chgrp
# chown — cambiar propietario $ sudo chown hugo archivo.txt # ahora hugo es el propietario de archivo.txt # chown — cambiar propietario Y grupo a la vez $ sudo chown hugo:devs proyecto/ # propietario: hugo | grupo: devs # Cambiar solo el grupo $ sudo chown :devs archivo.txt $ sudo chgrp devs archivo.txt # equivalente # Recursivo: cambiar propietario de toda una carpeta $ sudo chown -R hugo:hugo /var/www/mi-web/ # Útil cuando subes archivos al servidor como root # y necesitas que tu usuario pueda editarlos # Ver propietario actual $ ls -l archivo.txt -rw-r--r-- 1 hugo devs 220 jun 15 archivo.txt # │ └── grupo # └──────── propietario

🟢 Caso de uso real: servidor web

Cuando despliegas una web en un servidor, los archivos suelen necesitar que el servidor web (por ejemplo, www-data en nginx/Apache) pueda leerlos: sudo chown -R www-data:www-data /var/www/html/. Pero si tú también necesitas editar esos archivos: sudo chown -R tu-usuario:www-data /var/www/html/ y dale permisos al grupo.

Crear y gestionar usuarios
2:24:33 — Administrar cuentas de usuario en el sistema
gestión de usuarios
# CREAR usuario $ sudo useradd juan # crea usuario básico $ sudo useradd -m -s /bin/bash juan # con home y bash $ sudo adduser juan # forma interactiva (más amigable) # Establecer/cambiar contraseña $ sudo passwd juan # MODIFICAR usuario $ sudo usermod -aG sudo juan # agrega juan al grupo sudo $ sudo usermod -aG devs,docker hugo # agrega a múltiples grupos $ sudo usermod -l juan-nuevo juan # cambia el nombre de usuario # ELIMINAR usuario $ sudo userdel juan # elimina el usuario $ sudo userdel -r juan # elimina usuario Y su carpeta home # Ver información de usuarios $ id hugo # uid, gid y grupos de hugo uid=1000(hugo) gid=1000(hugo) groups=1000(hugo),27(sudo),999(docker) $ cat /etc/passwd # lista todos los usuarios del sistema $ who # usuarios conectados ahora $ w # usuarios conectados y qué hacen $ last # historial de logins # Gestión de grupos $ sudo groupadd devs # crear grupo $ cat /etc/group # ver todos los grupos $ groups hugo # grupos a los que pertenece hugo

Introducción a los Procesos
2:27:13 — Ver, controlar y gestionar lo que corre en el sistema

Un proceso es un programa en ejecución. Cada proceso tiene un PID (Process ID) único. Linux es multitarea — puede correr miles de procesos al mismo tiempo.

Ver procesos — ps y top

ps, top y htop
# ps — snapshot de procesos en este momento $ ps # solo los procesos de tu terminal PID TTY TIME CMD 1234 pts/0 00:00:00 bash 5678 pts/0 00:00:00 ps $ ps aux # TODOS los procesos del sistema USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND root 1 0.0 0.1 16932 7312 ? Ss 09:00 0:01 /sbin/init hugo 1234 0.5 1.2 123456 48000 pts/0 S 10:30 0:02 node server.js $ ps aux | grep node # filtrar por nombre $ ps -p 1234 # proceso con PID específico # top — monitor en tiempo real (como el Administrador de tareas) $ top # se actualiza cada 3 segundos. q para salir # Teclas dentro de top: q=salir, k=kill, h=ayuda, M=ordenar por memoria # htop — versión mejorada y visual de top (instalar: sudo apt install htop) $ htop

Procesos en background y foreground

foreground, background y jobs
# Ejecutar un proceso en BACKGROUND (& al final) $ node server.js & [1] 12345 # [job number] PID # Suspender el proceso actual (Ctrl+Z) $ nano archivo.txt # ^Z [1]+ Stopped nano archivo.txt # Ver los jobs en background $ jobs [1]+ Stopped nano archivo.txt [2]- Running node server.js & # Traer un job al foreground $ fg %1 # trae el job 1 al frente $ fg # trae el más reciente # Mandar job suspendido al background $ bg %1 # reanuda el job 1 en background # Encontrar el PID de un proceso por nombre $ pgrep node 12345 $ pidof nginx 3456 3457 3458

Señales — Comunicarse con los procesos
2:38:00 — Enviar instrucciones a procesos en ejecución

Las señales son mensajes que el sistema operativo (o tú) envía a un proceso. El proceso puede reaccionar a ellas de diferentes formas: terminar, pausarse, recargar su configuración, etc.

Las señales más importantes

SIGNAL 1
SIGHUP
Hang Up — recarga configuración o termina si no lo maneja
SIGNAL 2
SIGINT
Interrupt — es el Ctrl+C. Termina el proceso educadamente.
SIGNAL 9
SIGKILL
Kill — terminación inmediata. El proceso NO puede ignorarla.
SIGNAL 15
SIGTERM
Terminate — la señal por defecto de kill. El proceso puede limpiarse antes de terminar.
SIGNAL 19
SIGSTOP
Stop — pausa el proceso. No puede ignorarse. Es el Ctrl+Z del kernel.
SIGNAL 18
SIGCONT
Continue — reanuda un proceso pausado con SIGSTOP.

El comando kill — enviar señales

kill, killall y pkill
# kill — envía una señal a un proceso por PID $ kill 12345 # envía SIGTERM (15) al PID 12345 $ kill -9 12345 # envía SIGKILL (fuerza la terminación) $ kill -SIGTERM 12345 # por nombre de señal $ kill -SIGHUP 12345 # recarga configuración (nginx, apache...) # Ver todas las señales disponibles $ kill -l # killall — termina todos los procesos con ese nombre $ killall node # mata TODOS los procesos "node" $ killall -9 firefox # fuerza el cierre de todos los firefox # pkill — como killall pero acepta patrones $ pkill -f "server.js" # mata el proceso que tenga "server.js" en su comando # El flujo correcto para terminar un proceso $ kill 12345 # 1. SIGTERM — intenta terminar limpiamente # espera unos segundos... $ kill -9 12345 # 2. SIGKILL — si no respondió, fuerza

⚡ SIGTERM antes que SIGKILL

Siempre intenta primero kill PID (SIGTERM) y espera unos segundos. Esto da al proceso la oportunidad de cerrar conexiones, guardar datos y limpiar recursos. El kill -9 (SIGKILL) es una terminación brutal — el proceso no puede guardar nada ni limpiar. Úsalo como último recurso cuando el proceso no responde.

Apagar y reiniciar el sistema
2:47:50 — Los comandos correctos para apagar y reiniciar Linux
shutdown, reboot y halt
# APAGAR ahora mismo $ sudo shutdown -h now # apaga inmediatamente (-h = halt) $ sudo poweroff # equivalente $ sudo halt # otro equivalente # REINICIAR ahora mismo $ sudo shutdown -r now # reinicia inmediatamente (-r = reboot) $ sudo reboot # equivalente y más corto # PROGRAMAR apagado en el futuro $ sudo shutdown -h +30 # apaga en 30 minutos $ sudo shutdown -h 22:00 # apaga a las 10 PM $ sudo shutdown -r +5 # reinicia en 5 minutos # Con mensaje a todos los usuarios conectados $ sudo shutdown -h +15 "El servidor se apaga en 15 minutos. Guarda tu trabajo." # CANCELAR un apagado programado $ sudo shutdown -c # cancela el shutdown pendiente # Ver el estado del sistema antes de apagar $ uptime # cuánto tiempo lleva encendido 10:30:00 up 5 days, 3:22, 2 users, load average: 0.15, 0.12, 0.09 $ w # usuarios conectados antes de apagar

⚠️ En servidores remotos — ten mucho cuidado

Si estás conectado a un servidor remoto vía SSH y ejecutas sudo reboot o sudo shutdown, perderás la conexión SSH y el servidor se apagará o reiniciará. Solo hazlo si sabes que el servidor va a volver a estar disponible. Para actualizaciones sin apagar, mira systemctl restart para servicios específicos.

✏️ Ejercicio Parte D Avanzado
  1. Crea un archivo y un script: touch secreto.txt y touch script.sh
  2. Lee los permisos actuales: ls -l secreto.txt script.sh
  3. Haz el script ejecutable: chmod u+x script.sh → verifica con ls -l script.sh
  4. Cambia secreto.txt a 600 (solo tú puedes leerlo y escribirlo): chmod 600 secreto.txt
  5. Crea una carpeta compartida con sticky bit: mkdir compartida && chmod 1777 compartida → verifica con ls -ld compartida
  6. Ve el umask actual: umask y umask -S
  7. Ve tu información de usuario: id y groups
  8. Lista los procesos: ps aux | head -15 (solo los primeros 15)
  9. Filtra tus procesos: ps aux | grep $USER
  10. Abre nano en background: nano test.txt & → vélo con jobs → tráelo con fg %1 → cierra con Ctrl+X
  11. Ejecuta sleep 100 & → consigue su PID con jobs -p → mátalo con kill PID → verifica con jobs
  12. Abre top, observa los procesos 10 segundos y sal con q

🟢 Resumen de la Parte D

  • Permisos: tipo + owner(rwx) + group(rwx) + other(rwx). Leer con ls -l.
  • r=4, w=2, x=1. Suma los valores para obtener el octal. 755=rwxr-xr-x, 644=rw-r--r--
  • chmod simbólico: u+x g-w o=r. Octal: chmod 755 archivo. Recursivo: -R
  • umask 022 → archivos nuevos con 644, directorios con 755
  • Especiales: SUID(4xxx) ejecuta como owner, SGID(2xxx) hereda grupo, Sticky(1xxx) solo el dueño borra
  • sudo → un comando como root. sudo -i → shell de root. su usuario → cambiar de usuario
  • chown usuario:grupo archivo → cambia propietario. -R para recursivo
  • useradd -m -s /bin/bash, passwd, usermod -aG grupo, userdel -r
  • ps aux → todos los procesos. ps aux | grep nombre → filtrar. top / htop → tiempo real
  • Background: comando &. Jobs: jobs, fg %N, bg %N. Ctrl+Z pausa.
  • Señales: SIGTERM(15)=terminar limpio, SIGKILL(9)=forzar, SIGHUP(1)=recargar
  • kill PID, kill -9 PID, killall nombre, pkill -f patrón
  • sudo shutdown -h now, sudo reboot, sudo shutdown -h +30, sudo shutdown -c
