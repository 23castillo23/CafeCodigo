El kernel habla a través de archivos
Los pseudosistemas de archivos — la API del kernel para el userspace

El kernel de Linux no tiene una API de funciones que las aplicaciones llamen directamente para preguntarle cosas. En cambio, expone su estado interno y permite controlarlo a través de pseudosistemas de archivos — directorios especiales que parecen archivos pero son ventanas vivas al interior del kernel.

🎛️ Analogía — El panel de control de la central eléctrica

Imagina el kernel como una central eléctrica enorme y compleja. /proc es el tablero de instrumentos con medidores en tiempo real: muestra qué pasa ahora mismo en cada proceso y en la CPU. /sys es el panel de control con palancas y perillas: puedes leer el estado del hardware y también ajustarlo. /dev es la sala de enchufes: los dispositivos de hardware aparecen aquí como enchufes a los que conectarte. No son archivos reales en disco — son interfaces vivas que el kernel actualiza al instante.

/proc
procfs — estado de procesos y kernel
Un directorio por cada proceso (PID)
Info del kernel: CPU, RAM, red
Solo lectura en su mayoría
Montado en tmpfs — no usa disco
/sys
sysfs — estado y control del hardware
Árbol de dispositivos del kernel
Leer Y escribir para controlar hardware
CPU governors, LEDs, USB, bloques
Más estructurado que /proc
/dev
devtmpfs — dispositivos como archivos
Discos: /dev/sda, /dev/nvme0n1
Terminal: /dev/tty, /dev/pts/*
Nulos: /dev/null, /dev/zero, /dev/random
Gestionado por udev automáticamente
/run
tmpfs — datos temporales del arranque
PIDs de servicios en ejecución
Sockets Unix de systemd
Se borra en cada reinicio
Reemplaza /var/run (ahora symlink)
verificar los pseudosistemas montados
$ findmnt -t proc,sysfs,devtmpfs,tmpfs TARGET SOURCE FSTYPE OPTIONS /proc proc proc rw,nosuid,nodev,noexec,relatime /sys sysfs sysfs rw,nosuid,nodev,noexec,relatime /dev devtmpfs devtmpfs rw,nosuid,relatime,size=8192k /run tmpfs tmpfs rw,nosuid,nodev,relatime # No son particiones de disco — son interfaces del kernel
🔬
/proc — radiografía de los procesos y el kernel
Un directorio por proceso y ventanas al estado interno del sistema

/proc contiene un directorio numerado por cada proceso vivo en el sistema — /proc/1234/ corresponde al proceso con PID 1234. Además, los archivos directamente en /proc/ muestran el estado global del kernel.

/proc — exploración completa
## ARCHIVOS GLOBALES DE /proc $ cat /proc/version Linux version 6.8.0-50-generic (buildd@...) (gcc version 13.2.0) $ cat /proc/cpuinfo | grep -E "model name|cpu cores" | head -4 model name : Intel(R) Core(TM) i7-10750H CPU @ 2.60GHz cpu cores : 6 $ cat /proc/meminfo | grep -E "MemTotal|MemAvailable|SwapTotal" MemTotal: 16189208 kB MemAvailable: 10234567 kB SwapTotal: 8388608 kB $ cat /proc/loadavg 1.24 0.87 0.65 3/312 18924 # 1min 5min 15min running/total último_PID $ cat /proc/uptime 5432.12 42187.34 # segundos desde el arranque / tiempo total de CPU en idle $ cat /proc/mounts # todos los sistemas de archivos montados $ cat /proc/net/dev # estadísticas de red por interfaz $ cat /proc/diskstats # estadísticas de I/O de discos $ cat /proc/interrupts # interrupciones de hardware por núcleo $ cat /proc/sys/kernel/hostname # hostname del sistema ## DIRECTORIO POR PROCESO — /proc/PID/ $ ls /proc/$$ # $$ = PID del shell actual cmdline cwd environ exe fd maps mem net status ... $ cat /proc/$$/cmdline | tr '\0' ' ' # comando que lanzó el proceso bash $ cat /proc/$$/status | grep -E "Name|Pid|VmRSS|Threads" Name: bash Pid: 18924 VmRSS: 8344 kB ← RAM real usada (Resident Set Size) Threads: 1 $ ls -la /proc/$$/fd # archivos abiertos por el proceso lrwxrwxrwx 1 hugo hugo 64 ... 0 -> /dev/pts/0 ← stdin (terminal) lrwxrwxrwx 1 hugo hugo 64 ... 1 -> /dev/pts/0 ← stdout lrwxrwxrwx 1 hugo hugo 64 ... 2 -> /dev/pts/0 ← stderr $ ls -la /proc/$$/exe # el binario ejecutable del proceso lrwxrwxrwx ... /proc/18924/exe -> /usr/bin/bash $ cat /proc/$$/maps | head -5 # mapa de memoria virtual del proceso 55a1b2c3d000-55a1b2c5e000 r-xp /usr/bin/bash ← código del ejecutable 7f8a1b2c3000-7f8a1b4c3000 r-xp /lib/x86_64/libc.so.6 ← libc
Archivo en /proc/PID/Qué contiene
cmdlineEl comando completo con que fue lanzado el proceso (separado por \0)
statusEstado detallado: nombre, PID, PPID, usuario, RAM, estado, hilos
fd/Symlinks a cada archivo abierto (0=stdin, 1=stdout, 2=stderr, 3+=otros)
exeSymlink al binario ejecutable en disco
mapsMapa completo de la memoria virtual — qué está mapeado en qué dirección
environVariables de entorno con que fue lanzado el proceso
net/Vista de red del proceso (conexiones, sockets)
cwdSymlink al directorio de trabajo actual del proceso
🎛️
/sys — el panel de control del hardware
sysfs: leer y escribir para controlar dispositivos en tiempo real

/sys es el sistema de archivos del kernel más moderno. A diferencia de /proc, está organizado siguiendo la jerarquía del bus de hardware y permite tanto leer el estado del hardware como escribir para controlarlo en tiempo real sin reiniciar.

/sys — leer y controlar hardware en tiempo real
## ESTRUCTURA DE /sys $ ls /sys/ block bus class dev devices firmware fs kernel module power ## CPU — leer y cambiar el governor $ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor powersave $ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors performance powersave ondemand conservative schedutil $ echo "performance" | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor # Cambia AHORA el governor de TODOS los núcleos $ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq 4200000 ← 4.2 GHz (en Hz) ## DISCOS — el scheduler de I/O $ cat /sys/block/sda/queue/scheduler [mq-deadline] kyber bfq none $ echo "bfq" | sudo tee /sys/block/sda/queue/scheduler # Cambia el scheduler de I/O del disco sda a bfq ## RED — activar/desactivar reenvío de paquetes IP $ cat /sys/net/ipv4/ip_forward 0 ← desactivado (un router lo pondría a 1) ## LEDs — controlar el LED de un portátil $ ls /sys/class/leds/ input3::capslock input3::numlock phy0-led tpacpi::power $ cat /sys/class/leds/input3::capslock/brightness 0 $ echo 1 | sudo tee /sys/class/leds/input3::capslock/brightness # Enciende el LED de capslock desde la terminal ## BACKLIGHT — brillo de pantalla $ cat /sys/class/backlight/intel_backlight/max_brightness 1200 $ cat /sys/class/backlight/intel_backlight/brightness 800 $ echo 600 | sudo tee /sys/class/backlight/intel_backlight/brightness # Baja el brillo a la mitad desde la terminal ## USB — ver dispositivos USB conectados via sysfs $ ls /sys/bus/usb/devices/ $ cat /sys/bus/usb/devices/1-1/manufacturer Logitech

📌 Los cambios en /sys son temporales

Todo lo que escribes en /sys se aplica inmediatamente pero no persiste tras un reinicio — el kernel vuelve a sus valores por defecto. Para hacer permanentes los cambios de /sys, usa /etc/sysctl.conf (para parámetros del kernel) o reglas de udev (para hardware). Los governors y schedulers también se pueden fijar con systemd-tmpfiles o scripts de arranque.

🔌
/dev — los dispositivos como archivos
udev, dispositivos especiales y la filosofía "todo es un archivo"

En Linux, el hardware se accede a través de archivos de dispositivo en /dev/. Leer de un archivo de dispositivo es leer del hardware. Escribir a él es enviar datos al hardware. Esta abstracción unificada es una de las ideas más elegantes de Unix.

/dev — dispositivos especiales en acción
## DISPOSITIVOS ESPECIALES MÁS ÚTILES # /dev/null — el agujero negro: descarta todo lo que le envíes $ comando_ruidoso > /dev/null 2>&1 # silenciar stdout Y stderr $ cat /dev/null # devuelve vacío inmediatamente # /dev/zero — genera ceros infinitos $ dd if=/dev/zero of=/tmp/archivo bs=1M count=100 # crear archivo de 100MB de ceros $ dd if=/dev/zero of=/dev/sdb bs=4M # BORRAR un disco (¡cuidado!) # /dev/random y /dev/urandom — generadores de aleatoriedad $ head -c 32 /dev/urandom | base64 # generar una clave aleatoria de 32 bytes K7mP9qR2xN4vL8sA3wT6yB1cF5hE0jD+ $ od -An -N4 -tu4 /dev/urandom # número aleatorio de 32 bits # /dev/stdin, /dev/stdout, /dev/stderr — las E/S estándar como archivos $ echo "hola" > /dev/stdout # igual que echo "hola" $ echo "error" > /dev/stderr # escribe en stderr directamente # /dev/tty — la terminal de control del proceso actual $ echo "mensaje" > /dev/tty # siempre va a la terminal, aunque redirigido # /dev/pts/* — pseudoterminales (una por cada ventana de terminal abierta) $ ls /dev/pts/ 0 1 2 ptmx $ echo "¡Hola!" > /dev/pts/1 # enviar texto a otra terminal abierta # Ver el tipo de un archivo de dispositivo (c=char, b=block) $ ls -la /dev/sda /dev/null /dev/tty brw-rw---- ... /dev/sda ← b = block device (disco) crw-rw-rw- ... /dev/null ← c = char device (carácter) crw-rw-rw- ... /dev/tty ← c = char device ## UDEV — el gestor dinámico de /dev $ udevadm info /dev/sda # info completa de un dispositivo $ udevadm monitor # ver eventos de dispositivos en tiempo real # Conecta un USB y verás los eventos UDEV aparecer aquí

🟢 /dev/urandom para generar contraseñas y tokens

/dev/urandom genera bytes aleatorios criptográficamente seguros. Es la fuente de aleatoriedad de todo el sistema — SSH, TLS, generadores de UUID. Para generar una contraseña aleatoria fuerte: head -c 24 /dev/urandom | base64 | tr -d '+/=' | head -c 20. O más simple aún: openssl rand -base64 32, que internamente usa /dev/urandom.

🧩
Módulos del kernel — extensiones cargables
lsmod, modprobe, insmod — cómo Linux carga y descarga funcionalidad en tiempo real

El kernel de Linux es modular: no tiene que incluir todo el soporte de hardware en el kernel base. En cambio, carga módulos (ficheros .ko) según los necesita — para un disco NVMe, una tarjeta WiFi, un sistema de archivos, etc. Puedes cargar y descargar módulos sin reiniciar.

🔌 Analogía — Enchufes de regleta

El kernel base es una regleta con pocos enchufes. Los módulos son los adaptadores que enchufas según lo que necesitas: el módulo WiFi es el adaptador de WiFi, el módulo btrfs es el adaptador para ese sistema de archivos, el módulo usb-storage se enchufa al detectar un USB. Cuando ya no necesitas el adaptador, lo desenchufas (rmmod). La regleta no necesita apagarse para enchufar o desenchufar.

módulos del kernel — gestión completa
## VER MÓDULOS CARGADOS $ lsmod Module Size Used by nvidia 56832000 98 iwlwifi 417792 1 iwlmvm btrfs 1613824 1 usb_storage 77824 2 # Size = tamaño en bytes / Used by = módulos que dependen de éste # Ver cuántos módulos hay cargados $ lsmod | wc -l ## INFO DE UN MÓDULO $ modinfo iwlwifi filename: /lib/modules/6.8.0/kernel/drivers/net/wireless/intel/iwlwifi/iwlwifi.ko description: Intel(R) Wireless WiFi driver for Linux author: Copyright(c) 2003-2015 Intel Corporation depends: cfg80211 parm: debug:debug output mask (ulong) ## CARGAR Y DESCARGAR MÓDULOS $ sudo modprobe bluetooth # cargar módulo (con dependencias) $ sudo modprobe -r bluetooth # descargar módulo # insmod / rmmod — versiones más simples (sin gestión de dependencias) $ sudo insmod /lib/modules/$(uname -r)/kernel/drivers/bluetooth/bluetooth.ko $ sudo rmmod bluetooth ## HACER UN MÓDULO PERSISTENTE (cargarse siempre al arrancar) $ echo "bluetooth" | sudo tee /etc/modules-load.d/bluetooth.conf ## BLACKLIST — evitar que un módulo se cargue # Ej: el módulo pcspkr hace sonar el altavoz interno del PC (molesto) $ echo "blacklist pcspkr" | sudo tee /etc/modprobe.d/nobeep.conf ## VER LOS MÓDULOS DISPONIBLES PARA EL KERNEL ACTUAL $ ls /lib/modules/$(uname -r)/kernel/drivers/ | head -10 acpi ata bluetooth char cpufreq gpu hid input media net # Buscar un módulo por nombre $ find /lib/modules/$(uname -r) -name "*.ko" | grep wifi | head -5

Drivers — cómo Linux habla con el hardware
dmesg, lspci, lsusb y el flujo de detección de hardware

Un driver (controlador) es el código que sabe hablar el "idioma" de un dispositivo de hardware concreto. En Linux, los drivers son módulos del kernel. Cuando conectas un dispositivo, udev detecta el evento, identifica el hardware y carga el módulo correspondiente automáticamente.

# Flujo de detección de hardware en Linux Hardware se conecta (USB, PCIe, etc.) ↓ Kernel detecta el evento (interrupt / hotplug) ↓ udev recibe el evento de kobject del kernel ↓ udev consulta sus reglas en /etc/udev/rules.d/ ↓ udev identifica Vendor ID + Product ID del dispositivo ↓ modprobe carga el módulo del driver correcto ↓ El módulo inicializa el hardware ↓ Aparece el dispositivo en /dev/ con el nombre correcto ↓ Opcional: udev crea symlinks, ajusta permisos, lanza servicios
diagnosticar hardware y drivers
## dmesg — el log del kernel (eventos de hardware) $ dmesg | tail -30 # últimos mensajes del kernel $ dmesg --follow # en tiempo real (conecta un USB) $ dmesg | grep -i "error\|warn" # solo errores y advertencias $ dmesg | grep -i usb # eventos USB [ 2.345678] usb 1-1: new high-speed USB device number 2 [ 2.456789] usb 1-1: New USB device found, idVendor=046d (Logitech) [ 2.567890] hid-generic 0003:046D:C52B: input,hidraw0: USB HID v1.11 Mouse ## lspci — listar dispositivos PCI/PCIe $ lspci 00:00.0 Host bridge: Intel Corporation... 00:02.0 VGA compatible controller: Intel Corporation Iris Xe Graphics 00:14.0 USB controller: Intel Corporation Tiger Lake-H USB 3.2 Gen 2x1 01:00.0 3D controller: NVIDIA Corporation GA107M [GeForce RTX 3050] $ lspci -k | grep -A3 "VGA" # ver el kernel driver de la GPU 01:00.0 3D controller: NVIDIA Corporation GA107M Kernel driver in use: nvidia Kernel modules: nvidiafb, nvidia_drm, nvidia ## lsusb — listar dispositivos USB $ lsusb Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub Bus 001 Device 003: ID 046d:c52b Logitech, Inc. Unifying Receiver Bus 002 Device 004: ID 0951:1666 Kingston Technology DataTraveler 100 ## hwinfo — info detallada de todo el hardware $ sudo apt install hwinfo $ hwinfo --short # resumen de todo el hardware $ hwinfo --network # solo tarjetas de red $ hwinfo --gfxcard # solo tarjetas gráficas ## Ver qué driver usa un dispositivo $ udevadm info -a /dev/sda | grep driver | head -3 $ readlink /sys/block/sda/device/driver ../../../../../bus/scsi/drivers/sd ← driver 'sd' (SCSI disk)
🎛️
sysctl — parámetros del kernel en tiempo real
Ver y cambiar el comportamiento del kernel sin recompilar ni reiniciar

sysctl es la interfaz para leer y modificar parámetros del kernel en tiempo real. Los parámetros viven en /proc/sys/ como archivos, y sysctl es la herramienta que los gestiona de forma organizada. Son los mismos valores que ajustabas en /proc/sys antes, pero con una interfaz estándar y persistencia.

sysctl — leer, cambiar y hacer persistentes parámetros del kernel
## VER PARÁMETROS $ sysctl -a # todos los parámetros (muy largo) $ sysctl -a | grep vm # parámetros de memoria virtual $ sysctl kernel.hostname # ver un parámetro específico kernel.hostname = mi-equipo ## PARÁMETROS IMPORTANTES $ sysctl vm.swappiness vm.swappiness = 60 $ sysctl net.ipv4.ip_forward net.ipv4.ip_forward = 0 $ sysctl kernel.perf_event_paranoid kernel.perf_event_paranoid = 3 ## CAMBIAR UN PARÁMETRO (temporal — se pierde al reiniciar) $ sudo sysctl -w vm.swappiness=10 vm.swappiness = 10 $ sudo sysctl -w net.ipv4.ip_forward=1 # activar routing IP (para VPNs) $ sudo sysctl -w kernel.dmesg_restrict=0 # permitir dmesg sin sudo ## HACER PERSISTENTE — /etc/sysctl.conf o /etc/sysctl.d/ $ echo "vm.swappiness=10" | sudo tee -a /etc/sysctl.conf $ sudo sysctl -p # aplicar /etc/sysctl.conf ahora # Mejor práctica: archivos separados en /etc/sysctl.d/ $ sudo nano /etc/sysctl.d/99-optimizaciones.conf # Contenido: # vm.swappiness = 10 # net.core.somaxconn = 1024 # net.ipv4.tcp_syncookies = 1 $ sudo sysctl --system # aplicar todos los archivos sysctl.d/
vm.swappiness
Cuándo usar swap: 0=nunca, 60=defecto, 100=agresivo. Bajar a 10 con mucha RAM.
sysctl vm.swappiness sudo sysctl -w vm.swappiness=10
net.ipv4.ip_forward
Reenvío de paquetes IP entre interfaces. Necesario para Docker, VPNs y routers.
sysctl net.ipv4.ip_forward sudo sysctl -w net.ipv4.ip_forward=1
kernel.hostname
El nombre del sistema. Cambiarlo aquí es temporal — usa hostnamectl para permanente.
sysctl kernel.hostname hostnamectl set-hostname nuevo-nombre
net.ipv4.tcp_syncookies
Protección contra ataques SYN flood. Debe estar siempre en 1 (activo por defecto).
sysctl net.ipv4.tcp_syncookies # Debe ser = 1
✏️ Ejercicio del Nivel 22 Kernel

Explora el interior del kernel de tu sistema:

  1. /proc global: ejecuta cat /proc/version, cat /proc/uptime y cat /proc/loadavg. ¿Qué versión del kernel tienes? ¿Cuánto tiempo lleva encendido el sistema?
  2. /proc por proceso: ejecuta ls /proc/$$ y cat /proc/$$/status | head -10. ¿Cuánta RAM real usa tu shell (VmRSS)?
  3. Archivos abiertos: ejecuta ls -la /proc/$$/fd. ¿A dónde apuntan los file descriptors 0, 1 y 2?
  4. /sys CPU: ejecuta cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor. ¿Qué governor usa tu CPU?
  5. Módulos: ejecuta lsmod | wc -l y lsmod | head -10. ¿Cuántos módulos hay cargados? ¿Reconoces alguno?
  6. Hardware: ejecuta lspci | grep -iE "vga|3d|network|audio". ¿Qué GPU y tarjeta de red tiene tu equipo?
  7. dmesg: ejecuta dmesg | grep -i "error" | tail -5. ¿Hay errores de hardware en el log del kernel?
  8. sysctl: ejecuta sysctl vm.swappiness net.ipv4.ip_forward kernel.hostname. ¿Cuáles son los valores actuales?

Desafío: conecta un USB y ejecuta sudo dmesg --follow justo antes de conectarlo. ¿Ves el proceso de detección — el kernel reconociendo el VendorID, cargando el módulo usb-storage, creando el dispositivo en /dev/?

🟥 Resumen del Nivel 22

  • El kernel expone su estado y control a través de pseudosistemas de archivos: /proc, /sys, /dev — no son archivos en disco, son interfaces vivas del kernel.
  • /proc — estado en tiempo real: /proc/cpuinfo, /proc/meminfo, /proc/PID/ (un directorio por proceso con cmdline, fd, status, maps).
  • /sys — leer Y controlar hardware: governors de CPU, schedulers de disco, brillo de pantalla, LEDs. Los cambios son temporales — usar sysctl.conf para persistencia.
  • /dev — dispositivos como archivos: /dev/null (agujero negro), /dev/zero (ceros), /dev/urandom (aleatoriedad), discos, terminales. Gestionado por udev.
  • Módulos — extensiones cargables del kernel: lsmod (ver), modprobe nombre (cargar), modprobe -r nombre (descargar). /etc/modules-load.d/ para persistencia.
  • Flujo de detección de hardware: evento hardware → udev → modprobe → driver → /dev. dmesg registra todo este proceso.
  • lspci — dispositivos PCIe. lsusb — dispositivos USB. lspci -k — qué driver usa cada dispositivo.
  • sysctl — parámetros del kernel. sysctl -a (ver todos), sysctl -w param=val (cambiar), /etc/sysctl.conf (hacer persistente).
