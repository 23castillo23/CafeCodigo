📦 Nivel 6 — Familia Debian
🌀
Debian — la madre de la familia
La distribución más influyente de la historia de Linux

Debian nació en 1993 — solo 2 años después del kernel Linux — y se convirtió en la base sobre la que se construyeron cientos de distribuciones, incluyendo la más popular del mundo: Ubuntu. Su filosofía es simple: estabilidad extrema y software 100% libre.

🌳 Analogía — El árbol del que nacen los frutos

Debian es como un árbol centenario que tardó décadas en afianzar sus raíces. Sus frutos (Ubuntu, Mint, Kali…) crecen más rápido y son más coloridos, pero todos sacan su nutrición del mismo tronco sólido. Sin Debian, la mayoría del ecosistema Linux de escritorio no existiría tal como lo conocemos hoy.

Lo que hace especial a Debian:

  • Gobernanza democrática — los desarrolladores votan las decisiones importantes. No hay una empresa detrás.
  • Más de 59,000 paquetes en sus repositorios — el catálogo más grande de cualquier distro.
  • Multiplataforma — soporta x86, x64, ARM, MIPS, PowerPC y más arquitecturas que ninguna otra distro.
  • El Social Contract — un documento que compromete a Debian a permanecer siempre libre y para la comunidad.

📌 ¿Por qué no usamos Debian directamente para aprender?

Debian Stable usa versiones de software muy conservadoras — pueden tener 2–3 años de antigüedad. Para aprender, es más cómodo Ubuntu o Mint que tienen software más reciente y mejor soporte de hardware. Cuando trabajes en servidores de producción, Debian Stable será tu mejor amigo.

🌿
Las tres ramas de Debian
Stable, Testing e Unstable — tres niveles de estabilidad vs novedad

Debian mantiene tres ramas de desarrollo simultáneas con distintos niveles de madurez del software. Cada paquete entra por Unstable, migra a Testing tras pasar pruebas y llega a Stable solo cuando está completamente probado.

Stable
Codename: Bookworm (2023)
Software muy probado. Puede tener versiones antiguas pero casi nunca falla. Ideal para servidores. Soporte de 5+ años.
Testing
Codename: Trixie
Software reciente que pasó pruebas básicas. Buen equilibrio entre novedad y estabilidad. Usada por desarrolladores Debian.
Unstable (Sid)
Siempre se llama "Sid"
Las versiones más recientes sin casi pruebas. Puede romperse. Solo para desarrolladores que saben arreglarlo.
# Flujo de paquetes en Debian: Upstream → Unstable (Sid) → Testing (Trixie) → Stable (Bookworm) autor entra primero 10 días sin bugs congelado y probado # Ubuntu toma un snapshot de Debian Testing cada 6 meses # y lo pule con sus propias herramientas y configuración

🏭 Analogía — La línea de control de calidad

Imagina una fábrica de coches: los prototipos salen del taller (Unstable), pasan por pruebas de choque y rendimiento (Testing) y solo los que superan todos los controles llegan a la sala de ventas (Stable). Ubuntu es como un concesionario que compra los coches en la fase Testing, les pone sus propios acabados y los vende antes de que lleguen a la sala principal de Debian.

La familia Debian — las distros hijas
Las distribuciones más usadas del mundo nacen de Debian

Debian es la base de más de 120 distribuciones activas. Aquí las más relevantes para un estudiante de sistemas:

🟠
Ubuntu
Canonical · desde 2004
La más popular del mundo. Sale cada 6 meses (versiones LTS cada 2 años con 5 años de soporte). Base de millones de servidores en la nube. GNOME por defecto.
🍃
Linux Mint
Basada en Ubuntu · desde 2006
La favorita para migrar desde Windows. Escritorio Cinnamon muy familiar. Más conservadora que Ubuntu — no te fuerza a actualizaciones. Sin snaps por defecto.
🚀
Pop!_OS
System76 · desde 2017
Optimizada para desarrollo y gaming. Excelente soporte NVIDIA out-of-the-box. Escritorio COSMIC propio en desarrollo. Muy popular entre programadores.
🐉
Kali Linux
Offensive Security · desde 2013
Especializada en ciberseguridad. 600+ herramientas de pentesting preinstaladas. Basada en Debian Testing. No es para uso diario — es una herramienta profesional.
🍓
Raspberry Pi OS
Raspberry Pi Foundation · desde 2012
Debian optimizada para la Raspberry Pi. Ligera, eficiente y con herramientas específicas para el hardware del Pi. La referencia para proyectos de hardware y IoT.
🌙
elementary OS
Basada en Ubuntu · desde 2011
La distro más parecida a macOS en diseño. Escritorio Pantheon propio, muy pulido. Su App Center tiene apps de pago. Para usuarios que priorizan la estética.

🟢 ¿Por qué tanta distro basada en Debian/Ubuntu?

Porque APT y el formato .deb son maduros, bien documentados y tienen el mayor repositorio de paquetes del mundo. Construir sobre Debian/Ubuntu significa heredar 30 años de trabajo en gestión de paquetes, seguridad y estabilidad. Es el camino de menor resistencia para crear una nueva distro.

📦
Paquetes .deb — el formato de software
Qué hay dentro de un paquete y cómo funciona la gestión de dependencias

Un paquete .deb es un archivo comprimido que contiene todo lo necesario para instalar un programa: los archivos binarios, las bibliotecas, la configuración, la documentación y los metadatos. Es el formato de instalación estándar de la familia Debian.

📦 Analogía — Un paquete de IKEA

Un .deb es como un paquete de IKEA: dentro viene el mueble desmontado (archivos del programa), el manual de instrucciones (scripts de instalación), la lista de piezas (metadatos) y una nota que dice "necesitas un destornillador Phillips y cola de madera" (dependencias). APT es el empleado de IKEA que, antes de entregarte el paquete, ya fue al almacén a buscar el destornillador y la cola por ti.

# Estructura interna de un archivo .deb firefox_125.0_amd64.deb ├── control.tar.xz │ ├── control → nombre, versión, arquitectura, descripción │ ├── depends → lista de dependencias requeridas │ ├── preinst → script que corre ANTES de instalar │ └── postinst → script que corre DESPUÉS de instalar └── data.tar.xz ├── usr/bin/firefox → el ejecutable ├── usr/lib/firefox/ → bibliotecas del programa ├── usr/share/applications/ → acceso directo del escritorio └── usr/share/man/ → páginas del manual

💡 Las dependencias — el problema que APT resuelve

Cada paquete puede depender de otros. Firefox necesita libgtk-3, que necesita libglib2.0, que necesita otras cosas. Instalar manualmente una cadena de 20 dependencias en el orden correcto sería imposible. APT lo hace automáticamente — calcula el árbol completo de dependencias y los instala todos en el orden correcto.

🗄️
Repositorios — de dónde vienen los paquetes
Los servidores donde vive el software que instala APT

Un repositorio es un servidor (o red de servidores) donde están almacenados todos los paquetes .deb disponibles para instalar. Cuando ejecutas apt install firefox, APT busca Firefox en los repositorios configurados, lo descarga e instala.

📡
main
Software libre mantenido oficialmente por Ubuntu/Debian. El más confiable.
🔄
universe
Software libre mantenido por la comunidad. Enorme catálogo, menos verificación.
🔒
restricted
Software no libre pero necesario: drivers privativos de NVIDIA, WiFi broadcom.
🌐
multiverse
Software privativo que no cumple políticas de Debian. Codecs, Flash (histórico).
➕
PPA
Personal Package Archives — repositorios de terceros. Para software no oficial.
# Ver los repositorios configurados en tu sistema cat /etc/apt/sources.list # Ejemplo de línea en sources.list (Ubuntu 24.04): deb https://archive.ubuntu.com/ubuntu noble main restricted universe multiverse # ↑ ↑ # codename distro secciones habilitadas # Archivos adicionales de repositorios van en: ls /etc/apt/sources.list.d/

⚠️ Cuidado con los PPAs de terceros

Los PPAs (Personal Package Archives) permiten instalar software no oficial, pero también pueden instalar software malicioso o romper el sistema. Solo añade PPAs de fuentes confiables — proyectos conocidos o el propio desarrollador del software. Antes de añadir un PPA, busca si existe alternativa oficial.

¿Cómo sabe APT qué hay disponible? — El índice

1
apt update — descarga la lista actualizada de paquetes de cada repositorio
2
APT guarda el índice en /var/lib/apt/lists/ — una "foto" de lo disponible
3
apt install X — busca X en el índice local, resuelve dependencias, descarga e instala
4
Los .deb descargados van a /var/cache/apt/archives/ (caché local)
5
dpkg extrae e instala cada .deb en las rutas correctas del sistema
⚙️
APT — Advanced Package Tool
La herramienta de gestión de paquetes de la familia Debian

APT (Advanced Package Tool) es la interfaz de alto nivel para gestionar software en la familia Debian. Se encarga de todo el proceso: buscar paquetes, resolver dependencias, descargar, verificar integridad e instalar. Llama internamente a dpkg para hacer la instalación real.

🛒 Analogía — El asistente de compras inteligente

APT es como un asistente personal de compras que conoce todas las tiendas de la ciudad (repositorios). Le dices "quiero hacer paella" (instalar un programa) y él identifica todos los ingredientes necesarios (dependencias), los busca en las mejores tiendas, verifica que no están caducados (firma GPG), los compra en el orden correcto y los pone en tu cocina (instala en las rutas correctas). Tú solo dices qué quieres.

apt vs apt-get — ¿cuál usar?

apt es la versión moderna pensada para uso interactivo en terminal: tiene barra de progreso, colores y mensajes más claros. apt-get es la versión antigua, más estable para scripts porque su salida no cambia entre versiones. En el día a día usa apt; en scripts de automatización usa apt-get.

📋
Comandos APT esenciales
Los que usarás cada semana administrando tu sistema
apt update
Actualiza el índice local de paquetes disponibles. No instala nada, solo refresca la lista.
sudo apt update
apt upgrade
Actualiza todos los paquetes instalados a su versión más reciente disponible.
sudo apt upgrade -y
apt install
Instala uno o varios paquetes junto con sus dependencias automáticamente.
sudo apt install git curl wget
apt remove
Elimina un paquete pero conserva sus archivos de configuración.
sudo apt remove firefox
apt purge
Elimina un paquete Y sus archivos de configuración. Limpieza total.
sudo apt purge firefox
apt autoremove
Elimina paquetes instalados como dependencias que ya no son necesarios.
sudo apt autoremove
apt search
Busca paquetes por nombre o descripción en los repositorios configurados.
apt search "editor de texto"
apt show
Muestra información detallada de un paquete: versión, tamaño, dependencias.
apt show nodejs
apt list
Lista paquetes instalados, actualizables o disponibles según el filtro.
apt list --installed
apt full-upgrade
Como upgrade pero puede eliminar paquetes si es necesario para resolver conflictos.
sudo apt full-upgrade
add-apt-repository
Añade un PPA o repositorio de terceros a sources.list.
sudo add-apt-repository ppa:user/repo
apt clean
Elimina los .deb del caché local para liberar espacio en disco.
sudo apt clean
rutina semanal de mantenimiento recomendada
# La rutina completa de mantenimiento — una línea $ sudo apt update && sudo apt upgrade -y && sudo apt autoremove -y && sudo apt clean # Ver cuánto espacio liberaste $ df -h / Filesystem Size Used Avail Use% Mounted on /dev/sda2 49G 18G 29G 38% / # Ver los últimos paquetes instalados $ grep " install " /var/log/dpkg.log | tail -20
🔩
dpkg — la herramienta de bajo nivel
El motor que APT usa internamente para instalar paquetes .deb

dpkg (Debian Package) es la herramienta de bajo nivel que realmente instala, elimina y gestiona paquetes .deb. APT llama a dpkg internamente — tú normalmente usas APT, pero dpkg es útil cuando necesitas instalar un .deb descargado manualmente o consultar el estado del sistema de paquetes.

dpkg — casos de uso comunes
# Instalar un .deb descargado manualmente (ej: VS Code) $ sudo dpkg -i code_1.89.1_amd64.deb # Si dpkg falla por dependencias, APT las resuelve: $ sudo apt install -f # Ver si un paquete está instalado $ dpkg -l | grep firefox ii firefox 125.0.2+build1-0ubuntu0.24.04.1 amd64 Safe and easy web browser # ↑↑ # ii = instalado correctamente # rc = eliminado pero quedan archivos de configuración # Ver qué archivos instaló un paquete $ dpkg -L git /usr/bin/git /usr/share/man/man1/git.1.gz # Saber a qué paquete pertenece un archivo $ dpkg -S /usr/bin/git git: /usr/bin/git

💡 APT vs dpkg — la relación

dpkg es como un mecánico que sabe exactamente cómo montar y desmontar piezas de un motor — pero no sabe dónde conseguir las piezas. APT es el mecánico que además tiene acceso a todos los proveedores, sabe qué piezas son compatibles y cuáles necesitas antes de empezar. Para el uso diario usas APT siempre; dpkg solo cuando tienes un .deb suelto o necesitas consultar el estado del sistema.

✏️ Ejercicio del Nivel 6 Terminal

Con tu Ubuntu o Linux Mint instalado (o VM), practica estos comandos en orden:

  1. Ejecuta sudo apt update — observa cuántos repositorios consulta y cuántos paquetes actualiza el índice.
  2. Ejecuta apt list --upgradable 2>/dev/null — ¿cuántos paquetes tienes pendientes de actualizar?
  3. Instala htop, tree y ncdu: sudo apt install htop tree ncdu -y. Son tres herramientas muy útiles.
  4. Ejecuta apt show htop — lee las dependencias que tiene. ¿Ya estaban instaladas?
  5. Ejecuta dpkg -L htop — ¿en qué ruta se instaló el ejecutable de htop?
  6. Ejecuta htop — verás un monitor de procesos en tiempo real. Presiona q para salir.
  7. Ejecuta sudo apt remove htop && sudo apt autoremove — desinstala htop y limpia.
  8. Ejecuta la rutina de mantenimiento completa: sudo apt update && sudo apt upgrade -y && sudo apt autoremove -y && sudo apt clean

Bonus: Añade el repositorio de VS Code con sudo snap install code --classic o siguiendo las instrucciones oficiales de code.visualstudio.com/docs/setup/linux para añadirlo vía APT.

🟥 Resumen del Nivel 6

  • Debian (1993) es la madre de la familia: 59,000+ paquetes, gobernanza democrática, multiplataforma.
  • Debian tiene 3 ramas: Stable (muy probada), Testing y Unstable/Sid (más reciente, menos estable).
  • La familia incluye: Ubuntu, Linux Mint, Pop!_OS, Kali, Raspberry Pi OS, elementary OS y 100+ más.
  • Un .deb contiene: archivos del programa + metadatos + scripts de instalación + lista de dependencias.
  • Los repositorios son servidores donde viven los paquetes. Ubuntu tiene: main, universe, restricted, multiverse.
  • APT gestiona el ciclo completo: busca en repositorios, resuelve dependencias, descarga e instala.
  • Rutina semanal: sudo apt update && sudo apt upgrade -y && sudo apt autoremove -y
  • dpkg es la herramienta de bajo nivel que APT usa internamente. Útil para instalar .deb manuales.
