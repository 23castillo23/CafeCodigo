La raíz — todo empieza en /
El árbol de directorios de Linux y por qué es diferente a Windows

En Linux no existen las letras de unidad (C:, D:, E:). Todo el sistema de archivos forma un único árbol que empieza en la raíz /. Los discos adicionales, los USBs, las particiones — todo se "monta" como ramas dentro de este árbol. Una sola jerarquía, un solo punto de entrada.

🌳 Analogía — Un árbol con una sola raíz

Windows tiene varios árboles separados: C:\ para el sistema, D:\ para datos, E:\ para el DVD. Linux tiene un único árbol que empieza en /. Cuando conectas un USB, no aparece como "F:\" — se "injerta" como una rama en el árbol existente, por ejemplo en /media/hugo/usb-sandisk. Todo es accesible desde el mismo árbol usando las mismas rutas.

/ ← RAÍZ — el origen de todo ├── bin/ → binarios esenciales del sistema (ls, cp, mv, bash) ├── boot/ → kernel, initrd, GRUB — lo necesario para arrancar ├── dev/ → dispositivos como archivos (sda, tty, null, random) ├── etc/ → configuración del sistema (archivos de texto editables) ├── home/ → directorios personales de usuarios │ ├── hugo/ ← TU home — documentos, proyectos, configuración │ └── maria/ ├── lib/ → bibliotecas compartidas usadas por /bin y /sbin ├── media/ → punto de montaje para USB, DVD, discos externos ├── mnt/ → montajes temporales manuales ├── opt/ → software opcional de terceros (JetBrains, Google Chrome) ├── proc/ → sistema de archivos virtual del kernel (procesos, CPU) ├── root/ → home del usuario root (diferente a /home/root) ├── run/ → datos runtime — PIDs, sockets — se borra al reiniciar ├── sbin/ → binarios de administración del sistema (fdisk, ip, mount) ├── srv/ → datos de servicios del servidor (web, FTP) ├── sys/ → interfaz con el kernel — dispositivos, módulos, configuración ├── tmp/ → archivos temporales — se borran al reiniciar ├── usr/ → la mayoría del software instalado │ ├── bin/ ← ejecutables de usuario (git, python3, node) │ ├── lib/ ← bibliotecas de aplicaciones │ ├── local/ ← software instalado por el administrador manualmente │ └── share/ ← datos compartidos (iconos, documentación, man pages) └── var/ → datos variables — logs, bases de datos, caches, colas ├── log/ ← logs del sistema (syslog, auth.log, dpkg.log) ├── www/ ← archivos del servidor web (nginx, apache) └── cache/ ← caches de aplicaciones

💡 El estándar FHS — Filesystem Hierarchy Standard

Esta estructura no es arbitraria — está definida por el FHS (Filesystem Hierarchy Standard), un documento que especifica qué debe ir en cada directorio. Todas las distribuciones Linux siguen el FHS para garantizar compatibilidad. Así un script escrito para Ubuntu puede asumir que Python está en /usr/bin/python3 en cualquier distro Linux.

Rutas absolutas y relativas
Las dos formas de especificar la ubicación de cualquier archivo

Para referenciar un archivo o directorio en Linux siempre usas una ruta. Hay dos tipos y es fundamental entender la diferencia.

# RUTA ABSOLUTA — empieza siempre con / # Describe el camino completo desde la raíz # Funciona igual sin importar en qué directorio estés /home/hugo/proyectos/cafe-codigo/index.html │ │ │ │ └── archivo │ │ │ └──────────── subdirectorio │ │ └─────────────────────── directorio de proyecto │ └───────────────────────────── home de hugo └────────────────────────────────── raíz del sistema # RUTA RELATIVA — empieza desde el directorio actual (sin /) # Depende de dónde estés en el árbol proyectos/cafe-codigo/index.html ← si estás en /home/hugo cafe-codigo/index.html ← si estás en /home/hugo/proyectos index.html ← si estás en /home/hugo/proyectos/cafe-codigo # Símbolos especiales de ruta: . = directorio actual .. = directorio padre (un nivel arriba) ~ = tu home (/home/hugo) - = el directorio anterior (para cd -)
rutas en la práctica
# Estás en /home/hugo/proyectos hugo@ubuntu:~/proyectos$ # Ruta absoluta — siempre funciona igual $ ls /home/hugo/proyectos/cafe-codigo $ cat /etc/hosts # Ruta relativa — depende de dónde estés $ ls cafe-codigo # = /home/hugo/proyectos/cafe-codigo $ ls ../documentos # = /home/hugo/documentos $ ls ../../etc # = /etc (sube dos niveles) # ~ siempre apunta a tu home $ cd ~/proyectos # va a /home/hugo/proyectos $ ls ~/.bashrc # = /home/hugo/.bashrc # cd - vuelve al directorio anterior $ cd /etc $ cd ~/proyectos $ cd - # vuelve a /etc /etc

Navegación y operaciones básicas
Los comandos del día a día para moverte y manipular archivos
navegación básica — los más usados
# pwd — dónde estás ahora mismo $ pwd /home/hugo/proyectos # ls — listar contenido $ ls # lista básica $ ls -l # lista larga (permisos, tamaño, fecha) $ ls -la # lista larga + archivos ocultos (.bashrc) $ ls -lh # tamaño human-readable (KB, MB, GB) $ ls -lt # ordenado por fecha (más reciente primero) $ ls -R # recursivo — lista subdirectorios también # cd — cambiar de directorio $ cd /etc # ruta absoluta $ cd proyectos # ruta relativa $ cd .. # directorio padre $ cd # sin argumentos → va a ~ $ cd - # directorio anterior # tree — ver el árbol visual (instalar primero: apt install tree) $ tree ~/proyectos -L 2 proyectos/ ├── cafe-codigo/ │ ├── index.html │ └── assets/ └── api-rest/
🔧
Operaciones con archivos y directorios
Crear, copiar, mover, renombrar y eliminar — la base del trabajo diario
mkdir
Crear directorios. Con -p crea toda la cadena de padres.
mkdir proyectos mkdir -p a/b/c/d
touch
Crear archivo vacío o actualizar la fecha de modificación.
touch index.html touch archivo1 archivo2
cp
Copiar archivos. Con -r copia directorios recursivamente.
cp archivo.txt copia.txt cp -r carpeta/ destino/
mv
Mover o renombrar. Si el destino es diferente directorio, mueve. Si es mismo directorio, renombra.
mv archivo.txt nuevo.txt mv archivo.txt ~/documentos/
rm
Eliminar archivos. Con -r elimina directorios. -f fuerza sin preguntar.
rm archivo.txt rm -rf carpeta/
cat / less / head / tail
Ver contenido de archivos. less es para archivos largos.
cat archivo.txt less /var/log/syslog head -20 archivo.txt tail -f /var/log/syslog
wc
Contar líneas, palabras y caracteres de un archivo.
wc -l archivo.txt wc -w archivo.txt
stat
Ver información detallada de un archivo: tamaño, permisos, fechas, inodo.
stat archivo.txt stat /etc/hosts
file
Detectar el tipo real de un archivo (no se fía de la extensión).
file imagen.jpg file script.sh

⚠️ rm -rf — el comando más peligroso de Linux

rm -rf elimina recursiva y forzosamente sin preguntar y sin papelera — no hay deshacer. rm -rf / borraría el sistema entero (Linux moderno tiene protección, pero aun así). Antes de ejecutar rm -rf algo, sustituye el rm -rf por ls -la para ver exactamente qué vas a borrar. Si tienes dudas, mueve a /tmp primero.

operaciones comunes en la práctica
# Crear estructura de proyecto en una línea $ mkdir -p mi-app/{src,public,tests,docs} $ tree mi-app mi-app/ ├── docs/ ├── public/ ├── src/ └── tests/ # Copiar con respaldo de timestamp $ cp importante.conf importante.conf.bak.$(date +%Y%m%d) # Ver los últimos N logs en tiempo real (follow) $ tail -f -n 100 /var/log/nginx/access.log # Verificar tipo real de un archivo $ file documento.pdf documento.pdf: PDF document, version 1.7 $ file foto.jpg foto.jpg: JPEG image data, JFIF standard 1.01

Inodos — la ficha técnica de cada archivo
El concepto que explica cómo Linux realmente almacena la información

Cada archivo en Linux tiene dos partes: el nombre (que ves en el directorio) y el inodo (que contiene toda la información real del archivo). El nombre es solo una etiqueta que apunta a un inodo.

📚 Analogía — El índice de una biblioteca

Un libro en una biblioteca tiene una ficha en el catálogo (inodo) y un nombre en el lomo. La ficha contiene: número de clasificación, autor, editorial, número de páginas, ubicación exacta en la estantería. El nombre en el lomo es solo una etiqueta conveniente para encontrarlo. Puedes tener el mismo libro con varios nombres en el catálogo (hard links) — todos apuntan a la misma ficha y al mismo libro físico.

# Qué contiene un inodo inodo #47382 ├── tipo → archivo regular, directorio, enlace, dispositivo… ├── permisos → rwxr-xr-x (modo octal: 755) ├── propietario → hugo (UID 1000) ├── grupo → hugo (GID 1000) ├── tamaño → 4521 bytes ├── timestamps → acceso, modificación, cambio de metadatos ├── hard links → contador de cuántos nombres apuntan a este inodo └── bloques → lista de bloques del disco donde están los datos # El nombre del archivo NO está en el inodo # Está en el directorio, como un puntero al número de inodo Directorio /home/hugo/: "index.html" → inodo #47382 ".bashrc" → inodo #47383 "proyectos" → inodo #47390 (directorio)
inspeccionar inodos
# Ver el número de inodo de un archivo $ ls -i archivo.txt 47382 archivo.txt # Ver información completa del inodo $ stat archivo.txt File: archivo.txt Size: 4521 Blocks: 16 IO Block: 4096 Device: 802h/2050d Inode: 47382 Links: 1 Access: (0644/-rw-r--r--) Uid: (1000/hugo) Gid: (1000/hugo) Modify: 2025-01-15 10:23:44 # Ver cuántos inodos quedan libres en el disco $ df -i Filesystem Inodes IUsed IFree IUse% Mounted on /dev/nvme0n1p2 6553600 245678 6307922 4% /

📌 Se pueden llenar los inodos antes que el disco

El número total de inodos se fija al crear el sistema de archivos. Si tienes millones de archivos pequeños (logs, caché, emails), puedes quedarte sin inodos aunque quede espacio en disco. El síntoma: "No space left on device" pero df -h muestra espacio libre. La solución: df -i confirma el problema, y hay que eliminar archivos pequeños para liberar inodos.

Hard links y Soft links (Symlinks)
Dos formas de hacer que un archivo tenga varios nombres o ubicaciones

Linux permite que un archivo tenga múltiples "entradas" en el sistema de archivos — multiple names que apuntan al mismo contenido. Hay dos tipos con comportamientos muy distintos.

🔗 Hard Link — enlace duro
Apunta directamente al inodo
El archivo existe mientras haya ≥1 hard link
No se puede hacer entre filesystems distintos
No se puede hacer a directorios
No "se rompe" si borras el original
Ocupa 0 bytes adicionales
🔀 Soft Link / Symlink — enlace simbólico
Apunta al nombre del archivo (ruta)
Si borras el original, el symlink queda "roto"
Puede cruzar filesystems distintos
Puede apuntar a directorios
Tiene su propio inodo pequeño
Como un acceso directo de Windows
crear y gestionar enlaces
# Crear hard link $ ln archivo-original.txt enlace-duro.txt $ ls -li # ambos tienen el mismo número de inodo 47382 -rw-r--r-- 2 hugo hugo 4521 archivo-original.txt 47382 -rw-r--r-- 2 hugo hugo 4521 enlace-duro.txt # ↑ Links: 2 — dos nombres para el mismo inodo # Crear symlink (soft link) — -s de symbolic $ ln -s /ruta/al/archivo-original.txt enlace-simbolico.txt $ ls -la lrwxrwxrwx 1 hugo hugo 28 jan 15 enlace-simbolico.txt -> /ruta/al/archivo-original.txt # ↑ La l al inicio indica symlink, y se muestra → destino # Symlink a directorio — muy útil para configuración $ ln -s ~/proyectos/cafe-codigo /var/www/cafe # Ahora /var/www/cafe apunta a tu proyecto de desarrollo # Ver el destino real de un symlink $ readlink enlace-simbolico.txt /ruta/al/archivo-original.txt $ readlink -f enlace-simbolico.txt # ruta absoluta completa

🟢 Symlinks en la práctica — los más útiles

  • /usr/bin/python → /usr/bin/python3 — que python apunte a python3
  • ~/.config/nvim → ~/dotfiles/nvim — gestión de dotfiles con Git
  • /var/www/html → ~/proyectos/web — desarrollo local en servidor
  • /etc/nginx/sites-enabled/cafe → /etc/nginx/sites-available/cafe — el patrón de nginx

Buscar archivos — find y locate
Las herramientas más potentes para encontrar lo que buscas
find — búsqueda potente en tiempo real
# Sintaxis: find [donde] [criterio] [acción] # Buscar por nombre $ find ~ -name "*.html" $ find /etc -name "nginx.conf" $ find . -iname "readme*" # -iname ignora mayúsculas # Buscar por tipo $ find ~ -type f # solo archivos regulares $ find ~ -type d # solo directorios $ find ~ -type l # solo symlinks # Buscar por tamaño $ find ~ -size +100M # archivos mayores de 100 MB $ find /tmp -size -1k # archivos menores de 1 KB # Buscar por fecha de modificación $ find ~ -mtime -7 # modificados en los últimos 7 días $ find ~ -newer archivo.txt # más recientes que archivo.txt # Ejecutar una acción en cada resultado encontrado $ find ~ -name "*.log" -delete # borrar todos los .log $ find ~ -name "*.py" -exec wc -l {} \; # contar líneas de cada .py # locate — busca en una base de datos (más rápido pero no en tiempo real) $ sudo updatedb # actualizar la base de datos $ locate nginx.conf /etc/nginx/nginx.conf

💡 grep para buscar dentro de archivos

find busca archivos por sus atributos (nombre, tamaño, fecha). grep busca texto dentro de los archivos. Combinados son imparables: grep -r "TODO" ~/proyectos --include="*.js" encuentra todas las ocurrencias de "TODO" en archivos JavaScript de tus proyectos.

tar, gzip y compresión en Linux
El formato estándar de archivos comprimidos en el ecosistema Linux

tar (Tape ARchive) empaqueta múltiples archivos en uno solo. gzip/bzip2/xz comprimen ese archivo. Juntos crean los famosos .tar.gz (o .tgz) que son el formato estándar de distribución de software en Linux.

📫 Analogía — El sobre y la cinta de embalar

tar es como meter varios documentos en un sobre — los agrupa sin comprimir. gzip es la cinta de embalar que comprime el sobre para que ocupe menos. Juntos: metes los papeles en el sobre (tar) y lo comprimes con la cinta (gzip). El resultado es un paquete compacto y portátil con todos los documentos dentro.

tar — crear, extraer e inspeccionar archivos
# CREAR — empaquetar y comprimir $ tar -czf backup.tar.gz carpeta/ # -c = crear -z = comprimir con gzip -f = nombre del archivo $ tar -cjf backup.tar.bz2 carpeta/ # bzip2 (mejor compresión, más lento) $ tar -cJf backup.tar.xz carpeta/ # xz (mejor compresión aún, más lento) # EXTRAER — descomprimir $ tar -xzf backup.tar.gz # extrae en el directorio actual $ tar -xzf backup.tar.gz -C /tmp/ # extrae en /tmp/ # VER CONTENIDO sin extraer $ tar -tzf backup.tar.gz carpeta/ carpeta/index.html carpeta/assets/logo.png # gzip / gunzip — comprimir/descomprimir un solo archivo $ gzip archivo.txt # crea archivo.txt.gz y borra el original $ gunzip archivo.txt.gz # descomprime $ gzip -k archivo.txt # -k = keep, mantiene el original # zip/unzip — formato compatible con Windows $ zip -r archivo.zip carpeta/ $ unzip archivo.zip -d /destino/

🟢 El truco de las flags de tar

Para recordar las flags más usadas de tar: piensa en cxtz f — crear, extraer, listar, gzip, fichero. Las flags más comunes son -czf (crear con gzip) y -xzf (extraer gzip). En versiones modernas de tar puedes omitir el guión: tar czf backup.tar.gz carpeta/.

✏️ Ejercicio del Nivel 13 Práctica completa

Construye un proyecto de práctica completo en tu terminal:

  1. Estructura: crea la estructura mkdir -p ~/practica-n13/{src,docs,tests,backup} y crea 3 archivos HTML vacíos en src con touch ~/practica-n13/src/{index,about,contact}.html
  2. Rutas: navega a ~/practica-n13/src y ejecuta ls ../docs (ruta relativa) y ls /home/$USER/practica-n13/backup (ruta absoluta). Nota la diferencia.
  3. Inodo: ejecuta stat ~/practica-n13/src/index.html. Anota el número de inodo. Luego crea un hard link: ln index.html ../backup/index-backup.html y ejecuta stat en ambos — ¿tienen el mismo inodo?
  4. Symlink: crea un symlink: ln -s ~/practica-n13 ~/escritorio-practica. Ejecuta ls -la ~ | grep practica — ¿ves la flecha →?
  5. find: ejecuta find ~/practica-n13 -name "*.html". ¿Cuántos archivos .html hay?
  6. tar: crea un backup: tar -czf ~/practica-n13/backup/proyecto.tar.gz ~/practica-n13/src/. Luego lista su contenido con tar -tzf ~/practica-n13/backup/proyecto.tar.gz.
  7. Limpieza: verifica el espacio usado con du -sh ~/practica-n13.

🟥 Resumen del Nivel 13

  • Linux tiene un único árbol desde /. No hay letras de unidad. Todo se monta como rama del árbol.
  • Directorios clave: /etc (config), /var/log (logs), /home (usuarios), /tmp (temporal), /proc (kernel virtual).
  • Ruta absoluta empieza con /. Ruta relativa empieza desde el directorio actual. ~ = home, .. = padre.
  • Operaciones esenciales: ls -la, cd, mkdir -p, cp -r, mv, rm -rf (con cuidado), touch.
  • El inodo contiene toda la info del archivo excepto su nombre. El directorio guarda la relación nombre→inodo.
  • Hard link — apunta al inodo, no se rompe al borrar el original. Symlink — apunta al nombre, se puede romper.
  • find — búsqueda por nombre, tipo, tamaño, fecha. Muy potente con -exec.
  • tar -czf empaquetar y comprimir. tar -xzf extraer. tar -tzf ver contenido sin extraer.
