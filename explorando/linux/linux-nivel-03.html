🌱 Nivel 3 — ¿Qué es GNU?
🏛️
El Proyecto GNU
La iniciativa que empezó 8 años antes que Linux y lo completó

En 1983, antes de que Linux existiera, Richard Stallman lanzó el Proyecto GNU con un objetivo ambicioso: crear un sistema operativo completamente libre — donde cualquiera pudiera ver el código, modificarlo y compartirlo sin restricciones.

🏗️ Analogía — Construir una ciudad sin el suelo

GNU construyó durante años todos los edificios de una ciudad: casas, tiendas, calles, semáforos, tuberías. Todo estaba listo. Pero les faltaba el suelo — el sistema operativo base que conectara todo con el hardware. Cuando Linus Torvalds creó el kernel Linux en 1991, fue como encontrar el terreno perfecto. Los edificios de GNU se instalaron sobre el suelo Linux y nació GNU/Linux.

📌 GNU es un acrónimo recursivo

GNU significa GNU's Not Unix — es un chiste de informático. El nombre se define a sí mismo en forma de broma. GNU se inspiró en Unix (el sistema operativo de los años 70), pero sin copiar su código — todo reescrito desde cero con licencia libre.

# Cronología: GNU empezó 8 años antes que Linux 1969 Unix creado en Bell Labs (AT&T) — código privado 1983 Richard Stallman anuncia el Proyecto GNU 1985 Stallman publica el Manifiesto GNU y funda la FSF 1989 Primera versión de la GNU GPL — la licencia libre 1991 Linus Torvalds crea el kernel Linux 1992 Linux adopta la GPL — GNU + Linux se unen oficialmente 1993 Nace Debian — primera gran distribución GNU/Linux
👤
Richard Stallman — El hacker filósofo
El hombre que decidió que el software debía ser libre por principio ético
🧔

Richard Matthew Stallman (RMS) — 1953

Programador del MIT en los años 70. Vivía en una cultura donde los programadores compartían el código libremente — hasta que las empresas empezaron a privatizarlo. En 1980 tuvo un momento revelador: no pudo modificar el software de una impresora Xerox porque el código era privado. Ese momento cambió su vida y, sin exagerar, la historia del software.

📚 Analogía — El bibliotecario que no puede prestar libros

Imagina que trabajas en una biblioteca y alguien te da un libro interesantísimo, pero con una condición: no puedes prestarlo, no puedes fotocopiarlo, no puedes decirle a nadie qué dice. Para Stallman, eso era exactamente lo que estaba pasando con el software — y lo encontró moralmente inaceptable. La solución no fue quejarse: fue escribir el software alternativo él mismo y regalarlo al mundo.

La Fundación del Software Libre (FSF)

En 1985 Stallman fundó la Free Software Foundation (FSF) para financiar y coordinar el proyecto GNU. La FSF sigue activa hoy, promoviendo el software libre y desarrollando herramientas como GCC y glibc.

💡 "Free as in freedom, not as in free beer"

La famosa frase de Stallman. En inglés "free" significa gratis y libre. El software libre no es necesariamente gratuito — es libre como en libertad. Puedes cobrar por él. Lo que no puedes hacer es quitarle esas libertades a quien lo recibe.

🔓
¿Qué es el Software Libre?
Las 4 libertades que definen si un software es realmente "libre"

Stallman definió con precisión qué significa que un software sea libre. No es una cuestión de precio — es una cuestión de cuatro libertades concretas que el usuario debe tener.

🏃
Libertad 0
Usar el programa con cualquier propósito, sin restricciones. Para trabajo, para jugar, para lo que quieras.
🔍
Libertad 1
Estudiar cómo funciona el programa y modificarlo. Requiere acceso al código fuente.
📤
Libertad 2
Distribuir copias del programa para ayudar a otros — con o sin cobrar dinero.
🔄
Libertad 3
Mejorar el programa y publicar esas mejoras para que toda la comunidad se beneficie.
🔓 Software Libre
Ver el código fuente completo
Modificarlo como quieras
Distribuir tus modificaciones
Usarlo en cualquier contexto
Ejemplos: Linux, Firefox, LibreOffice, VLC
🔒 Software Privativo
Ver el código fuente
Modificarlo
Distribuir copias (generalmente)
Usar para ciertos propósitos
Ejemplos: Windows, macOS, Photoshop, Office

🟢 Software Libre ≠ Open Source

Aunque se usan casi como sinónimos, hay una diferencia filosófica. Software Libre (Stallman/FSF) es una cuestión ética — la libertad es un derecho del usuario. Open Source (OSI) es una cuestión práctica — el código abierto produce mejor software. En la práctica, la mayoría de las licencias se aplican a ambas definiciones, incluida la GPL y la MIT.

📜
GNU General Public License — La GPL
La licencia que usa el kernel Linux y que protege la libertad del software

La GPL es la licencia de software libre más influyente del mundo. El kernel Linux usa la GPL versión 2. La idea central de la GPL es brillantemente simple: si usas código GPL, tu código también tiene que ser GPL. La libertad se propaga como una cadena.

🧬 Analogía — El virus de la libertad

La GPL funciona como un "virus de la libertad" — en el buen sentido. Si tomas código GPL y lo incorporas en tu programa, todo tu programa debe ser GPL. No puedes tomar software libre, mejorarlo y hacerlo privativo. La libertad se contagia obligatoriamente. Las empresas que quieren usar Linux en productos privativos tienen que negociar o usar el kernel con cuidado de no mezclar código GPL con el suyo.

Las licencias libres más comunes — comparativa

⚠️ Por qué el kernel Linux usa GPLv2 específicamente

Linus Torvalds eligió GPLv2 en 1992 y se ha negado a actualizar a GPLv3. Su razón: la GPLv3 añade restricciones sobre "tivoización" (hardware que solo acepta software firmado). Linus considera que eso va más allá de lo que debería hacer una licencia de software. Este debate sigue activo en la comunidad.

Herramientas GNU — Las que usas cada día
Los programas de GNU que forman la base de cualquier sistema Linux

Cuando abres una terminal y escribes ls, cp, grep o find — estás usando herramientas del Proyecto GNU. Sin ellas, Linux sería solo un kernel sin nada útil que hacer.

🔨 Analogía — La caja de herramientas del mecánico

El kernel Linux es el taller mecánico — tiene la estructura, la electricidad, el espacio. Las herramientas GNU son la caja de herramientas: llaves, destornilladores, alicates, martillos. Sin la caja de herramientas, el mecánico (usuario) no puede hacer nada útil en el taller. Las herramientas GNU son tan fundamentales que ni las notas porque siempre están ahí.

🐚
Bash — La shell de GNU
El intérprete de comandos que es el idioma de la terminal

Bash (Bourne Again SHell) es la shell por defecto en casi todas las distribuciones Linux. Es un proyecto GNU — fue creado para reemplazar la sh original de Unix. Cuando abres una terminal y escribes comandos, Bash los interpreta y ejecuta.

🗣️ Analogía — El intérprete humano en una conferencia

Bash es como el intérprete en una conferencia internacional. Tú hablas en tu idioma (comandos legibles para humanos: ls -la /home), el intérprete (Bash) lo traduce al idioma del sistema (llamadas al kernel) y te devuelve la respuesta traducida de vuelta. Sin el intérprete, tú y el kernel no podéis comunicaros directamente.

bash — el intérprete en acción
# Bash procesa lo que escribes ANTES de ejecutarlo # 1. Lee la línea que escribiste # 2. La analiza (parsing) # 3. Expande variables, comodines, etc. # 4. Ejecuta el comando # 5. Muestra el resultado $ echo $SHELL # ¿qué shell estás usando? /bin/bash $ bash --version # versión de Bash instalada GNU bash, version 5.2.15(1)-release # Bash también es un lenguaje de programación $ for i in 1 2 3; do echo "Número: $i"; done Número: 1 Número: 2 Número: 3

💡 Bash no es el único — pero es el más común

Existen otras shells: zsh (por defecto en macOS, muy popular con Oh My Zsh), fish (más amigable), sh (la más básica y portable), dash (muy rápida, usada en scripts de sistema). Bash es el estándar en la mayoría de sistemas Linux y la que aprenderás en esta guía.

📚
GCC y glibc — El compilador y la biblioteca C
Las dos piezas de GNU que hacen posible que el software exista

De todas las herramientas GNU, dos son las más fundamentales a nivel de infraestructura: el compilador GCC y la biblioteca C estándar glibc. Sin ellas, el software moderno simplemente no existiría.

GCC — GNU Compiler Collection

🏭 Analogía — La fábrica que convierte planos en máquinas

El código fuente en C o C++ son los planos de una máquina — instrucciones legibles por humanos. GCC es la fábrica que convierte esos planos en una máquina real (un binario ejecutable). Sin la fábrica, los planos son papel inútil. El propio kernel Linux se compila con GCC.

GCC en acción — compilar un programa en C
# Tienes este código fuente en hola.c: #include <stdio.h> int main() { printf("Hola, GNU/Linux!\n"); return 0; } # GCC lo convierte en un ejecutable: $ gcc hola.c -o hola $ ./hola Hola, GNU/Linux! # Ver la versión de GCC $ gcc --version gcc (Ubuntu 13.2.0-23ubuntu4) 13.2.0 Copyright (C) 2023 Free Software Foundation, Inc.

glibc — GNU C Library

La glibc es la biblioteca C estándar de GNU. Es la capa que conecta los programas con el kernel — proporciona funciones como printf(), malloc(), open(). Casi todo el software en Linux la usa, sea consciente de ello o no.

# Cómo se llama al kernel a través de glibc Tu programa → printf("Hola") # llamada a función de C ↓ glibc → write(1, "Hola", 4) # convierte a system call ↓ Kernel Linux → accede al hardware # muestra en pantalla # glibc es el puente entre el código C y el kernel # Sin glibc, cada programa tendría que hacer las system calls directamente

🟢 ¿Por qué glibc usa LGPL y no GPL?

Si glibc usara GPL estricta, ningún software privativo (como drivers de NVIDIA o aplicaciones comerciales) podría ejecutarse en Linux — porque todos enlazan con glibc. La LGPL (Lesser GPL) permite que software privativo use la librería sin tener que hacer su código abierto, pero cualquier modificación a glibc en sí debe seguir siendo libre.

🤝
GNU + Linux = Un sistema operativo completo
Cómo se ensamblan las piezas para formar lo que usas cada día

Ahora puedes ver el cuadro completo. GNU construyó todas las piezas del sistema operativo — todo excepto el kernel. Linux aportó el kernel que faltaba. Juntos forman un sistema operativo completo y libre.

┌─────────────────────────────────────────────────────┐ │ Lo que ves y usas: GNOME, KDE, Firefox, VS Code │ ├─────────────────────────────────────────────────────┤ │ GNU: bash, ls, grep, gcc, glibc, coreutils, make │ ├─────────────────────────────────────────────────────┤ │ Kernel Linux: scheduler, memoria, drivers, red │ ├─────────────────────────────────────────────────────┤ │ Hardware: CPU, RAM, Disco, GPU, Red, USB... │ └─────────────────────────────────────────────────────┘ └─ Todo esto junto = lo que llamamos "Linux" o "GNU/Linux"
🐧
Aportación de Linux
El kernel — la pieza que habla con el hardware. Gestión de procesos, memoria, drivers, red y seguridad.
🦬
Aportación de GNU
El resto del sistema: Bash, coreutils, GCC, glibc, grep, sed, awk, tar, make y decenas de herramientas esenciales.
🏢
Aportación de la comunidad
El escritorio (GNOME, KDE), las aplicaciones, los gestores de paquetes, la documentación y el soporte.
📦
Aportación de la distro
Empaqueta todo junto: Ubuntu, Fedora, Arch. Añaden el instalador, el configurador y la identidad visual.

🟢 Por qué GNU fue tan importante

Cuando Linus Torvalds creó el kernel Linux, no tuvo que escribir desde cero la shell, el compilador, las utilidades básicas ni la biblioteca C — todo eso ya existía como software libre gracias a GNU. Pudo centrarse en el kernel y simplemente adoptó todo el ecosistema GNU. Sin GNU, Linux habría tardado años más en convertirse en un sistema utilizable.

✏️ Ejercicio del Nivel 3 Exploración

Abre una terminal (en Linux, macOS o WSL en Windows) y ejecuta estos comandos para descubrir las herramientas GNU en tu sistema:

  1. Ejecuta bash --version — ¿qué versión de Bash tienes? Observa que dice "GNU bash".
  2. Ejecuta ls --version — ¿dice "GNU coreutils"?
  3. Ejecuta grep --version — ¿dice "GNU grep"?
  4. Ejecuta gcc --version — ¿tienes GCC instalado? Si no: sudo apt install gcc
  5. Ejecuta ldd --version — verás la versión de glibc que usa tu sistema.
  6. Crea un archivo hola.c con el código del ejemplo de arriba y compílalo con gcc hola.c -o hola. ¡Ejecuta ./hola!

Reflexión: Cuando usas ls o grep, ¿sabías que estabas usando software del Proyecto GNU de 1983? ¿Cómo cambia eso tu perspectiva sobre la terminal?

🟥 Resumen del Nivel 3

  • GNU es un proyecto de software libre lanzado por Stallman en 1983 — 8 años antes que Linux.
  • El nombre es un acrónimo recursivo: GNU's Not Unix.
  • Stallman lo inició por razones éticas: el software debe ser libre como en libertad, no como en precio.
  • El software libre garantiza 4 libertades: usar, estudiar, distribuir y mejorar.
  • La GPL es la licencia que usa el kernel Linux — el copyleft garantiza que la libertad se propague.
  • GNU aportó: Bash, coreutils (ls, cp, mv…), GCC (compilador), glibc (biblioteca C), grep, sed, awk y más.
  • Bash es la shell de GNU — el intérprete que traduce tus comandos al lenguaje del kernel.
  • glibc es el puente entre el código C de las apps y las system calls del kernel.
  • GNU + Linux = un sistema operativo completo. Sin GNU, Linux sería solo un kernel sin nada útil.
