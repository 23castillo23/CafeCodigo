Discos y su nomenclatura en Linux
Cómo Linux nombra los dispositivos de almacenamiento en /dev/

En Linux, los discos y sus particiones aparecen como archivos especiales en /dev/. El nombre del dispositivo sigue una convención que indica el tipo de interfaz y el orden de detección.

📪 Analogía — Las casillas de correo del edificio

Imagina un edificio (tu sistema) con casillas de correo en la entrada (/dev/). Cada casilla tiene un número único: sda es la primera casilla SATA/USB, sdb la segunda, nvme0n1 es la casilla NVMe especial. Dentro de cada casilla grande hay subdivisiones (sda1, sda2) — las particiones. El cartero (kernel) sabe exactamente a qué casilla entregar cada paquete de datos.

# Nomenclatura de dispositivos en /dev/ SATA / USB / SCSI sda → primer disco SATA/USB sda1 → primera partición de sda sda2 → segunda partición de sda sdb → segundo disco SATA/USB sdb1 → primera partición de sdb NVMe (SSDs modernos) nvme0n1 → primer disco NVMe (nvme0 = controladora, n1 = namespace) nvme0n1p1 → primera partición de nvme0n1 nvme0n1p2 → segunda partición nvme1n1 → segundo disco NVMe Loop devices (imágenes, Snaps) loop0 → primer dispositivo loop (para montar imágenes .iso, Snaps) loop1 → segundo dispositivo loop Dispositivos especiales sr0 → unidad de DVD/CD-ROM mmcblk0 → tarjeta SD o eMMC

Particiones — dividir el disco
MBR vs GPT y el esquema de particiones típico de Linux

Una partición es una división lógica del disco físico. Cada partición actúa como un disco independiente con su propio sistema de archivos. El mapa de particiones (dónde empieza y termina cada una) se guarda en el disco mismo, en el MBR o la tabla GPT.

gestionar particiones
# fdisk — el clásico para MBR y GPT $ sudo fdisk /dev/sdb # abre interfaz interactiva # m = ayuda n = nueva d = eliminar p = mostrar w = guardar q = salir # parted — más potente, soporta GPT bien $ sudo parted /dev/sdb # (parted) mklabel gpt → crear tabla de particiones GPT # (parted) mkpart primary 1MiB 512MiB → crear partición # (parted) print → mostrar particiones # (parted) quit → salir # gparted — versión gráfica de parted (la más fácil) $ sudo apt install gparted $ sudo gparted # Ver tabla de particiones actual $ sudo parted /dev/sda print Model: Samsung SSD 870 (scsi) Disk /dev/sda: 500GB Partition Table: gpt Number Start End Size File system Name Flags 1 1049kB 538MB 537MB fat32 boot, esp 2 538MB 500GB 499GB ext4

📌 UUID vs nombre de dispositivo en fstab

Los nombres como /dev/sda1 pueden cambiar si añades otro disco — el que era sda puede convertirse en sdb. Por eso en /etc/fstab siempre se usa el UUID (Universally Unique Identifier) de cada partición — un número que identifica la partición de forma permanente independientemente del orden de detección. Obtenerlo: lsblk -f o blkid.

Sistemas de archivos — cómo organiza Linux los datos
ext4, btrfs, xfs, tmpfs y los demás — cuándo usar cada uno

Un sistema de archivos define cómo se organizan y almacenan los datos dentro de una partición: dónde va cada archivo, cómo se indexan, qué metadatos se guardan y cómo se recupera de fallos. Es como el sistema de organización de una biblioteca.

Formatear — crear un sistema de archivos
mkfs — el comando para preparar una partición para usar
mkfs — crear sistemas de archivos
# mkfs.ext4 — el más usado $ sudo mkfs.ext4 /dev/sdb1 $ sudo mkfs.ext4 -L "datos" /dev/sdb1 # -L = etiqueta # mkfs.btrfs $ sudo mkfs.btrfs /dev/sdb1 $ sudo mkfs.btrfs -L "backup" /dev/sdb1 # mkfs.xfs $ sudo mkfs.xfs /dev/sdb1 # mkfs.vfat (para USB o partición ESP) $ sudo mkfs.vfat -F 32 /dev/sdb1 $ sudo mkfs.vfat -F 32 -n "USB-HUGO" /dev/sdb1 # mkfs.exfat (para USB compatibles con Windows) $ sudo apt install exfatprogs $ sudo mkfs.exfat /dev/sdb1 # mkswap — crear partición de swap $ sudo mkswap /dev/sdb2 $ sudo swapon /dev/sdb2 # activar el swap $ free -h # verificar que el swap está activo # Verificar y reparar sistema de archivos ext4 $ sudo fsck.ext4 -f /dev/sdb1 # solo con la partición DESMONTADA

⚠️ mkfs borra todos los datos sin confirmación

mkfs formatea la partición inmediatamente — no hay "¿estás seguro?". Confirma siempre que el dispositivo que vas a formatear (/dev/sdb1) es el correcto antes de ejecutar. Un error aquí puede borrar el sistema operativo o todos tus datos. Verifica dos veces con lsblk y df antes de formatear.

mount y umount — conectar sistemas de archivos al árbol
Cómo Linux "injerta" particiones y dispositivos en el árbol de directorios

En Linux, para acceder al contenido de una partición o dispositivo hay que montarla en un directorio del árbol. El directorio donde se monta se llama punto de montaje. Montar conecta la raíz de esa partición con ese directorio.

🌲 Analogía — Injertar una rama en el árbol

El sistema de archivos de Linux es un árbol. Montar una partición es como injertar una rama nueva en ese árbol. Si montas un USB en /media/hugo/usb, esa rama crece desde ese punto con todo el contenido del USB. Si desmontás (umount), la rama desaparece del árbol — pero el USB sigue ahí con sus datos intactos.

mount y umount — uso completo
# Ver todos los sistemas de archivos montados actualmente $ mount | grep "^/dev" /dev/nvme0n1p2 on / type ext4 (rw,relatime) /dev/nvme0n1p1 on /boot/efi type vfat (rw,relatime) /dev/sda1 on /media/hugo/datos type ext4 (rw,relatime) # Montar una partición manualmente $ sudo mkdir -p /mnt/disco-extra $ sudo mount /dev/sdb1 /mnt/disco-extra # Montar con opciones específicas $ sudo mount -o ro /dev/sdb1 /mnt/disco-extra # solo lectura $ sudo mount -o rw,noatime /dev/sdb1 /mnt/datos # no actualizar atime $ sudo mount -t ntfs /dev/sdb1 /mnt/windows # forzar tipo de FS # Montar una imagen ISO sin quemarla $ sudo mount -o loop ubuntu.iso /mnt/iso # Desmontar — siempre antes de desconectar el disco $ sudo umount /mnt/disco-extra $ sudo umount /dev/sdb1 # también funciona con el dispositivo # Si da "device is busy", ver qué proceso usa el punto de montaje $ lsof /mnt/disco-extra $ fuser -v /mnt/disco-extra # Desmontar a la fuerza (cuidado con datos sin escribir) $ sudo umount -l /mnt/disco-extra # lazy unmount — espera a que liberen
findmnt
Vista en árbol de todos los puntos de montaje — más legible que mount.
findmnt findmnt /home findmnt --df
mount -a
Montar todos los sistemas de archivos definidos en /etc/fstab que no estén ya montados.
sudo mount -a # Útil para probar fstab sin reiniciar
udisksctl
Montar/desmontar sin sudo — para el usuario normal. El gestor automático del escritorio.
udisksctl mount -b /dev/sdb1 udisksctl unmount -b /dev/sdb1
blkid
Mostrar UUID, tipo de FS y etiqueta de todas las particiones. Esencial para fstab.
sudo blkid sudo blkid /dev/sda2

/etc/fstab — montajes permanentes
El archivo que define qué se monta automáticamente en cada arranque

/etc/fstab (File System TABle) es el archivo donde se definen todos los sistemas de archivos que deben montarse automáticamente al arrancar. systemd lo lee durante el boot y monta todo lo que encuentra ahí.

# /etc/fstab — formato: dispositivo punto_montaje tipo opciones dump pass # La partición raíz (UUID recomendado, no /dev/sdXY) UUID=a1b2c3d4-e5f6-7890-abcd-ef1234567890 / ext4 defaults 0 1 # La partición EFI UUID=1234-ABCD /boot/efi vfat umask=0077 0 1 # El home en una partición separada UUID=f9e8d7c6-b5a4-3210-fedc-ba9876543210 /home ext4 defaults 0 2 # Partición swap UUID=0a1b2c3d-4e5f-6789-abcd-ef0123456789 none swap sw 0 0 # tmpfs para /tmp en RAM (más rápido, se borra al reiniciar) tmpfs /tmp tmpfs nosuid,nodev 0 0 # Disco externo de datos montado permanentemente UUID=b2c3d4e5-f6a7-8901-bcde-f12345678901 /datos ext4 defaults,nofail 0 2 # nofail = si el disco no está, no falla el arranque

⚠️ Un fstab mal escrito puede impedir el arranque

Si escribes mal el UUID o el tipo de sistema de archivos en fstab, el sistema puede no arrancar. Antes de reiniciar después de editar fstab, prueba con sudo mount -a — si da error, corrígelo antes de reiniciar. Usa siempre UUID en lugar de /dev/sdXY y añade nofail a los discos opcionales para que el sistema arranque aunque ese disco no esté presente.

LVM — gestión de volúmenes lógicos
Cómo redimensionar particiones en caliente y combinar discos fácilmente

LVM (Logical Volume Manager) añade una capa de abstracción entre los discos físicos y los sistemas de archivos. Con LVM puedes redimensionar particiones en caliente, combinar varios discos en uno lógico, y hacer snapshots sin reiniciar.

🧱 Analogía — LEGO en lugar de bloques fijos

Las particiones normales son como bloques de madera cortados a medida — una vez cortados, redimensionarlos es difícil y arriesgado. LVM es como usar LEGO: tienes bloques físicos (Physical Volumes), los metes en un cubo grande (Volume Group), y de ese cubo sacas piezas del tamaño que necesitas (Logical Volumes). ¿Necesitas más espacio? Añades más bloques LEGO al cubo sin tocar las piezas ya construidas.

# Capas de LVM Discos físicos: /dev/sda2 /dev/sdb /dev/sdc ↓ ↓ ↓ PV (Physical pv /dev/sda2 pv /dev/sdb pv /dev/sdc Volumes): ← unidades físicas reconocidas por LVM → VG (Volume ╔═══════════════════════════════════════╗ Group): ║ vg-sistema (~2 TB total) ║ ╚═══════════════════════════════════════╝ ↓ ↓ ↓ LV (Logical lv-root (50G) lv-home (500G) lv-datos (1TB) Volumes): / /home /datos sistemas de archivos normales por encima
LVM — comandos esenciales
## VER LVM ACTUAL $ sudo pvs # Physical Volumes $ sudo vgs # Volume Groups $ sudo lvs # Logical Volumes $ sudo lvdisplay # info detallada de los LVs ## CREAR LVM (flujo básico) # 1. Crear Physical Volume sobre una partición $ sudo pvcreate /dev/sdb # 2. Crear Volume Group con ese PV $ sudo vgcreate vg-datos /dev/sdb # 3. Crear Logical Volume de 100GB dentro del VG $ sudo lvcreate -L 100G -n lv-proyectos vg-datos # 4. Formatear y montar como siempre $ sudo mkfs.ext4 /dev/vg-datos/lv-proyectos $ sudo mount /dev/vg-datos/lv-proyectos /mnt/proyectos ## AMPLIAR UN VOLUMEN LÓGICO (la killer feature de LVM) # Ampliar el LV en 50GB más $ sudo lvextend -L +50G /dev/vg-datos/lv-proyectos # Ampliar el sistema de archivos ext4 para usar el nuevo espacio $ sudo resize2fs /dev/vg-datos/lv-proyectos # (con btrfs): sudo btrfs filesystem resize max /mnt/proyectos
✏️ Ejercicio del Nivel 18 Almacenamiento

Explora el almacenamiento de tu sistema sin modificar nada:

  1. Discos: ejecuta lsblk y lsblk -f. ¿Cuántos discos tienes? ¿Cuántas particiones? ¿Qué sistema de archivos usa cada una?
  2. UUID: ejecuta sudo blkid. Anota el UUID de tu partición raíz (/). Luego compara con lo que hay en cat /etc/fstab — ¿coinciden?
  3. Montajes: ejecuta findmnt. ¿Cuántos sistemas de archivos distintos hay montados? ¿Puedes ver tmpfs, devtmpfs y los de tu disco?
  4. Espacio: ejecuta df -h. ¿Cuánto espacio libre queda en tu partición raíz? ¿Y en home?
  5. Ocupación: ejecuta du -sh ~/*/ y du -sh ~/.cache. ¿Qué carpeta ocupa más espacio?
  6. LVM: ejecuta sudo lvs 2>/dev/null && echo "Tienes LVM" || echo "Sin LVM". ¿Tu instalación usa LVM?
  7. Limpieza: ejecuta sudo apt clean && sudo apt autoremove -y. Luego df -h de nuevo — ¿cuánto espacio liberaste?

Reto: usa sudo apt install ncdu y luego sudo ncdu /. Navega para encontrar los 3 directorios que más espacio ocupan en tu sistema.

🟥 Resumen del Nivel 18

  • Los discos aparecen en /dev/: sda (SATA/USB), nvme0n1 (NVMe). Las particiones son sda1, nvme0n1p1…
  • Siempre usar UUID para identificar particiones en fstab — los nombres /dev/sdXY pueden cambiar.
  • Esquema típico en desktop: ESP (FAT32, 512MB) + swap + / (ext4) + /home (ext4).
  • ext4 — el estándar estable. btrfs — moderno con snapshots. xfs — para servidores grandes. tmpfs — en RAM.
  • mkfs.ext4 /dev/sdb1 formatea una partición — sin vuelta atrás. Verificar dos veces antes de ejecutar.
  • mount /dev/sdb1 /mnt/punto conecta la partición al árbol. umount la desconecta.
  • /etc/fstab define los montajes automáticos del arranque. Probar con mount -a antes de reiniciar.
  • df -h — espacio libre por sistema de archivos. du -sh directorio — espacio que ocupa un directorio. ncdu — explorador interactivo.
  • LVM añade flexibilidad: Physical Volumes → Volume Groups → Logical Volumes. Permite redimensionar en caliente con lvextend + resize2fs.
