Terminal vs Shell — la diferencia que confunde a todos
No son lo mismo — entender la distinción cambia cómo piensas en la línea de comandos

La mayoría de personas usa "terminal" y "shell" como sinónimos. No lo son — son dos piezas distintas que trabajan juntas.

🖥️ Terminal (Emulador)
La ventana gráfica que ves en pantalla. Dibuja texto, gestiona colores y fuentes, captura tu teclado. GNOME Terminal, Alacritty, Kitty, Tilix. Es solo un contenedor visual.
🐚 Shell (Intérprete)
El programa que interpreta y ejecuta tus comandos. Lee lo que escribes, lo analiza y llama al kernel. Bash, Zsh, Fish, Sh. Es el cerebro de la operación.

📺 Analogía — El televisor y el canal

El emulador de terminal es el televisor — la pantalla, los altavoces, los botones físicos. La shell es el canal de televisión — el contenido real que se transmite. Puedes cambiar el televisor (Alacritty vs GNOME Terminal) sin cambiar el contenido (Bash). Y puedes cambiar el canal (Bash vs Zsh) sin cambiar el televisor.

Anatomía del prompt
Todo lo que te dice esa línea antes de que escribas

El prompt es el texto que Bash muestra esperando que escribas un comando. No es decoración — te da información esencial sobre tu contexto actual.

hugo@ubuntu:~/proyectos/web$
hugo → usuario actual ubuntu → hostname de la máquina ~/proyectos/web → directorio actual $ → usuario normal (# = root)
el prompt en acción
# Prompt de usuario normal — $ al final hugo@ubuntu:~$ whoami hugo # Prompt de root — # al final (¡cuidado!) root@ubuntu:~# whoami root # Ver y personalizar la variable PS1 (define el prompt) $ echo $PS1 \u@\h:\w\$ # \u = usuario · \h = hostname · \w = directorio · \$ = símbolo # Cambiar el prompt temporalmente con colores $ PS1="\[\033[32m\]\u\[\033[0m\]@\h:\w$ "

🟢 Oh My Bash / Oh My Zsh — prompts hermosos con una línea

Personalizar el prompt manualmente con códigos de color es tedioso. Oh My Bash (para Bash) y Oh My Zsh (para Zsh) son frameworks que añaden temas hermosos, autocompletado mejorado y plugins con un solo comando de instalación. También existe Starship — un prompt ultra-rápido escrito en Rust que funciona con cualquier shell.

Variables en Bash
Variables locales, de entorno y las más importantes del sistema

Las variables en Bash almacenan valores que pueden ser cadenas de texto, números o resultados de comandos. Son la memoria de la shell.

variables en Bash — sintaxis completa
# Definir una variable (sin espacios alrededor del =) $ nombre="Hugo" $ edad=25 $ proyecto="cafe-codigo" # Usar una variable con $ $ echo "Hola, $nombre. Tienes $edad años." Hola, Hugo. Tienes 25 años. # Usar {} para delimitar el nombre de la variable $ echo "${nombre}ito" Hugito # Capturar la salida de un comando en una variable $ fecha=$(date +%Y-%m-%d) $ echo "Hoy es: $fecha" Hoy es: 2025-01-15 # Exportar variable para que la vean los procesos hijos $ export MI_VAR="valor" # Variables de solo lectura (constantes) $ readonly VERSION="1.0.0" # Ver todas las variables de entorno $ env | head -10 HOME=/home/hugo USER=hugo SHELL=/bin/bash

💡 La variable $? — el código de salida

Cada comando termina con un código de salida: 0 significa éxito y cualquier otro número significa error. La variable $? guarda el código del último comando. Es fundamental en scripts para tomar decisiones: if [ $? -eq 0 ]; then echo "OK"; else echo "ERROR"; fi. Muchos programas usan códigos específicos (1=error general, 127=comando no encontrado, 130=interrumpido por Ctrl+C).

El PATH — cómo Bash encuentra los comandos
La variable más importante del sistema — sin entenderla no puedes instalar herramientas correctamente

Cuando escribes git en la terminal, Bash no sabe dónde está ese programa. Busca en una lista de directorios definida en la variable PATH. Si lo encuentra, lo ejecuta. Si no, obtienes "command not found".

🗺️ Analogía — La guía telefónica de los comandos

El PATH es como la guía telefónica de tu ciudad. Cuando quieres llamar a "la pizzería", buscas en la guía — no necesitas saber la dirección exacta de cada pizzería de la ciudad. Cuando escribes git, Bash busca "git" en el PATH — no necesitas escribir /usr/bin/git cada vez. Si agregas una nueva "pizzería" (programa), tienes que añadir su "número" (directorio) a la guía (PATH) para que Bash lo encuentre.

PATH — ver, entender y modificar
# Ver el PATH actual (directorios separados por :) $ echo $PATH /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/home/hugo/.local/bin # Ver en forma legible $ echo $PATH | tr ':' '\n' /usr/local/sbin /usr/local/bin /usr/sbin /usr/bin /sbin /bin /home/hugo/.local/bin # Saber dónde está un comando exactamente $ which git /usr/bin/git $ which python3 /usr/bin/python3 # Añadir un directorio al PATH (temporalmente en esta sesión) $ export PATH="$HOME/.local/bin:$PATH" # Añadir al PATH permanentemente (en ~/.bashrc) $ echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc $ source ~/.bashrc # recargar .bashrc sin reiniciar la terminal

⚠️ El orden en el PATH importa

Bash busca en los directorios del PATH de izquierda a derecha y ejecuta el primer resultado que encuentra. Si tienes dos versiones de Python — una en /usr/bin/ y otra en /home/hugo/.local/bin/ — la que aparezca primero en el PATH es la que se ejecuta. Por eso añadir directorios al principio del PATH (PATH="$HOME/.local/bin:$PATH") les da prioridad sobre los del sistema.

El archivo ~/.bashrc — la configuración de tu shell

El archivo ~/.bashrc se ejecuta cada vez que abres una terminal interactiva. Es donde defines variables de entorno permanentes, alias, funciones y modificaciones al PATH.

# ~/.bashrc — ejemplo de configuración básica # Variables de entorno export EDITOR="code" export LANG="es_MX.UTF-8" # Añadir directorios al PATH export PATH="$HOME/.local/bin:$HOME/.cargo/bin:$PATH" # Alias útiles alias ll='ls -alF --color=auto' alias la='ls -A' alias ..='cd ..' alias ...='cd ../..' alias grep='grep --color=auto' # Historial mejorado export HISTSIZE=10000 export HISTFILESIZE=20000 export HISTCONTROL=ignoredups:erasedups # Prompt personalizado PS1='\[\033[01;32m\]\u@\h\[\033[00m\]:\[\033[01;34m\]\w\[\033[00m\]\$ '

Alias — comandos cortos para comandos largos
La forma más rápida de multiplicar tu velocidad en la terminal

Un alias es un nombre corto que sustituye a un comando (posiblemente largo y complicado). Una vez definido, puedes escribir el alias en lugar del comando completo. Son una de las primeras cosas que deberías configurar en tu .bashrc.

alias — crear, usar y gestionar
# Crear un alias (temporal — solo en esta sesión) $ alias ll='ls -la --color=auto' $ alias gs='git status' $ alias gc='git commit -m' $ alias gp='git push' $ alias update='sudo apt update && sudo apt upgrade -y' # Usar el alias $ ll total 48 drwxr-xr-x 2 hugo hugo 4096 jan 15 10:23 . drwxr-xr-x 8 hugo hugo 4096 jan 15 10:20 .. # Ver todos los alias activos $ alias alias gs='git status' alias ll='ls -la --color=auto' # Eliminar un alias $ unalias gs # Ejecutar el comando original sin el alias (con \) $ \ls # ejecuta ls sin el alias
alias .. y ...
Navegar directorios hacia arriba rápidamente.
alias ..='cd ..' alias ...='cd ../..'
alias para Git
Los comandos git más usados reducidos a 2 caracteres.
alias gs='git status' alias ga='git add .' alias gc='git commit -m' alias gp='git push'
alias update
Actualizar el sistema con un solo comando.
alias update='sudo apt update && sudo apt upgrade -y && sudo apt autoremove -y'
alias para Python
Si tienes Python 2 y 3 instalados.
alias python='python3' alias pip='pip3' alias venv='python3 -m venv'

Historial de comandos — tu memoria de la terminal
Cómo buscar, reusar y gestionar el historial de Bash

Bash guarda todos los comandos que ejecutas en un archivo (~/.bash_history). El historial bien configurado es una de las herramientas de productividad más poderosas de la terminal.

historial — todos los trucos
# Ver el historial completo $ history 998 git push origin main 999 npm run dev 1000 sudo apt update # Buscar en el historial — Ctrl+R (búsqueda inversa interactiva) # Pulsa Ctrl+R y escribe parte del comando que buscas # Pulsa Ctrl+R otra vez para ver el siguiente resultado # Ejecutar el último comando que empezó con "git" $ !git git push origin main # Ejecutar el comando número 998 $ !998 # Repetir el último comando $ !! # Usar el último argumento del comando anterior con !$ $ mkdir proyectos/nuevo-sitio $ cd !$ # equivale a: cd proyectos/nuevo-sitio # Buscar comandos en el historial con grep $ history | grep "docker" 234 docker ps 567 docker-compose up -d # Limpiar el historial $ history -c && history -w

🟢 Ctrl+R — el atajo de historial más importante

Ctrl+R activa la búsqueda reversa interactiva: empieza a escribir parte de un comando y Bash te muestra el más reciente que coincide. Pulsa Ctrl+R otra vez para ver el anterior. Cuando encuentres el que buscas, pulsa Enter para ejecutarlo o las flechas para editarlo. Es el atajo que más tiempo ahorra a diario.

Redirección de entrada/salida
stdin, stdout, stderr y cómo controlar a dónde van los datos

En Linux, cada proceso tiene tres canales de datos estándar: entrada (stdin), salida (stdout) y errores (stderr). La redirección te permite cambiar de dónde vienen los datos y a dónde van — en lugar de teclado y pantalla, pueden ser archivos.

🚿 Analogía — Las tuberías de agua

stdin, stdout y stderr son como tuberías de agua. Normalmente el agua (datos) entra por el grifo (teclado) y sale por el desagüe (pantalla). La redirección te permite cambiar las tuberías: conectar la entrada a un depósito (archivo), mandar la salida a otro depósito, o separar el agua limpia (stdout) del agua sucia (stderr) en recipientes distintos.

redirección — todos los operadores
# stdout (>) — redirigir la salida a un archivo (SOBREESCRIBE) $ ls -la > lista.txt # guarda la lista en lista.txt $ echo "Hola" > archivo.txt # crea o sobreescribe archivo.txt # stdout (>>) — AÑADIR al final del archivo (no sobreescribe) $ echo "línea 1" > log.txt $ echo "línea 2" >> log.txt # añade al final, no borra línea 1 # stdin (<) — leer entrada desde un archivo $ sort < lista.txt # sort lee de lista.txt en vez del teclado $ wc -l < archivo.txt # cuenta las líneas del archivo # stderr (2>) — redirigir errores a un archivo $ ls /no-existe 2> errores.txt $ gcc programa.c 2> errores-compilacion.txt # Redirigir stdout Y stderr al mismo archivo $ comando > salida.txt 2>&1 # clásico $ comando &> salida.txt # sintaxis moderna # Descartar errores (enviarlos al agujero negro) $ comando 2>/dev/null # Descartar TODA la salida $ comando &>/dev/null
# Los tres file descriptors estándar stdin (0) → teclado por defecto → puede venir de un archivo con < stdout (1) → pantalla por defecto → puede ir a un archivo con > o >> stderr (2) → pantalla por defecto → puede ir a un archivo con 2> # 2>&1 significa "redirigir stderr (2) al mismo sitio que stdout (1)"
🔗
Pipes — encadenar comandos
La filosofía Unix: programas pequeños que hacen una cosa bien y se conectan entre sí

Un pipe (|) conecta la salida de un comando con la entrada del siguiente. Es la implementación de la filosofía Unix: en lugar de un programa gigante que hace todo, tienes muchos programas pequeños especializados que puedes encadenar.

🏭 Analogía — La cadena de montaje

Un pipe es una cadena de montaje. En la primera estación tomas los materiales brutos (ls, cat, find…). Cada estación siguiente procesa lo que recibe de la anterior y pasa el resultado a la siguiente (grep filtra, sort ordena, head trunca, wc cuenta). Al final de la cadena obtienes el producto terminado — exactamente lo que necesitabas.

pipes — del simple al complejo
# Simple: listar y filtrar $ ls -la | grep ".html" -rw-r--r-- 1 hugo hugo 4521 index.html -rw-r--r-- 1 hugo hugo 2341 about.html # Contar cuántos procesos corre Firefox $ ps aux | grep firefox | wc -l 8 # Los 5 procesos que más CPU consumen $ ps aux --sort=-%cpu | head -6 # Buscar en logs y mostrar solo las últimas 20 líneas de errores $ cat /var/log/syslog | grep "error" | tail -20 # Contar cuántos archivos .js hay en el proyecto $ find . -name "*.js" | wc -l 47 # Los 10 archivos más grandes del sistema $ du -ah / 2>/dev/null | sort -rh | head -10 # Ver las IPs que más conexiones hacen al servidor $ cat /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10 # Cadena compleja: palabras únicas en un archivo, ordenadas $ cat texto.txt | tr ' ' '\n' | sort | uniq | head -20

🟢 tee — bifurcar la salida

tee lee de stdin y escribe simultáneamente a stdout Y a un archivo. Perfecto cuando quieres ver la salida en pantalla y guardarla al mismo tiempo: make build 2>&1 | tee build.log — ves el output en tiempo real y queda guardado en build.log para revisar después.

Atajos de teclado — velocidad en la terminal
Los atajos que usan los profesionales a diario

La terminal es mucho más rápida con el teclado que con el ratón. Estos atajos de Bash son los que más productividad dan una vez que los interiorizas — y se aprenden en una semana de uso.

autocompletado con Tab

✏️ Ejercicio del Nivel 12 Práctica intensiva

Abre la terminal y practica cada concepto de este nivel:

  1. Variables: define nombre="TuNombre" y version=$(uname -r). Luego ejecuta echo "Hola $nombre, tu kernel es $version".
  2. PATH: ejecuta echo $PATH | tr ':' '\n'. Cuenta cuántos directorios tiene tu PATH. Ejecuta which ls, which git y which python3.
  3. Alias: crea estos alias y pruébalos: alias ll='ls -alh --color=auto', alias ..='cd ..', alias gs='git status'. Añádelos a tu ~/.bashrc.
  4. Historial: ejecuta 5 comandos distintos. Luego prueba Ctrl+R y busca uno de ellos. Prueba también !! para repetir el último.
  5. Redirección: ejecuta ls -la ~ > mi-home.txt. Luego cat mi-home.txt | wc -l. ¿Cuántos archivos tienes en tu home?
  6. Pipes: ejecuta ps aux | grep bash | head -5. Luego find ~ -name "*.html" 2>/dev/null | wc -l — ¿cuántos HTML tienes?
  7. Atajos: escribe un comando largo y practica: Ctrl+A (ir al inicio), Ctrl+E (ir al final), Ctrl+W (borrar palabra), Ctrl+K (borrar hasta el final).

Reto final: en una sola línea con pipes, muestra los 5 archivos más grandes de tu directorio home: du -ah ~/* 2>/dev/null | sort -rh | head -5

🟥 Resumen del Nivel 12

  • La terminal es la ventana gráfica. La shell (Bash) es el intérprete — son dos piezas distintas.
  • El prompt muestra usuario, host, directorio actual y si eres root (#) o usuario normal ($).
  • Variables: nombre="valor", usar con $nombre. Exportar con export para que las vean los procesos hijos.
  • El PATH es la lista de directorios donde Bash busca comandos — de izquierda a derecha. Añadir con export PATH="$dir:$PATH".
  • ~/.bashrc — se ejecuta al abrir la terminal. Aquí van PATH, alias y variables permanentes.
  • Alias: alias ll='ls -la' — atajos para comandos largos. Añadir al .bashrc para que persistan.
  • Historial: Ctrl+R para búsqueda inversa. !! repite el último. !$ usa el último argumento.
  • Redirección: > sobreescribe, >> añade, < lee de archivo, 2> redirige errores, 2>/dev/null descarta errores.
  • Pipes | encadenan comandos — la salida de uno es la entrada del siguiente.
  • Atajos clave: Ctrl+R, Ctrl+C, Ctrl+L, Ctrl+A/E, Ctrl+W/K/U, Tab.
