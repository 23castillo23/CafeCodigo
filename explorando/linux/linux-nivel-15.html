Los métodos para instalar software en Linux
No hay una sola forma — cada método tiene su propósito y sus ventajas

Una de las diferencias más notorias entre Linux y Windows/macOS es que en Linux no descargas un instalador .exe desde una web aleatoria. El software viene de fuentes verificadas y organizadas llamadas repositorios. Pero también existen formatos universales que funcionan en cualquier distro.

🏪 Analogía — Supermercado, tienda de especialidad y mercado

Instalar software en Linux es como abastecerse de comida: APT es el supermercado del barrio — todo verificado, fresco, entrega a domicilio, lo más cómodo. Snap/Flatpak son tiendas de marca — el producto viene empaquetado directamente del fabricante, sin intermediarios. AppImage es la comida de tupper — el chef te manda todo listo, sin instalación. Compilar desde fuente es cocinar tú mismo — máximo control pero más trabajo.

dpkg — la base del sistema de paquetes Debian
El instalador de bajo nivel sobre el que se construye APT

dpkg (Debian Package) es la herramienta de más bajo nivel para gestionar paquetes .deb. APT usa dpkg internamente — cuando APT instala algo, al final llama a dpkg para hacer el trabajo real. Tú usas dpkg directamente cuando tienes un archivo .deb descargado manualmente.

dpkg — comandos esenciales
# Instalar un .deb descargado manualmente $ sudo dpkg -i google-chrome-stable_amd64.deb # Si hay errores de dependencias, arreglarlos con: $ sudo apt install -f # Eliminar un paquete (mantiene archivos de configuración) $ sudo dpkg -r google-chrome-stable # Purgar un paquete (elimina también la configuración) $ sudo dpkg -P google-chrome-stable # Listar todos los paquetes instalados $ dpkg -l | head -20 ||/ Name Version Architecture Description ii bash 5.2-2ubuntu4 amd64 GNU Bourne Again SHell ii git 1:2.43.0 amd64 fast, scalable, distributed revision control # Ver si un paquete específico está instalado $ dpkg -l git ii git 1:2.43.0-1ubuntu7 amd64 fast, scalable... # ii = instalado rc = eliminado pero conf. aún presente un = no instalado # Ver qué archivos instaló un paquete $ dpkg -L git | head -10 /usr/bin/git /usr/lib/git-core/git /usr/share/man/man1/git.1.gz # Saber a qué paquete pertenece un archivo $ dpkg -S /usr/bin/git git: /usr/bin/git # Inspeccionar un .deb sin instalarlo $ dpkg -I programa.deb

💡 La diferencia entre -r y -P

dpkg -r (remove) elimina los archivos del programa pero deja los archivos de configuración — útil si quieres reinstalar después con la misma configuración. dpkg -P (purge) lo elimina todo incluyendo la configuración — limpieza completa. En APT se usan como apt remove y apt purge.

🚀
APT — el gestor de paquetes que usarás cada día
Advanced Package Tool — resolución automática de dependencias desde repositorios

APT (Advanced Package Tool) es la capa de alto nivel sobre dpkg. Su superpoder: resolver dependencias automáticamente. Si quieres instalar Firefox y Firefox necesita libssl, libnss y otras 12 bibliotecas, APT las instala todas sin que tengas que preocuparte.

1
apt update
Descarga la lista actualizada de paquetes disponibles de todos los repositorios. No instala nada — solo actualiza el catálogo local.
2
apt install nombre
Busca el paquete en el catálogo, calcula todas las dependencias necesarias, descarga todo y llama a dpkg para instalarlo.
3
apt upgrade
Actualiza todos los paquetes instalados a su versión más reciente disponible en los repositorios. Siempre hacer update antes.
APT — todos los comandos importantes
## INSTALAR Y ELIMINAR $ sudo apt install git # instalar un paquete $ sudo apt install git vim curl # varios a la vez $ sudo apt install git -y # sin preguntar confirmación $ sudo apt remove git # eliminar (conserva config) $ sudo apt purge git # eliminar + borrar config $ sudo apt autoremove # eliminar dependencias huérfanas ## ACTUALIZAR $ sudo apt update # actualizar el catálogo de paquetes $ sudo apt upgrade # actualizar todos los paquetes instalados $ sudo apt full-upgrade # upgrade + elimina paquetes si es necesario $ sudo apt update && sudo apt upgrade -y # el comando de actualización completo ## BUSCAR Y EXPLORAR $ apt search nodejs # buscar paquetes por nombre/descripción $ apt show git # ver info detallada de un paquete $ apt list --installed # listar paquetes instalados $ apt list --upgradable # paquetes con actualización disponible ## LIMPIAR $ sudo apt clean # borrar caché de paquetes descargados $ sudo apt autoclean # borrar solo paquetes obsoletos del caché $ sudo apt autoremove --purge # eliminar dependencias + config

🟢 apt vs apt-get — ¿cuál usar?

apt es la interfaz moderna con barra de progreso y salida más limpia — úsala en la terminal interactiva. apt-get es la interfaz clásica, más estable para scripts — úsala en scripts bash que necesitan output predecible. Ambas hacen lo mismo por debajo. En guías antiguas verás apt-get — funciona igual, solo es más verbose.

🗄️
Repositorios — de dónde viene el software
PPAs, repositorios de terceros y cómo añadirlos correctamente

Un repositorio es un servidor que aloja paquetes .deb. APT mantiene una lista de repositorios en /etc/apt/sources.list y en archivos dentro de /etc/apt/sources.list.d/. Cuando ejecutas apt install, APT busca en todos los repositorios configurados.

repositorios — ver y añadir
# Ver los repositorios configurados $ cat /etc/apt/sources.list deb http://archive.ubuntu.com/ubuntu noble main restricted deb http://archive.ubuntu.com/ubuntu noble universe deb http://archive.ubuntu.com/ubuntu noble-security main restricted # Añadir un PPA (Personal Package Archive) — repositorio de terceros $ sudo add-apt-repository ppa:papirus/papirus $ sudo apt update $ sudo apt install papirus-icon-theme # Añadir repositorio con clave GPG (método moderno, más seguro) # Ejemplo: instalar Node.js desde el repo oficial de NodeSource $ curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - $ sudo apt install nodejs # Eliminar un repositorio PPA $ sudo add-apt-repository --remove ppa:papirus/papirus # Ver todos los repositorios extra añadidos $ ls /etc/apt/sources.list.d/ nodesource.list papirus-ubuntu-papirus-noble.list vscode.list
Componente UbuntuQué contiene
mainSoftware libre con soporte oficial de Canonical. El más verificado.
restrictedDrivers propietarios (NVIDIA, Wi-Fi) con soporte oficial pero licencia no libre.
universeSoftware libre mantenido por la comunidad. Gran variedad pero soporte limitado.
multiverseSoftware propietario o con restricciones legales. No habilitado por defecto.

⚠️ Cuidado con los PPAs

Los PPAs son repositorios de terceros — no verificados por Canonical. Un PPA comprometido puede instalar software malicioso con privilegios de root. Usa solo PPAs de fuentes de confianza (proyectos conocidos, desarrolladores verificados). Antes de añadir un PPA busca opiniones de la comunidad.

🔵
Snap — paquetes universales sandboxeados
El formato universal de Canonical que funciona en cualquier distro con systemd

Snap es un formato de paquete desarrollado por Canonical (la empresa detrás de Ubuntu). Los paquetes Snap incluyen la aplicación y todas sus dependencias en un único archivo comprimido. Corren en un sandbox aislado y se actualizan automáticamente.

snap — gestión completa
# Buscar e instalar snaps $ snap find spotify $ sudo snap install spotify $ sudo snap install code --classic # --classic rompe el sandbox (como una app normal) # Ver snaps instalados $ snap list Name Version Rev Tracking Publisher Notes core22 20240111 1122 latest/stable canonical✓ base spotify 1.2.31 78 latest/stable spotify✓ - # Actualizar snaps $ sudo snap refresh # actualizar todos los snaps $ sudo snap refresh spotify # actualizar solo spotify # Eliminar un snap $ sudo snap remove spotify # Ver información de un snap $ snap info firefox

📌 La controversia de Snap en la comunidad

Snap tiene sus detractores: los snaps arrancan más lento que las apps nativas, el snap store es controlado exclusivamente por Canonical (no hay mirrors ni alternativas), y en Ubuntu 22.04+ Firefox viene como snap por defecto sin opción fácil de cambiarlo. La alternativa más popular en la comunidad es Flatpak.

🟣
Flatpak — el preferido de la comunidad
Paquetes universales con Flathub como tienda central y mejor integración de escritorio

Flatpak es la alternativa comunitaria a Snap, impulsada por Red Hat y la comunidad GNOME. Su tienda principal es Flathub — un repositorio enorme con miles de aplicaciones. Tiene mejor integración con los temas del escritorio que Snap.

flatpak — instalación y gestión
# Instalar Flatpak (si no viene con tu distro) $ sudo apt install flatpak $ sudo apt install gnome-software-plugin-flatpak # integración con GNOME Software # Añadir el repositorio Flathub (la tienda principal) $ flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo # Buscar e instalar apps desde Flathub $ flatpak search gimp $ flatpak install flathub org.gimp.GIMP $ flatpak install flathub com.spotify.Client $ flatpak install flathub org.videolan.VLC # Ejecutar una app Flatpak $ flatpak run org.gimp.GIMP # Ver Flatpaks instalados $ flatpak list Name Application ID Version Branch GIMP org.gimp.GIMP 2.10.36 stable Spotify com.spotify.Client 1.2.31 stable # Actualizar todos los Flatpaks $ flatpak update # Eliminar un Flatpak $ flatpak uninstall org.gimp.GIMP $ flatpak uninstall --unused # eliminar runtimes no usados

💿
AppImage — sin instalación, sin root
Un archivo, doble clic y corre — la app más portable de Linux

Un AppImage es un archivo único autocontenido que incluye la aplicación y todas sus dependencias. No requiere instalación, no necesita root, no modifica el sistema. Perfecta para probar software, usar versiones específicas o en sistemas donde no tienes privilegios.

AppImage — descargar y ejecutar
# 1. Descargar el AppImage (ejemplo: Obsidian) $ wget https://github.com/obsidianmd/obsidian-releases/releases/download/v1.5.3/Obsidian-1.5.3.AppImage # 2. Darle permiso de ejecución $ chmod +x Obsidian-1.5.3.AppImage # 3. Ejecutar directamente $ ./Obsidian-1.5.3.AppImage # Opcional: mover a un directorio conveniente $ mkdir -p ~/.local/bin/appimages $ mv Obsidian-1.5.3.AppImage ~/.local/bin/appimages/ # Si falta libfuse2 (dependencia de AppImage en Ubuntu 22.04+) $ sudo apt install libfuse2 # AppImageLauncher — gestor visual de AppImages (opcional) $ sudo add-apt-repository ppa:appimagelauncher-team/stable $ sudo apt install appimagelauncher # Integra los AppImages en el menú de apps automáticamente

🟢 Dónde encontrar AppImages

AppImageHub (appimage.github.io) es el directorio principal. También muchos proyectos publican AppImages en sus releases de GitHub: GIMP, Inkscape, KeePass, Obsidian, DaVinci Resolve. Busca en la sección "Releases" del repositorio de GitHub del proyecto.

🔧
Compilar desde fuente — el método de los expertos
Cuando necesitas la versión exacta, con opciones específicas, que no está en ningún repositorio

Compilar desde fuente significa descargar el código fuente de un programa y compilarlo tú mismo para tu sistema. Es más lento y complejo, pero da control total: versión exacta, opciones de compilación personalizadas, parches específicos.

🍕 Analogía — Hacer la pizza desde cero

Compilar desde fuente es como hacer una pizza desde cero: eliges exactamente la harina, el tomate, los ingredientes y el tiempo de horneado. Tarda más que comprar una pizza hecha (apt install) o semicongelada (AppImage), pero el resultado puede ser exactamente lo que necesitas — con esa feature experimental que ningún paquete de repositorio incluye todavía.

compilar desde fuente — el flujo estándar
# 0. Instalar las herramientas de compilación $ sudo apt install build-essential git cmake pkg-config # build-essential incluye: gcc, g++, make, libc-dev # 1. Obtener el código fuente $ git clone https://github.com/proyecto/programa.git $ cd programa/ # O descargar tarball: $ wget https://ejemplo.com/programa-2.1.tar.gz $ tar -xzf programa-2.1.tar.gz && cd programa-2.1/ # 2. Instalar dependencias de compilación $ sudo apt install libssl-dev libcurl4-openssl-dev zlib1g-dev # (las dependencias varían — consulta el README del proyecto) # 3A. Flujo autoconf (./configure) — el clásico $ ./configure --prefix=/usr/local # configura y detecta el sistema $ make -j$(nproc) # compila usando todos los núcleos CPU $ sudo make install # instala en /usr/local/ # 3B. Flujo CMake — el moderno $ mkdir build && cd build $ cmake .. -DCMAKE_INSTALL_PREFIX=/usr/local -DCMAKE_BUILD_TYPE=Release $ make -j$(nproc) $ sudo make install # Desinstalar (si el proyecto lo soporta) $ sudo make uninstall
build-essential
Metapaquete con todo lo necesario para compilar: gcc, g++, make, headers de glibc.
sudo apt install build-essential
make -j$(nproc)
Compila usando todos los núcleos disponibles en paralelo. Mucho más rápido que make solo.
make -j$(nproc) # $(nproc) = número de núcleos CPU
checkinstall
En lugar de make install, crea un .deb del programa compilado. Permite desinstalarlo limpiamente con dpkg después.
sudo apt install checkinstall sudo checkinstall
apt build-dep
Instala automáticamente todas las dependencias de compilación de un paquete de los repos.
sudo apt build-dep ffmpeg

⚠️ make install ensucia el sistema

sudo make install copia archivos directamente en /usr/local/ sin registrarlos en ningún gestor de paquetes. Esto dificulta desinstalarlo después. La solución: usa checkinstall en lugar de make install — crea un .deb del programa compilado que puedes gestionar con dpkg normalmente. O usa --prefix=$HOME/.local para instalar solo en tu home sin root.

✏️ Ejercicio del Nivel 15 Instalación real

Practica los principales métodos de instalación en tu sistema:

  1. APT básico: ejecuta sudo apt update && sudo apt install tree htop curl -y. Luego prueba cada uno: tree ~, htop (q para salir), curl https://example.com.
  2. Explorar dpkg: ejecuta dpkg -L git | head -10 — ¿ves dónde instaló cada archivo? Luego dpkg -S /usr/bin/curl — ¿a qué paquete pertenece curl?
  3. Buscar: ejecuta apt search "text editor" | head -20. ¿Cuántos editores de texto hay en los repos?
  4. Flatpak: si no tienes Flatpak: sudo apt install flatpak && flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo. Luego flatpak search vlc.
  5. AppImage: descarga un AppImage de tu elección desde appimage.github.io, dale permisos con chmod +x *.AppImage y ejecútalo.
  6. Desde fuente (rápido): instala sudo apt install build-essential y ejecuta gcc --version. ¿Qué versión de GCC tienes?

Reflexión: ¿Cuál método usarías para instalar cada uno de estos? Firefox, una versión beta de un juego indie, una app que solo publicó el dev como AppImage, y el kernel Linux con una patch específica.

🟥 Resumen del Nivel 15

  • dpkg — instalador de bajo nivel para archivos .deb. Sin resolución de dependencias. Base de APT.
  • APT — el gestor del día a día en Debian/Ubuntu. Resuelve dependencias, descarga de repositorios verificados. apt update → apt install → apt upgrade.
  • Repositorios en /etc/apt/sources.list. PPAs para software de terceros — usar con cuidado.
  • Snap — formato universal de Canonical. Auto-actualiza, sandboxed, más lento al arrancar. Controversia en la comunidad.
  • Flatpak — alternativa comunitaria. Tienda: Flathub. Preferida por la comunidad. Mejor integración de temas.
  • AppImage — un archivo, sin instalación, sin root. chmod +x app.AppImage && ./app.AppImage.
  • Compilar desde fuente — máximo control, versión exacta. Flujo: instalar build-essential → ./configure o cmake → make -j$(nproc) → checkinstall.
  • Usar checkinstall en lugar de make install para poder desinstalar limpiamente después.
