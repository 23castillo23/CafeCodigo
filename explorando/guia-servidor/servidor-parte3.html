¿Qué es Samba y por qué lo necesitas?
El puente entre el sistema de archivos de Linux y el resto de tus computadoras

Linux y Windows guardan y organizan archivos de forma distinta por dentro, y no "hablan" el mismo idioma de red para compartir carpetas de manera nativa. Samba es el programa que resuelve exactamente ese problema: hace que una carpeta de Linux se pueda ofrecer en la red usando SMB, el protocolo que Windows entiende de forma nativa desde hace décadas — y que Linux y Mac también saben leer perfectamente.

🌉 Piénsalo como un mesero, no como una puerta abierta

Tu PC principal nunca entra directamente al sistema de archivos del servidor. En vez de eso, le pide a Samba: "quiero ver lo que hay en el recurso llamado Archivos". Samba recibe esa petición, revisa si el usuario y la contraseña son correctos, revisa los permisos, y solo entonces entrega (o niega) lo que se pidió. Nunca hay una conexión directa sin pasar por ese "mesero".

Gracias a esto, vas a poder ver la carpeta del servidor como si fuera una carpeta más de tu propia computadora — sin importar si estás en Windows 11, Zorin, Mint o Voyager — arrastrar archivos hacia ella, crear carpetas nuevas, y abrir documentos y videos directamente, sin copiarlos primero a tu disco local.

📦
Instalar Samba
Conectado por SSH desde tu PC principal, como en toda la Parte 2
servidor
$ sudo apt install samba
$ systemctl status smbd
● smbd.service - Samba SMB Daemon
Active: active (running) ...
// "smbd" es el nombre del proceso de Samba que atiende las peticiones — presiona "q" para salir
📁
Crear la carpeta que vas a compartir
Un lugar dedicado, no todo el sistema

No vamos a compartir todo el disco ni la carpeta personal del usuario. Vamos a crear una ubicación específica para este propósito: /srv/archivos. /srv es, por convención en Linux, el lugar donde viven los datos que un servidor ofrece a otras máquinas.

servidor
$ sudo mkdir -p /srv/archivos/Documentos /srv/archivos/Videos /srv/archivos/Musica /srv/archivos/Fotos
$ ls -l /srv/archivos
Documentos Fotos Musica Videos

Un par de detalles sobre estos comandos, para que ningún carácter se quede como misterio: la -p de mkdir -p significa "crea también cualquier carpeta intermedia que haga falta" — en este caso te deja crear /srv/archivos y las cuatro subcarpetas de un solo golpe, aunque /srv/archivos todavía no existiera. Sin -p, mkdir se hubiera quejado de que /srv/archivos no existe. La -l de ls -l es de "formato largo": en vez de solo listar los nombres, muestra una línea por elemento con más información (dueño, permisos, tamaño) — la vas a usar todo el tiempo de aquí en adelante.

🔐
Propietario y permisos, antes de seguir
La causa número uno de "Samba dice que sí, pero no me deja escribir"

En Linux, cada archivo y carpeta tiene un propietario, y ese propietario decide quién puede leer, escribir o ejecutar sobre ellos. Revisa quién es el dueño actual de la carpeta que acabas de crear:

servidor
$ ls -ld /srv/archivos
drwxr-xr-x 2 root root ... /srv/archivos

Ya conoces la -l de la sección anterior (formato largo, con dueño y permisos). La -d es nueva: le dice a ls que te muestre información de la carpeta en sí, no de lo que hay adentro. Sin -d, ls -l /srv/archivos te listaría el contenido de la carpeta (que todavía está vacía); con -d, ves los datos de /srv/archivos como objeto — que es justo lo que queremos aquí, saber quién es su dueño.

Ves root root: el dueño de esa carpeta es el superusuario, no tu propio usuario. Queremos que tu usuario pueda trabajar cómodamente sobre ella, así que le cambiamos el dueño:

servidor
$ sudo chown -R victor:victor /srv/archivos
// cambia "victor" por tu propio usuario, el que te devolvió "whoami" en la Parte 2
$ ls -ld /srv/archivos
drwxr-xr-x 2 victor victor ... /srv/archivos

chown (de "change owner") es el comando que cambia el dueño de un archivo o carpeta; victor:victor significa "usuario:grupo", así que aquí le estás dando la carpeta al usuario victor y también al grupo victor (todo usuario nuevo en Debian recibe automáticamente un grupo con su mismo nombre). La -R es de "recursivo": aplica el cambio no solo a /srv/archivos, sino a absolutamente todo lo que haya adentro — carpetas y subcarpetas incluidas. Sin -R, solo la carpeta archivos cambiaría de dueño, y las subcarpetas Documentos, Videos, etc. seguirían siendo de root.

⚠️ Esto es exactamente lo que causa la mayoría de los "no puedo guardar archivos" más adelante

Samba tiene su propia configuración de permisos (read only = no, que vamos a ver en un momento), pero eso solo controla si Samba intenta escribir. Si los permisos de Linux de la carpeta no lo permiten, la escritura va a fallar de todas formas, sin importar qué diga smb.conf. Vale la pena recordar este paso si algún día algo no cuadra.

🔑
Crear tu usuario y contraseña de Samba
Tu usuario de Linux y tu usuario de Samba están relacionados, pero no son la misma contraseña

Samba mantiene su propia base de datos de autenticación, separada de la de Linux. Necesitas registrar ahí a tu usuario y darle una contraseña específica para Samba — puede ser la misma que usas para SSH o una distinta, tú decides:

servidor
$ sudo smbpasswd -a victor
New SMB password:
Retype new SMB password:
Added user victor.

La -a es de "add" (agregar): le dice a smbpasswd que este es un usuario nuevo que quieres dar de alta en la base de datos de Samba, no uno que ya existe. Reemplaza victor por tu propio usuario de Linux — Samba necesita que ya exista como usuario del sistema antes de poder registrarlo, así que tiene que ser exactamente el mismo nombre que usas para SSH.

Esta va a ser la contraseña que uses cuando cualquiera de tus otras computadoras se conecte al recurso compartido — no confundirla con la contraseña de tu usuario de Linux, aunque el nombre de usuario sea el mismo.

📝
Configurar Samba: el archivo smb.conf
Aquí es donde le dices a Samba qué carpeta compartir y con qué reglas

Todo Samba se configura desde un único archivo de texto: /etc/samba/smb.conf. Antes de tocarlo, hazle una copia de seguridad — así, si algo sale mal, siempre puedes volver al punto de partida:

servidor
$ sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.backup

Revisa el bloque [global] antes de agregar nada

Abre el archivo con el editor de terminal nano:

servidor
$ sudo nano /etc/samba/smb.conf

Cerca del inicio del archivo vas a encontrar una sección [global] que ya trae valores por defecto. Busca la línea workgroup — normalmente dice WORKGROUP. Ese es el nombre del "grupo de trabajo" de red que usa Windows por convención. Si nunca cambiaste ese valor en tu PC con Windows 11, déjalo tal cual — coinciden por defecto.

📍 ¿Para qué sirve el workgroup?

Es una forma antigua, previa a las redes modernas, de agrupar equipos dentro de una misma red local para que se puedan "descubrir" entre sí más fácilmente al explorar la red. Hoy en día no es estrictamente necesario que coincida para que la conexión funcione (sobre todo si te conectas directamente por IP, como vamos a hacer en la Parte 4), pero es buena práctica dejarlo consistente.

Agrega el recurso compartido

Ve hasta el final del archivo (con las flechas del teclado, o Ctrl+_ seguido del número de línea si nano te lo permite) y agrega este bloque:

[Archivos] path = /srv/archivos browseable = yes read only = no valid users = victor

Cambia victor por tu propio usuario. Cada línea significa algo específico:

LíneaQué significa
[Archivos]El nombre del recurso — así es como va a aparecer cuando lo veas desde tus otras computadoras.
pathLa ruta real, dentro del servidor, donde están físicamente los archivos.
browseable = yesPermite que el recurso aparezca al explorar la red, en vez de tener que conocer su nombre exacto de antemano.
read only = noPermite escribir: crear, copiar, modificar y borrar archivos, no solo verlos.
valid usersQué usuario de Samba puede acceder a este recurso — puedes separar varios nombres con comas si más adelante quieres agregar más usuarios.

Guarda el archivo con Ctrl+O, confirma con Enter, y sal del editor con Ctrl+X.

🔄
Aplicar los cambios y comprobar que todo esté bien
Nunca reinicies Samba sin antes validar la configuración
servidor
$ testparm
// revisa la sintaxis de smb.conf sin aplicar nada todavía
...
Loaded services file OK.

La línea que de verdad importa al final es Loaded services file OK. — esa es la confirmación de que no hay errores de sintaxis. Antes de esa línea vas a ver un resumen largo de toda tu configuración (secciones [global], [Publico], etc.); no hace falta revisarlo línea por línea, solo confirma que termine con ese "OK".

⚠️ Si testparm muestra un error, no sigas

Detente ahí y revisa el bloque que acabas de agregar — normalmente el error es un espacio de más, una llave o corchete que no cierra, o una línea mal escrita. Si todo se ve bien y no encuentras el problema, siempre puedes restaurar la copia de seguridad con sudo cp /etc/samba/smb.conf.backup /etc/samba/smb.conf y volver a intentar.

Si testparm no reporta errores graves, reinicia el servicio y confirma que sigue activo:

servidor
$ sudo systemctl restart smbd
$ systemctl status smbd
Active: active (running)

Y, ya que instalamos ufw en la Parte 2, agrega ahora la regla para que el firewall permita el tráfico de Samba (todavía sin activar el firewall — eso queda para la Parte 5):

servidor
$ sudo ufw allow samba
Rules updated

🟢 Comprueba que Samba esté escuchando en la red

Como confirmación extra, puedes correr sudo ss -tulpn | grep -E '445|139'. Si ves esos números de puerto en la lista, Samba está correctamente a la espera de conexiones — 445 es el puerto que usa el SMB moderno.

Glosario
Términos nuevos de esta parte
Samba
El programa que permite a Linux compartir carpetas usando el protocolo SMB.
SMB
El protocolo de red que usan Windows, Mac y Linux para compartir carpetas y archivos.
smbd
El proceso (demonio) de Samba que atiende las peticiones que llegan por la red.
Recurso compartido
Una carpeta que Samba ofrece con un nombre propio a través de la red — en esta guía, "Archivos".
Propietario
El usuario de Linux al que pertenece un archivo o carpeta, y que controla quién puede acceder a él.
Workgroup
Un nombre de agrupación de red heredado de Windows, usado para descubrir equipos en la misma red local.
