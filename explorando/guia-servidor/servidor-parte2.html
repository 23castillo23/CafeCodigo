📡
Las dos PCs tienen que estar en la misma red local
Sin esto, nada de lo que sigue va a funcionar

Para que tu PC principal pueda "ver" al servidor, ambas computadoras necesitan estar conectadas al mismo router — ya sea por cable Ethernet o por Wi-Fi, pero dentro de la misma red doméstica.

tu red doméstica
Router
/ \
PC principal PC servidor (A6-5350)
Windows/Zorin/Mint/Voyager Debian, sin pantalla

🔌 Por qué te recomiendo cable en el servidor

Puedes usar Wi-Fi si no tienes otra opción, pero conectar la PC servidor por cable Ethernet te da una conexión más estable y predecible: sin caídas por interferencia, sin fluctuaciones de velocidad. Es especialmente importante si planeas reproducir videos grandes directamente desde el servidor — lo vas a agradecer en la Parte 4.

🔎
Encontrar la dirección IP del servidor
El "número de casa" de tu servidor dentro de la red

Todavía frente al monitor conectado al servidor (con el usuario que creaste en la Parte 1 ya iniciado), escribe:

servidor
$ whoami
victor
$ hostname
servidor
$ hostname -I
192.168.1.50

whoami confirma tu usuario, hostname confirma el nombre que le diste a la máquina, y hostname -I muestra su dirección IP dentro de la red local. Anota esa IP — es diferente en tu red, así que usa exactamente lo que te muestre tu propia PC, no el ejemplo de esta guía.

🟢 Confirma la conexión desde tu PC principal

Antes de seguir, abre una terminal en tu PC principal (cualquiera de tus sistemas) y ejecuta ping seguido de esa IP, por ejemplo ping 192.168.1.50. Si recibes respuesta, las dos computadoras se están comunicando correctamente por la red.

📌
Evitar que esa IP cambie sola
Un detalle que la mayoría de las guías se saltan, y que causa dolores de cabeza después

La IP que acabas de anotar normalmente se la asigna el router de forma automática mediante un sistema llamado DHCP, y por defecto puede cambiar con el tiempo — por ejemplo, después de reiniciar el router. Si eso pasa, un día vas a intentar conectarte a 192.168.1.50 y el servidor ya no va a estar ahí, aunque siga encendido y funcionando perfectamente.

⚠️ Por qué esto importa más de lo que parece

En la Parte 4 vas a guardar esta dirección IP en el explorador de archivos de tus sistemas para acceder rápido al servidor. Si la IP cambia, esos accesos guardados dejan de funcionar y vas a pensar que algo se rompió, cuando en realidad el servidor sigue perfectamente sano — solo cambió de dirección.

Hay dos formas de resolverlo. Elige la que te resulte más cómoda:

Opción A — Reservar la IP en el router (la más simple)

Entra a la configuración de tu router (normalmente escribiendo su propia IP, como 192.168.1.1, en un navegador) y busca una sección llamada algo como "DHCP" o "Reserva de direcciones". Ahí puedes indicarle: "a este dispositivo (identificado por su dirección MAC) siempre dale esta misma IP". Los pasos exactos varían según la marca del router, pero el concepto es siempre este.

Opción B — IP estática directamente en Debian

Si prefieres resolverlo desde el propio servidor, puedes configurar una IP fija con nmcli (el administrador de red de Debian):

servidor
$ nmcli connection show
// anota el nombre exacto de la conexión, ej. "Wired connection 1"
$ sudo nmcli connection modify "Wired connection 1" ipv4.addresses 192.168.1.50/24 ipv4.gateway 192.168.1.1 ipv4.dns "192.168.1.1" ipv4.method manual
$ sudo nmcli connection up "Wired connection 1"

Reemplaza 192.168.1.50 por la IP que ya estaba usando tu servidor (así no rompes nada más en tu red), y 192.168.1.1 por la IP de tu router, que normalmente coincide con la puerta de enlace que verías en la configuración de red de cualquiera de tus otras PCs.

🟢 Si no estás seguro, usa la Opción A

Reservar la IP desde el router es menos propenso a errores para alguien que empieza, y no requiere tocar la configuración de red del servidor directamente.

🔄
Actualizar el sistema
Antes de instalar nada más, dejamos Debian al día
servidor
$ sudo apt update
// descarga la lista de versiones disponibles, no instala nada todavía
$ sudo apt upgrade
// instala las actualizaciones disponibles — confirma con "Y" si te lo pide

apt update y apt upgrade son dos pasos distintos: el primero solo revisa qué hay disponible, el segundo instala esas actualizaciones. Vas a usar esta misma pareja de comandos regularmente para mantener el servidor al día.

🔐
Conectarte por SSH desde tu PC principal
El momento en que dejas de necesitar el monitor y el teclado del servidor

SSH (Secure Shell) es un protocolo que te permite abrir una terminal de una computadora remota, como si estuvieras sentado frente a ella, con toda la comunicación cifrada. Como en la Parte 1 dejaste marcada la opción "servidor SSH" durante la instalación, ya debería estar funcionando. Confírmalo desde el propio servidor:

servidor
$ systemctl status ssh
● ssh.service - OpenBSD Secure Shell server
Active: active (running) ...
// presiona "q" para salir de esta pantalla

⚠️ Si en vez de eso te dice "Unit ssh.service could not be found"

Eso significa que el servidor SSH no llegó a instalarse — lo más común es que la casilla [✔] servidor SSH de la Parte 1 se haya quedado sin marcar por accidente durante la instalación de Debian. No es un error grave ni tienes que reinstalar nada: se instala manualmente en dos comandos.

servidor
$ sudo apt install openssh-server
$ sudo systemctl enable --now ssh
$ systemctl status ssh
● ssh.service - OpenBSD Secure Shell server
Active: active (running) ...

apt install openssh-server descarga e instala el programa. systemctl enable --now ssh hace dos cosas en un solo comando: lo enciende ahora mismo (--now) y lo deja programado para arrancar solo cada vez que prendas el servidor (enable) — sin esto último, tendrías que volver a encenderlo a mano después de cada reinicio. Vuelve a correr systemctl status ssh para confirmar que ahora sí dice active (running), y continúa con el resto de esta sección con toda confianza.

Ahora, desde tu PC principal, abre una terminal:

SistemaCómo abrir la terminal con SSH
Windows 11Abre "Terminal" o "PowerShell" desde el menú Inicio. El comando ssh ya viene incluido en Windows 11 sin instalar nada extra.
Zorin OS, Linux Mint, VoyagerAbre la aplicación de Terminal de tu escritorio. ssh viene preinstalado en cualquier distribución basada en Debian/Ubuntu.

Y en cualquiera de ellos, escribe:

🟢 ¿De dónde saco mi usuario y mi IP exactos?

Son los mismos dos datos que ya obtuviste más arriba, en Encontrar la IP, corriendo whoami y hostname -I directamente en el servidor. Por ejemplo, si tu usuario es vikthor23 y tu IP es 192.168.1.72, el comando completo sería ssh vikthor23@192.168.1.72 — no copies victor@192.168.1.50 tal cual, es solo un ejemplo para que veas el formato.

tu PC principal
$ ssh victor@192.168.1.50
The authenticity of host '192.168.1.50' can't be established.
Are you sure you want to continue connecting (yes/no)?
$ yes
victor@192.168.1.50's password:
victor@servidor:~$

Reemplaza victor por tu propio usuario (el que te devolvió whoami) y la IP por la que te devolvió hostname -I. La primera vez, SSH te pregunta si confías en la identidad de ese equipo — responde yes. Después escribe tu contraseña (tampoco vas a ver asteriscos). En cuanto veas el símbolo de sistema del servidor, estás controlando la PC A6-5350 completamente desde tu PC principal.

🔐 Ahora sí puedes desconectar el monitor del servidor

A partir de este punto, cualquier comando que escribas dentro de esta sesión de SSH se ejecuta en el servidor, no en tu PC principal — aunque estés viendo la ventana en tu propia pantalla. Es exactamente lo que buscábamos con la instalación headless de la Parte 1.

🟢 SSH no es lo mismo que Samba — para no confundirlos desde ya

SSH te da control total del servidor por terminal: instalar programas, editar configuración, apagar, todo lo que harías sentado frente a él. Samba, que vas a instalar en la Parte 3, es algo distinto: es lo que hace que una carpeta del servidor se vea como una carpeta más en tu explorador de archivos, sin necesidad de terminal. Vas a usar los dos, pero para cosas diferentes — en la Parte 4 hay una tabla comparando SSH, Samba y una tercera herramienta (SFTP) lado a lado.

🧱
Un primer vistazo al firewall
Instalarlo ahora, antes de que haya más servicios que proteger, para no olvidarlo después

Un firewall (cortafuegos) decide qué tipo de tráfico de red puede entrar o salir de tu servidor. Debian no trae uno activado por defecto. Vamos a instalar ufw ("Uncomplicated Firewall"), que es una versión simplificada pensada para principiantes, y a dejarlo listo para SSH desde ahora:

servidor
$ sudo apt install ufw
$ sudo ufw allow ssh
Rule added

⚠️ Por qué permitimos SSH antes de activar el firewall

No vamos a activar ufw todavía — eso lo haremos hasta la Parte 5, después de agregar también la regla para Samba. Si activas el firewall sin haber permitido SSH primero, te quedarías fuera de tu propio servidor: como estás conectado por SSH, esa misma conexión se cortaría y no podrías volver a entrar de forma remota. Por eso, cada vez que instalemos un servicio nuevo en las siguientes partes, vamos a ir agregando su regla de firewall correspondiente antes de activarlo.

Glosario
Términos nuevos de esta parte

El sistema con el que un router asigna direcciones IP automáticamente, y que puede cambiarlas con el tiempo.

Una dirección IP que se le asigna permanentemente a un dispositivo, para que nunca cambie.

Programa que filtra qué tráfico de red puede entrar o salir de un equipo.

La dirección IP del router dentro de tu propia red, por donde sale todo el tráfico hacia internet.
