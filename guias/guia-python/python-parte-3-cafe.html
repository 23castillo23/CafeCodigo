Comparaciones
Preguntas cuya respuesta es Sí (True) o No (False)

Para decidir, un programa primero necesita hacer una pregunta. En Python esas preguntas son comparaciones y siempre responden True (sí) o False (no):

OperadorPreguntaEjemploResultado
==¿Es igual?5 == 5True
!=¿Es distinto?5 != 3True
>¿Es mayor?3 > 5False
<¿Es menor?3 < 5True
>=¿Es mayor o igual?5 >= 5True
<=¿Es menor o igual?6 <= 5False

☕ Analogía

Una comparación es una pregunta de sí o no que le haces a Python: "¿5 es mayor que 3?". Y Python solo contesta True o False, nunca "tal vez".

La confusión número 1: = (un igual) guarda un valor: edad = 18. == (dos iguales) pregunta si son iguales: edad == 18. Y con textos, las mayúsculas cuentan: "hola" no es igual a "Hola".

Ejecutar código solo si algo es verdadero

if significa "si". El código que va debajo solo se ejecuta si la condición es True. Ejecuta este y luego cambia edad = 20 por edad = 15:

☕ Analogía

Es una regla de la vida diaria: "si llueve, llevo paraguas". Si la condición se cumple, haces lo de adentro; si no, te lo saltas y sigues con tu día.

Las 3 piezas de un if

if edad >= 18La palabra if y la condición (una comparación que da True o False).
:Los dos puntos al final de la línea. Sin ellos, error. Significan "lo que sigue es el bloque".
print(...)El bloque: líneas con sangría (4 espacios). Solo ellas dependen del if.
La sangría es obligatoria en Python. Es lo que le dice a Python qué líneas están "dentro" del if. Mira que print("Fin del programa") no tiene sangría, así que se ejecuta siempre. En VS Code, la tecla Tab pone la sangría.

☕ Analogía

La sangría es como entrar a una habitación: las líneas con sangría están "dentro del cuarto" del if. Si la puerta del if está cerrada (condición False), nada de lo que hay en el cuarto se ejecuta.

elif: varias opciones
Cuando hay más de dos caminos

elif es "si no, y si...". Sirve para encadenar más condiciones. Python las revisa de arriba hacia abajo y ejecuta solo la primera que sea True:

☕ Analogía

Es como una ventanilla con filtros: "¿Tienes 90 o más? Pasa por aquí. ¿No? ¿70 o más? Por esta otra ventanilla...". En cuanto una te acepta, te atienden ahí y ya no sigues revisando las demás.

El orden importa

Mira este código con las condiciones en mal orden. La nota es 95, ¡pero no sale "Excelente"!

Como 95 ya cumple nota >= 70, Python se detuvo ahí y jamás llegó al elif. Regla: pon primero las condiciones más específicas (la más exigente) y al final las generales. Intercambia el orden y compruébalo.

and, or y not
Combinar condiciones
OperadorSignificaEs True cuando...

orOal menos una es True
notNOla condición es False (invierte el resultado)

☕ Analogía

and: para entrar al cine necesitas boleto Y ser mayor de la edad de la película; si falta una, no pasas. or: puedes pagar con efectivo O tarjeta; con cualquiera de las dos es suficiente. not es un interruptor inverso: lo que era sí pasa a no y viceversa.

if dentro de if
Decisiones anidadas

Un if puede contener otro if. Cada nivel adentro lleva una sangría más:

☕ Analogía

Son muñecas rusas: primero pasas la puerta de la sala (edad), y adentro hay otra puerta (boleto). Cada puerta es un if y cada cuarto más profundo lleva más sangría.

Consejo: si puedes escribir lo mismo con and (if edad >= 18 and tiene_boleto:), el código queda más corto y fácil de leer. Usa anidados cuando cada caso tenga su propio mensaje.
