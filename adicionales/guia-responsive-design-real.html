Introducción — más allá de "le puse una media query"
Responsive de verdad es una forma de pensar el diseño, no un parche al final

Mucha gente cree que "hacer responsive" significa agregar un par de @media al final para que no se rompa en celular. El responsive design real empieza desde el primer día: pensando en unidades flexibles, contenido que se adapta y un orden de prioridades claro entre pantallas.

💡 La idea central

Un sitio verdaderamente responsivo no tiene "una versión para celular y otra para desktop" — tiene un solo diseño fluido que se reorganiza según el espacio disponible, apoyándose en unidades relativas, layouts flexibles (Flexbox/Grid) y media queries solo donde realmente son necesarias.

📱
Mobile-first, no desktop-first
Diseñar de lo simple a lo complejo, no al revés

Mobile-first significa escribir tu CSS base pensando primero en la pantalla más pequeña, y usar media queries con min-width para ir agregando complejidad conforme hay más espacio — en lugar de diseñar para desktop y luego usar max-width para ir quitando cosas.

🧳 Analogía: empacar una maleta de mano contra una de bodega

Diseñar mobile-first es como empacar primero solo lo esencial en una maleta de mano — te obliga a decidir qué es realmente indispensable. Diseñar desktop-first es empacar la maleta grande primero, y luego tratar de decidir, ya tarde, qué sacar para que quepa en la de mano. La primera forma casi siempre produce mejores decisiones de prioridad.

/* Mobile-first: CSS base = versión pequeña */ .tarjetas { display: grid; grid-template-columns: 1fr; /* una columna por defecto */ } /* Se agrega complejidad conforme crece la pantalla */ @media (min-width: 768px) { .tarjetas { grid-template-columns: 1fr 1fr; } } @media (min-width: 1024px) { .tarjetas { grid-template-columns: 1fr 1fr 1fr; } }

🟢 Por qué min-width y no max-width

Usar siempre min-width (y nunca max-width) evita que las reglas de distintos breakpoints se peleen entre sí o se sobrescriban de forma confusa. El CSS "crece" de forma predecible, una capa a la vez.

⚠️ No diseñes para "el iPhone 15" — diseña para tu contenido

Los tamaños de pantalla cambian constantemente (nuevos celulares, nuevos monitores). En vez de fijar breakpoints según un dispositivo específico, cambia el layout en el punto donde tu propio diseño empieza a verse mal — reduce el navegador poco a poco y define el breakpoint justo ahí.

@media (min-width: 768px) and (max-width: 1023px) { /* Solo para tablets */ } @media (orientation: landscape) { /* Cuando el dispositivo está en horizontal */ } @media (prefers-color-scheme: dark) { /* Cuando el sistema del usuario usa tema oscuro */ }

⚠️ El problema de usar solo px para fuentes

Si un usuario configura su navegador para usar un tamaño de fuente base más grande (por accesibilidad, por ejemplo), el texto en px no responde a esa preferencia — se queda fijo. El texto en rem sí escala junto con esa configuración, respetando las necesidades del usuario.

🎚️
clamp(): responsive sin escribir una sola media query
Un mínimo, un valor preferido, y un máximo — todo en una línea

Achica y agranda la ventana de tu navegador para ver este texto escalar suavemente, sin ningún salto brusco:

Este texto usa clamp()

font-size: clamp(0.85rem, 2vw + 0.5rem, 1.6rem)

h1 { font-size: clamp(1.5rem, 4vw, 3rem); } /* mínimo: 1.5rem — nunca más pequeño, aunque la pantalla sea diminuta */ /* preferido: 4vw — crece de forma fluida con el ancho de pantalla */ /* máximo: 3rem — nunca más grande, aunque la pantalla sea gigante */

🟢 Por qué clamp() está reemplazando tantas media queries

clamp(mínimo, preferido, máximo) permite que un tamaño de fuente, un padding o un ancho escalen de forma continua entre dos límites, sin los "saltos" abruptos típicos de las media queries tradicionales — el navegador interpola el valor en cada tamaño de pantalla intermedio.

🖼️
Imágenes responsivas
No basta con poner max-width: 100%
<img src="foto-800.jpg" srcset="foto-400.jpg 400w, foto-800.jpg 800w, foto-1200.jpg 1200w" sizes="(max-width: 600px) 100vw, 50vw" alt="Descripción de la foto" >

El atributo srcset le da al navegador varias versiones de la misma imagen en distintos tamaños, y sizes le indica qué tan ancha se mostrará esa imagen en distintos escenarios. El navegador elige automáticamente la versión más adecuada según el tamaño de pantalla y la densidad de píxeles del dispositivo — descargando menos datos en pantallas pequeñas.

TécnicaQué resuelve
max-width: 100%Evita que una imagen se desborde de su contenedor — lo básico, pero no suficiente por sí solo.
srcset / sizesSirve la imagen del tamaño adecuado según pantalla, ahorrando datos.
object-fit: coverRecorta una imagen para llenar su contenedor sin deformarse, sin importar su proporción original.

Ejercicios
Para practicar lo que acabas de leer

Ejercicio 1 — Convierte a mobile-first

Toma un layout que tengas hecho con max-width y reescríbelo usando solo min-width, empezando por el estilo base para pantallas pequeñas.

Ejercicio 2 — Un título con clamp()

Reemplaza un font-size fijo en un <h1> por clamp(1.5rem, 5vw, 3.5rem), y observa cómo escala al redimensionar la ventana.

Ejercicio 3 — srcset real

Toma una imagen de tu proyecto, genera dos versiones más pequeñas, y arma un srcset con las tres versiones más el atributo sizes correspondiente.

💡 Para llevarte de esta guía

Responsive real es diseñar mobile-first, apoyarte en unidades relativas (rem, %, vw) y clamp() para reducir la cantidad de media queries que necesitas, y servir imágenes del tamaño correcto con srcset. Las media queries siguen siendo útiles, pero deberían ser el último recurso, no el primero.
