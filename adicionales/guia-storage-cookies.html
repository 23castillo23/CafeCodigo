LocalStorage vs SessionStorage vs Cookies

Cuándo usar cada uno para guardar datos

Introducción — tres formas de que el navegador "recuerde" algo
Mismo objetivo general, comportamientos muy distintos

Cuando una página necesita recordar información entre visitas —el idioma preferido, si el usuario inició sesión, los artículos de un carrito de compras— tiene tres herramientas principales para guardar esos datos en el navegador: localStorage, sessionStorage y cookies. Las tres cumplen un propósito parecido, pero con reglas muy distintas de duración, tamaño y quién puede leerlas.

💡 La diferencia que más importa

La pregunta clave para elegir entre las tres casi siempre es: ¿cuánto tiempo necesito que sobrevivan estos datos, y necesita el servidor enterarse de ellos automáticamente en cada petición?

💾
localStorage
Persiste para siempre, hasta que alguien lo borre

localStorage guarda datos sin fecha de expiración: siguen ahí después de cerrar la pestaña, cerrar el navegador por completo, o incluso reiniciar la computadora. Solo desaparecen si el usuario los borra manualmente (o tu código lo hace).

// Guardar localStorage.setItem('tema', 'oscuro'); // Leer const tema = localStorage.getItem('tema'); // 'oscuro' // Borrar una clave específica localStorage.removeItem('tema'); // Borrar todo localStorage.clear();

⚠️ Solo guarda texto (strings)

localStorage únicamente almacena cadenas de texto. Para guardar un objeto o arreglo, hay que convertirlo con JSON.stringify() al guardar, y con JSON.parse() al leerlo de vuelta.

const carrito = [{ producto: 'Café', cantidad: 2 }]; localStorage.setItem('carrito', JSON.stringify(carrito)); const carritoGuardado = JSON.parse(localStorage.getItem('carrito'));
🗂️
sessionStorage
La misma API, pero con memoria de corto plazo

sessionStorage comparte exactamente la misma API que localStorage (setItem, getItem, removeItem, clear), pero con una diferencia clave de comportamiento: los datos se borran automáticamente al cerrar la pestaña o el navegador.

📝 Analogía: el post-it contra el archivero

sessionStorage es como un post-it pegado en tu escritorio: útil mientras trabajas en algo, pero se tira al final del día. localStorage es como un archivero: lo que guardas ahí sigue existiendo mañana, la próxima semana, y el próximo mes, hasta que tú decidas sacarlo.

🟢 Cada pestaña tiene su propio sessionStorage

Si abres el mismo sitio en dos pestañas distintas, cada una tiene su propio sessionStorage independiente, aunque sea exactamente la misma URL. Esto lo hace ideal para datos temporales de un solo flujo, como el progreso de un formulario de varios pasos.

🍪
Cookies
La opción más antigua — y la única que viaja al servidor sola

Las cookies son la forma más antigua de almacenamiento en el navegador, con una característica que las diferencia por completo de las otras dos: se envían automáticamente al servidor en cada petición HTTP hacia ese dominio, sin que tengas que hacer nada extra en tu código.

// Crear una cookie con JavaScript (existe, pero rara vez se usa así) document.cookie = "idioma=es; max-age=2592000; path=/"; // Leer todas las cookies (viene como un solo string, hay que parsearlo) console.log(document.cookie);

⚠️ En la práctica, casi nadie maneja cookies "a mano" con JS

La API nativa de document.cookie es incómoda de usar (todo llega como un solo string que hay que separar manualmente). En proyectos reales, las cookies importantes —como las de sesión de login— casi siempre las crea y gestiona el servidor, con la cabecera HTTP Set-Cookie, no JavaScript en el navegador.

Atributo de cookieQué controla
max-age / expiresCuánto tiempo vive la cookie antes de borrarse sola.
HttpOnlyImpide que JavaScript la lea, protegiendo cookies de sesión sensibles contra ataques.
SecureSolo se envía por HTTPS, nunca por conexiones sin cifrar.

Cuál usar en cada caso
Ejemplos concretos para no dudar la próxima vez
🎨
Preferencia de tema (claro/oscuro)
localStorage — no cambia entre pestañas y debe recordarse indefinidamente, sin que el servidor necesite saberlo.
📋
Progreso de un formulario largo
sessionStorage — solo importa mientras dura esa visita; no tiene sentido que sobreviva a que cierres el navegador.
🔐
Sesión de login
Cookie (idealmente HttpOnly) — el servidor necesita recibirla automáticamente en cada petición para saber quién eres.
🛒
Carrito de compras persistente
localStorage — el usuario espera encontrarlo igual aunque cierre y regrese días después.
🏋️
Ejercicios
Para practicar lo que acabas de leer

Ejercicio 1 — Contador persistente

Crea un botón que aumente un contador guardado en localStorage. Recarga la página y verifica que el número siga ahí.

Ejercicio 2 — Compara la duración

Guarda un valor en sessionStorage y otro en localStorage. Cierra la pestaña (no todo el navegador) y vuelve a abrir el sitio. ¿Cuál de los dos sigue ahí?

Ejercicio 3 — Objeto completo

Guarda un objeto con varias propiedades (nombre, preferencias, etc.) en localStorage usando JSON.stringify(), y recupéralo con JSON.parse(), mostrando cada propiedad por separado en consola.

💡 Para llevarte de esta guía

Si el servidor necesita conocer el dato automáticamente en cada petición (como una sesión de login), usa cookies. Si es solo para esta visita, sessionStorage. Si debe sobrevivir indefinidamente y solo lo necesita el navegador, localStorage. Las tres resuelven "recordar algo" — la diferencia está en quién necesita leerlo y por cuánto tiempo.
