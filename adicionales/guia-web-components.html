Introducción — crear tus propias etiquetas HTML
Sin necesitar React, Vue ni ningún framework

Web Components es un conjunto de estándares nativos del navegador que permite crear elementos HTML completamente nuevos y reutilizables —con su propia lógica, estilos encapsulados y estructura interna— sin depender de ningún framework externo.

💡 La idea central

Web Components se apoya en tres tecnologías que trabajan juntas: Custom Elements (definir etiquetas nuevas), Shadow DOM (encapsular estilos y estructura) y <template> (definir contenido reutilizable). Juntas, permiten construir algo parecido a un "componente" de React, pero usando solo APIs nativas del navegador.

🏷️
Custom Elements
Definir tu propia etiqueta HTML con class y customElements.define()
class TarjetaSaludo extends HTMLElement { connectedCallback() { this.innerHTML = `<p>¡Hola desde un elemento personalizado! 👋</p>`; } } customElements.define('tarjeta-saludo', TarjetaSaludo);
<tarjeta-saludo></tarjeta-saludo> <!-- El navegador la reconoce como una etiqueta HTML real -->

⚠️ El nombre siempre necesita un guion

Las especificaciones exigen que el nombre de un elemento personalizado contenga al menos un guion (tarjeta-saludo, no tarjetasaludo). Esto evita cualquier conflicto futuro con nombres de etiquetas HTML estándar, que nunca usan guiones.

Método del ciclo de vidaCuándo se ejecuta
connectedCallbackCuando el elemento se inserta en el DOM.
disconnectedCallbackCuando el elemento se elimina del DOM.
attributeChangedCallbackCuando cambia un atributo observado del elemento.

Shadow DOM
Estilos que no se filtran hacia afuera ni hacia adentro

El Shadow DOM le da a un elemento su propio "sub-árbol" del DOM, aislado del resto de la página. El CSS que escribas dentro de él no afecta al resto del sitio, y el CSS del resto del sitio no afecta lo que hay dentro — una encapsulación real, sin necesitar convenciones de nombres como BEM para evitar choques de clases.

🏠 Analogía: la casa con reglas propias

El DOM normal es como un vecindario abierto, donde el ruido de una casa (el CSS) se escucha en todas las demás. El Shadow DOM es como construir una casa completamente insonorizada: lo que pasa adentro (tus estilos) se queda adentro, y lo que pasa afuera no se filtra hacia adentro tampoco.

class TarjetaAislada extends HTMLElement { constructor() { super(); const shadow = this.attachShadow({ mode: 'open' }); shadow.innerHTML = ` <style> p { color: hotpink; font-weight: bold; } </style> <p>Este estilo NO se filtra al resto de la página</p> `; } } customElements.define('tarjeta-aislada', TarjetaAislada);

🟢 mode: 'open' vs. 'closed'

{ mode: 'open' } permite acceder al Shadow DOM desde JavaScript externo (elemento.shadowRoot). Con { mode: 'closed' }, ese acceso queda bloqueado desde afuera — en la práctica, la gran mayoría de los componentes usan 'open'.

<template> y slots
Contenido reutilizable, con huecos que el usuario del componente puede llenar

La etiqueta <template> define un fragmento de HTML que el navegador no renderiza hasta que se clona explícitamente por JavaScript. Los <slot> dentro de un Shadow DOM son "huecos" donde se inserta el contenido que el usuario del componente puso entre las etiquetas del elemento.

<template id="tarjeta-tpl"> <style> .caja { border: 2px solid orange; border-radius: 8px; padding: 1rem; } </style> <div class="caja"> <slot></slot> <!-- aquí se inserta el contenido del usuario --> </div> </template>
// Uso desde el HTML: <tarjeta-con-slot> ¡Este texto llena el slot! </tarjeta-con-slot>

Ejemplo completo, funcionando
Un contador con estado propio, encapsulado

Este componente está corriendo de verdad en esta página — cada clic incrementa su propio contador interno:

class MiContador extends HTMLElement { constructor() { super(); this.count = 0; this.attachShadow({ mode: 'open' }); } connectedCallback() { this.render(); this.shadowRoot.querySelector('button') .addEventListener('click', () => { this.count++; this.render(); }); } render() { this.shadowRoot.innerHTML = ` <style> button { padding: .6rem 1.2rem; border-radius: 8px; border: none; background: #c49a1a; color: #1a1814; font-weight: 700; cursor: pointer; } </style> <button>Clics: ${this.count}</button> `; } } customElements.define('mi-contador', MiContador);

Cuándo tienen sentido (y cuándo no)
No reemplazan a React o Vue en todos los casos
Buen caso de usoCuándo mejor usar un framework
Un widget reutilizable entre proyectos distintos (que quizás no todos usan el mismo framework).Una aplicación grande con mucho estado compartido entre muchos componentes.
Una librería de componentes de diseño (design system) usada por varios equipos.Proyectos que ya usan un framework y se benefician de su ecosistema de herramientas.
Un solo widget embebido en un sitio que no es tuyo (como un chat de soporte).Interfaces con routing complejo, manejo de formularios avanzado, etc.

🟢 La ventaja que ningún framework puede igualar

Un Web Component, una vez definido, funciona exactamente igual en cualquier proyecto — sin importar si el resto del sitio usa React, Vue, Angular o HTML plano. Es la única forma de crear un componente verdaderamente "agnóstico de framework".

Ejercicios
Para practicar lo que acabas de leer

Ejercicio 1 — Tu primer custom element

Crea un elemento <fecha-hoy> que, al insertarse en la página, muestre la fecha actual formateada.

Ejercicio 2 — Agrégale Shadow DOM

Toma el componente anterior y dale su propio Shadow DOM con estilos internos (color, tipografía) que no afecten al resto de tu página.

Ejercicio 3 — Un slot con contenido del usuario

Crea un componente <caja-alerta> con un <slot> dentro, de forma que puedas escribir <caja-alerta>Texto de aviso</caja-alerta> y el texto aparezca dentro de una caja con estilo propio.

💡 Para llevarte de esta guía

Web Components te da tres herramientas nativas —Custom Elements, Shadow DOM y <template>— para crear tus propias etiquetas HTML reutilizables, con estilos verdaderamente encapsulados, sin depender de ningún framework. Son especialmente útiles para widgets que necesitan funcionar en cualquier proyecto, sin importar qué tecnología use el resto del sitio.
