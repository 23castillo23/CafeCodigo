Introducción — movimiento sin una sola línea de JavaScript
Dos herramientas, dos propósitos distintos

CSS tiene dos formas principales de animar elementos: transition, para cambios simples entre dos estados (como al pasar el mouse), y @keyframes con animation, para secuencias más complejas que se repiten o tienen varios pasos intermedios.

💡 La regla para elegir entre las dos

Si el cambio es "de A a B" y se dispara por algo (hover, clic, una clase que se agrega), usa transition. Si necesitas una secuencia con varios pasos, que se repita sola, o que arranque automáticamente al cargar la página, usa @keyframes.

🎞️ Analogía: el interruptor y la película

transition es como un interruptor de luz con atenuador (dimmer): pasa suavemente de apagado a encendido cuando lo activas, pero solo conoce esos dos estados. @keyframes es como una película completa: tú defines qué pasa en el minuto 0, en el minuto 2, en el minuto 5... y el navegador reproduce toda la secuencia, las veces que le digas.

🔀
transition: el cambio simple
De un estado a otro, de forma suave

Pasa el mouse sobre esta tarjeta:

hover aquí →
.chip { background: var(--primary); transition: transform .3s ease, background .3s ease; } .chip:hover { transform: scale(1.15) rotate(-3deg); background: var(--secondary); }

transition necesita tres piezas de información: qué propiedad animar, cuánto tiempo debe tardar, y cómo debe acelerar o desacelerar (la timing function, que vemos más abajo).

PropiedadQué controla
transition-propertyQué propiedad(es) CSS animar. all anima todas, pero es menos eficiente.
transition-durationCuánto tiempo dura el cambio (ej. .3s).
transition-timing-functionLa curva de aceleración del cambio.
transition-delayCuánto esperar antes de empezar la transición.

🟢 La forma abreviada que verás más seguido

transition: transform .3s ease; combina las cuatro propiedades en una sola línea: propiedad, duración, timing function y (opcionalmente) delay, en ese orden.

🎬
@keyframes: la secuencia completa
Definiendo "fotogramas clave" en porcentajes
pulso
rebote
@keyframes pulso { 0%, 100% { transform: scale(1); opacity: 1; } 50% { transform: scale(1.15); opacity: .7; } } .elemento { animation: pulso 1.6s ease-in-out infinite; }

Cada porcentaje dentro de @keyframes representa un punto en el tiempo de la animación completa: 0% es el inicio, 100% el final, y puedes agregar tantos puntos intermedios como necesites (25%, 50%, 75%...).

Propiedad de animationQué controla
animation-nameEl nombre del @keyframes a usar.
animation-durationCuánto dura un ciclo completo.
animation-iteration-countCuántas veces se repite (infinite para siempre).
animation-directionnormal, reverse, o alternate para ir y volver.
animation-fill-modeQué estilo mantiene el elemento antes/después de que corra la animación.

Timing functions: la diferencia entre "robótico" y "natural"
La curva de aceleración lo cambia casi todo

Observa cómo el mismo recorrido se siente completamente distinto según la curva usada:

linear — velocidad constante, se siente mecánico

ease — arranca rápido, termina lento (la más natural)

ease-in-out — lento al inicio y al final

cubic-bezier personalizada — efecto de rebote

🟢 Cuándo usar cada una

  • linear: para animaciones continuas y mecánicas, como un spinner de carga girando.
  • ease / ease-in-out: la opción por defecto para la mayoría de las interacciones de interfaz — se siente natural.
  • cubic-bezier() personalizada: para efectos con personalidad, como rebotes o resortes. Herramientas como cubic-bezier.com ayudan a diseñar la curva visualmente.
⚡
Rendimiento: qué animar y qué no
No todas las propiedades CSS son igual de "baratas" de animar

⚠️ Evita animar width, height, top, left, margin

Animar estas propiedades obliga al navegador a recalcular el layout completo de la página en cada fotograma (lo que se conoce como "reflow"), lo cual es costoso y puede generar animaciones con tirones (jank), sobre todo en dispositivos menos potentes.

En vez de...Usa...Por qué
left / toptransform: translate()No dispara reflow; se procesa en la GPU.
width / heighttransform: scale()Escala visualmente sin recalcular el layout de otros elementos.
display (para ocultar)opacity + visibilityPermite transición suave; display cambia de golpe, sin animación posible.

Las propiedades transform y opacity son las más "baratas" de animar porque el navegador puede procesarlas directamente en la GPU, sin recalcular la posición de ningún otro elemento en la página.

Ejercicios
Para practicar lo que acabas de leer

Ejercicio 1 — Botón con transición

Crea un botón que cambie de color de fondo y se agrande ligeramente (transform: scale(1.05)) al pasar el mouse, con una transición de .2s.

Ejercicio 2 — Spinner de carga

Crea un @keyframes llamado girar que rote un elemento de 0deg a 360deg, y aplícalo con animation: girar 1s linear infinite; a un círculo pequeño.

Ejercicio 3 — Compara timing functions

Toma la misma animación de movimiento y pruébala con linear, ease y una cubic-bezier personalizada (usa cubic-bezier.com para diseñarla). Anota cuál se siente más apropiada para tu caso de uso.

💡 Para llevarte de esta guía

Usa transition para cambios simples entre dos estados y @keyframes para secuencias completas. Prioriza animar transform y opacity por rendimiento, y elige la timing function pensando en qué "sensación" quieres transmitir — no solo en que algo se mueva.
