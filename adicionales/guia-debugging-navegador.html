Introducción — hay mucho más que console.log
Las DevTools son, probablemente, la herramienta más subutilizada del desarrollo web

Como se cuenta en la guía de historia sobre "Cómo era programar web antes de las DevTools", estas herramientas tardaron años en existir. Hoy vienen integradas gratis en cualquier navegador moderno — pero la mayoría de la gente solo usa una fracción mínima de lo que ofrecen.

💡 La idea central

Depurar con console.log funciona, pero es lento: agregas la línea, recargas, lees, borras la línea, repites. Las DevTools ofrecen herramientas para pausar la ejecución exactamente donde quieres, inspeccionar el estado completo del programa en ese instante, y hasta modificar valores en vivo sin tocar tu código fuente.

🟢 Cómo abrirlas

Presiona F12, o Ctrl + Shift + I (Windows/Linux), o Cmd + Option + I (Mac). También puedes hacer clic derecho sobre cualquier elemento de la página y elegir "Inspeccionar".

🖥️
Más allá de console.log
El objeto console tiene más de una docena de métodos útiles
console.table([ { nombre: 'Ana', edad: 28 }, { nombre: 'Luis', edad: 34 } ]); // Muestra los datos como una tabla real, no como texto plano console.group('Validación de formulario'); console.log('Email válido'); console.log('Contraseña muy corta'); console.groupEnd(); // Agrupa mensajes relacionados, colapsables en el panel console.time('procesar'); // ...código que quieres medir... console.timeEnd('procesar'); // procesar: 42.31ms console.trace(); // Muestra la pila de llamadas completa hasta este punto console.assert(usuario.edad >= 18, 'El usuario debería ser mayor de edad'); // Solo imprime el mensaje si la condición es FALSA
MétodoPara qué sirve
console.table()Muestra arreglos de objetos como una tabla ordenada.
console.warn() / console.error()Igual que log(), pero con color e ícono de advertencia/error para que resalten.
console.group() / groupEnd()Agrupa mensajes relacionados en un bloque colapsable.
console.time() / timeEnd()Mide cuánto tiempo tarda un bloque de código en ejecutarse.
console.assert()Solo imprime si la condición dada es falsa — útil para validar suposiciones sin llenar la consola de ruido.
⏸️
Breakpoints de verdad
Pausar la ejecución sin escribir ni una línea de código

Un breakpoint pausa la ejecución de JavaScript exactamente en la línea que elijas, permitiéndote inspeccionar el valor de cada variable en ese momento exacto — algo que console.log nunca puede mostrarte con la misma precisión.

Cómo ponerloDónde
Clic en el número de líneaPanel Sources — pausa siempre que se llegue a esa línea.
Palabra clave debugger;Directo en tu código — pausa ahí, pero solo si las DevTools están abiertas.
Clic derecho sobre un elemento → "Break on..."Panel Elements — pausa cuando ese elemento del DOM cambia.
Breakpoint condicional (clic derecho en el número de línea)Panel Sources — pausa solo si una condición que tú escribes es verdadera.
function calcularDescuento(precio, porcentaje) { debugger; // la ejecución se detiene aquí si las DevTools están abiertas return precio - (precio * porcentaje / 100); }

🟢 Una vez pausado, tienes control total

  • F10 — ejecuta la línea actual y pasa a la siguiente ("step over").
  • F11 — entra dentro de la función que se está llamando ("step into").
  • Shift + F11 — sale de la función actual ("step out").
  • F8 — reanuda la ejecución normal hasta el siguiente breakpoint.

⚠️ No olvides quitar los debugger;

A diferencia de console.log (que solo "ensucia" la consola), un debugger; olvidado literalmente pausa la ejecución para cualquier usuario que tenga las DevTools abiertas — vale la pena revisar tu código antes de publicarlo.

El panel Elements
Editar HTML y CSS en vivo, sin tocar tu archivo

El panel Elements muestra el DOM tal como está ahora mismo — incluyendo cambios hechos por JavaScript, no el HTML original del archivo. Puedes hacer doble clic sobre cualquier texto, atributo o valor de CSS y editarlo directamente para probar ideas sin tocar tu código fuente.

FunciónCómo usarla
Editar CSS en vivoEn el panel de estilos, haz clic sobre cualquier valor y cámbialo — verás el resultado al instante.
Forzar estado (:hover, :focus)Botón ":hov" en el panel de estilos — útil para depurar estilos que solo aparecen en esos estados.
$0 en la consolaReferencia al último elemento seleccionado en Elements — puedes manipularlo directo desde Console.
Panel ComputedMuestra el valor final de cada propiedad CSS después de aplicar toda la cascada — útil para saber "por qué" un estilo ganó.
🌐
El panel Network
Todo lo que tu página pide o descarga, en un solo lugar

El panel Network registra cada petición que hace tu página: archivos, imágenes, peticiones fetch(). Es la primera parada cuando algo relacionado con una API "no está funcionando", como se explica en la guía de "Fetch API y promesas".

Columna / funciónQué te dice
StatusEl código HTTP de respuesta (200 = éxito, 404 = no encontrado, 500 = error del servidor).
ResponseEl contenido exacto que devolvió el servidor — útil para ver si el JSON viene con el formato esperado.
HeadersLas cabeceras enviadas y recibidas — útil para depurar problemas de CORS o autenticación.
ThrottlingSimula una conexión lenta (3G, por ejemplo) para probar cómo se comporta tu página con mala señal.
Preserve logMantiene el historial de peticiones aunque la página navegue a otra URL o se recargue.

🟢 El filtro "Fetch/XHR"

Si solo te interesan las peticiones que hace tu propio JavaScript (no imágenes, CSS o fuentes), usa el filtro "Fetch/XHR" en la parte superior del panel Network para quitar todo el ruido visual y ver solo lo relevante.

Ejercicios
Para practicar lo que acabas de leer

Ejercicio 1 — Reemplaza tus console.log

Toma un proyecto tuyo con varios console.log sueltos y reemplázalos por console.table() (para arreglos de objetos) o console.group() (para mensajes relacionados).

Ejercicio 2 — Tu primer breakpoint

Agrega un debugger; dentro de una función tuya, ábrela con las DevTools abiertas, y usa F10 para avanzar línea por línea observando cómo cambian tus variables.

Ejercicio 3 — Investiga una petición real

Abre el panel Network en cualquier sitio web, recarga la página, y encuentra una petición fetch o XHR. Revisa su Status, sus Headers y su Response.

💡 Para llevarte de esta guía

Las DevTools van mucho más allá de console.log: la consola tiene métodos especializados (table, group, time), los breakpoints te dan control total sobre la ejecución sin modificar tu código, el panel Elements te deja experimentar con CSS en vivo, y el panel Network es tu primera parada para cualquier problema relacionado con peticiones al servidor.
