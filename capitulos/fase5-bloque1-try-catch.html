Vocabulario nuevo
Las cuatro palabras de este bloque

🧠 Piénsalo así

try es como decir "voy a intentar cruzar este puente". catch es la red de seguridad que te atrapa SI el puente se rompe, en vez de dejarte caer. Sin esa red, un solo tablón roto (un error) tira toda tu aplicación; con ella, te recuperas y sigues.

🧨
Error
Algo que salió mal mientras se ejecutaba tu código
🛡
try
El bloque de código que "intentas" ejecutar
🥅
catch
El bloque que se ejecuta SI algo del try falla
📢
throw
Cómo TÚ provocas un error a propósito, con tu propio mensaje

PARTE 1 — try / catch
La estructura básica
JStry { const datos = JSON.parse("esto no es JSON válido"); console.log("Esto nunca se imprime"); } catch (error) { console.log("Algo salió mal:", error.message); }
Parte¿Qué hace?
try { }El código que quieres ejecutar. Si TODO sale bien, catch ni se toca.
catch (error) { }Si CUALQUIER línea dentro de try falla, la ejecución salta inmediatamente aquí — se salta el resto del try.
error.messageEl objeto error que JavaScript te da automáticamente trae una propiedad message con la descripción del problema.

💡 ¿Ya habías visto esto?

Sí — en el Bloque de fetch, await fetch(...) puede fallar (sin internet, URL mala). Por eso ese código ya iba envuelto en try/catch, aunque en ese momento no lo explicamos a fondo.

💡 Qué observar

Cuando eliges "Código sin errores", el bloque try se ilumina en verde y catch se queda gris — nunca se ejecuta. Con cualquier otro error, try se detiene a la mitad y catch se activa en rojo con el mensaje real que da JavaScript.

📢
PARTE 3 — throw: crea tus propios errores
Para cuando TÚ decides que algo es un error, aunque JavaScript no se queje
JSfunction dividir(a, b) { if (b === 0) { throw new Error("No se puede dividir entre cero"); } return a / b; } try { console.log(dividir(10, 0)); } catch (error) { console.log(error.message); }
Parte¿Qué hace?
throw new Error("...")Detiene la función inmediatamente y "lanza" un error con tu propio mensaje — como si fuera uno de JavaScript, pero con el texto que tú elegiste.
¿Por qué es útil?Dividir entre cero NO da error automático en JavaScript (da Infinity) — pero si TÚ decides que en tu app eso es un problema, throw te deja tratarlo como uno.

⚠️ Un throw sin try/catch SÍ rompe tu código

throw por sí solo detiene todo, igual que cualquier otro error. Solo es "seguro" si está dentro de un try con su catch correspondiente listo para atraparlo.

💡 Bonus: finally

Puedes agregar un tercer bloque, finally { }, que se ejecuta SIEMPRE — haya habido error o no. Se usa para cosas como "ocultar el mensaje de cargando", sin importar si la petición funcionó o falló.
