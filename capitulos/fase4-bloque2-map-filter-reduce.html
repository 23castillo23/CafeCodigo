Antes de empezar: recordatorio rápido
Lo que ya sabes del Bloque 1

Ya sabes recorrer un arreglo con for, y escribir arrow functions cortas. Este bloque une ambas cosas: .map(), .filter() y .reduce() son métodos que YA incluyen el bucle por dentro — tú solo les dices, con una arrow function, qué hacer con cada elemento.

📖
Vocabulario nuevo
Tres métodos, un patrón en común

🧠 Piénsalo así

Imagina una fábrica con una banda transportadora de cajas (tu arreglo). .map() es una estación que ABRE cada caja y la transforma (le cambia el contenido). .filter() es un inspector que deja pasar solo algunas cajas y descarta otras. .reduce() es la estación final que junta TODAS las cajas en un solo resultado.

🔄
.map()
Transforma cada elemento y regresa un arreglo NUEVO del mismo tamaño
🔍
.filter()
Deja solo los elementos que cumplen una condición
➕
.reduce()
Combina todo el arreglo en UN SOLO valor
📞
Callback
La función que le pasas a estos métodos para decirles qué hacer
🔄
PARTE 1 — .map()
Cambia la operación y mira el arreglo transformarse
JSconst numeros = [1, 2, 3, 4]; const dobles = numeros.map((n) => n * 2); console.log(dobles); // [2, 4, 6, 8]
Parte¿Qué hace?
.map((n) => n * 2)Por cada elemento n del arreglo, ejecuta esa arrow function y guarda el resultado en un arreglo NUEVO.
numerosQueda EXACTAMENTE igual — .map() nunca modifica el arreglo original, siempre crea uno nuevo.

🔍
PARTE 2 — .filter()
Cambia la condición y observa qué se queda y qué se va
JSconst numeros = [1, 2, 3, 4, 5, 6]; const pares = numeros.filter((n) => n % 2 === 0); console.log(pares); // [2, 4, 6]
Parte¿Qué hace?
.filter((n) => n % 2 === 0)Por cada elemento, revisa si la condición da true. Si es true, lo mantiene; si es false, lo descarta.
Diferencia con .map().map() SIEMPRE regresa el mismo número de elementos (transformados). .filter() puede regresar MENOS elementos (o ninguno).
.filter() →

💡 Se ven tachados los que no pasaron

En el arreglo de "antes", los números tachados en rojo son los que .filter() descarta con la condición actual — así ves exactamente cuáles sí cumplen y cuáles no, antes de ver el resultado final.

➕
PARTE 3 — .reduce()
El más distinto de los tres — míralo paso a paso
JSconst numeros = [1, 2, 3, 4]; const total = numeros.reduce((acumulador, actual) => acumulador + actual, 0); console.log(total); // 10
Parte¿Qué hace?
acumuladorVa guardando el resultado acumulado hasta el momento — como una "bolsa" que va creciendo.
actualEl elemento del arreglo en el que va la vuelta actual.
, 0El SEGUNDO argumento de .reduce() — el valor inicial del acumulador, antes de empezar.

acumulador:

0

⚠️ Es el que más cuesta entender al principio

Es normal que .reduce() te tome más tiempo que los otros dos — hasta programadores con experiencia a veces lo tienen que revisar dos veces. Presiona "Siguiente paso" varias veces seguidas y verás el patrón: el acumulador siempre carga el resultado de la vuelta anterior.

💡 Se pueden encadenar

Como cada uno regresa un arreglo nuevo, puedes conectarlos uno después de otro: numeros.filter(...).map(...) — primero filtra, y al resultado le aplica map. Pruébalo con el tercer botón de arriba.
