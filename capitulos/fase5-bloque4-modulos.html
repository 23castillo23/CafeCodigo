Antes de empezar: recordatorio rápido
Todo lo que has hecho hasta ahora vivía en UN solo archivo

Hasta ahora, todo tu HTML, CSS y JavaScript ha vivido en un solo archivo .html, con un solo <script>. Eso funciona bien para aprender, pero en proyectos reales más grandes, el código se divide en varios archivos .js — uno por tema (uno para las tareas, otro para validaciones, etc.). Los módulos son la forma en que esos archivos se "hablan" entre sí.

📖
Vocabulario nuevo
Dos palabras, una en cada archivo

🧠 Piénsalo así

Es como prestar un libro. export es "este libro está disponible para prestar" — lo marcas como público. import es "quiero ese libro específico de esa biblioteca" — lo pides desde otro lugar. Sin export, nadie de afuera puede usar lo que escribiste en ese archivo.

📤
export
Marca una función, variable o clase como disponible para otros archivos
📥
import
Trae algo exportado desde otro archivo, para usarlo aquí
⚠️
Antes que nada: una limitación importante
Este bloque es distinto a todos los anteriores

⚠️ Aquí no puedo darte un laboratorio 100% en vivo como los anteriores

Todos tus bloques anteriores funcionaban abriendo un solo archivo .html directo desde tu carpeta (doble clic). Los módulos de JavaScript no funcionan así — por seguridad, los navegadores bloquean los import entre archivos cuando abres un HTML directamente desde tu computadora (protocolo file://). Necesitas un servidor local, aunque sea muy simple, para probarlos de verdad. Te explico cómo abajo, en la Parte 3.

📤
PARTE 1 — export e import
Dos archivos, conectados
tareas.jsexport function crearTarea(texto) { return { texto, completada: false }; } export const MAX_TAREAS = 50;
main.jsimport { crearTarea, MAX_TAREAS } from "./tareas.js"; const t1 = crearTarea("Aprender módulos"); console.log(t1, MAX_TAREAS);
Parte¿Qué hace?
export function ...La palabra export antes de cualquier declaración la hace disponible para otros archivos.
import { crearTarea } from "./tareas.js"Las llaves listan EXACTAMENTE qué quieres traer, y from indica de qué archivo — con ./ al inicio, porque es una ruta relativa a la carpeta.

💡 export default

Si un archivo exporta UNA sola cosa principal, puedes usar export default — y al importarla no necesitas llaves ni que el nombre coincida exactamente:

tareas.jsexport default function crearTarea(texto) { /* ... */ }
main.jsimport crearTarea from "./tareas.js"; // sin llaves

PARTE 3 — Cómo probarlo de verdad
Necesitas 3 archivos y un servidor local, así de simple

Estructura de carpeta que necesitarías:

📁 mi-proyecto/
📄 index.html
📄 main.js
📄 tareas.js
index.html<script type="module" src="main.js"></script>
Detalle¿Por qué importa?
type="module"Sin esto, el navegador no permite usar import/export en ese script.

Y para el servidor local (elige UNA opción, solo necesitas correrlo una vez por sesión de trabajo):

  • VS Code: instala la extensión "Live Server" → clic derecho en index.html → "Open with Live Server".
  • Si tienes Python instalado: abre una terminal en la carpeta del proyecto y escribe python -m http.server, luego abre http://localhost:8000 en tu navegador.

💡 ¿Por qué tanto rollo por esto?

Porque es exactamente cómo funcionan los proyectos reales — casi ningún sitio web en producción tiene todo en un solo archivo. Aprender esto ahora, aunque requiera un paso extra, te prepara para trabajar en proyectos de verdad más adelante.

PARTE 4 — Retos para practicar
Estos sí necesitas hacerlos en tu computadora, con archivos reales
🟡 Fácil

Reto 1 — Tu primer módulo

Crea saludos.js con una función saludar(nombre) exportada, e impórtala en main.js para usarla. Pruébalo con un servidor local.

🟠 Medio

Reto 2 — Exporta tu clase Tarea

Mueve tu clase Tarea (de la Fase 5) a un archivo tarea.js, expórtala, e impórtala en tu main.js para crear instancias ahí.

🔴 Avanzado

Reto 3 — Divide tu lista de tareas

Toma tu proyecto de la lista de tareas y sepáralo en tareas.js (la lógica: agregar, eliminar, guardar) y main.js (conectar con el DOM). Es un buen ejercicio de organización real.
