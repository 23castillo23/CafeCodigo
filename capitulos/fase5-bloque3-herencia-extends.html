Antes de empezar: recordatorio rápido
Lo que ya sabes de clases

Ya sabes crear una class con constructor, propiedades con this, y métodos. Ahora imagina que quieres una clase TareaUrgente que sea CASI igual a Tarea, pero con una propiedad extra (fechaLimite). En vez de copiar y pegar todo Tarea de nuevo, la herencia te deja decir "esta clase es como esa otra, más esto".

📖
Vocabulario nuevo
Tres piezas para heredar de otra clase

🧠 Piénsalo así

Piensa en "Vehículo" como una clase padre, y "Auto" como una clase hija. Un Auto ES un Vehículo (tiene ruedas, se mueve), pero además tiene cosas propias (número de puertas). La herencia evita que tengas que redefinir "tiene ruedas, se mueve" cada vez que creas un tipo nuevo de vehículo.

👪
Clase padre
La clase original, más general (ej. Tarea)
👶
Clase hija
La clase que hereda de la padre y le agrega cosas propias
⬡
extends
La palabra que conecta la clase hija con su clase padre
⬆️
super()
Llama al constructor de la clase padre desde la hija
⬡
PARTE 1 — extends y super()
La sintaxis básica de herencia
JSclass Tarea { constructor(texto) { this.texto = texto; this.completada = false; } } class TareaUrgente extends Tarea { constructor(texto, fechaLimite) { super(texto); this.fechaLimite = fechaLimite; } } const t1 = new TareaUrgente("Entregar reporte", "2026-09-20"); console.log(t1.texto); // "Entregar reporte" (heredado) console.log(t1.fechaLimite); // "2026-09-20" (propio)
Parte¿Qué hace?
extends TareaTareaUrgente hereda TODO lo de Tarea: sus propiedades y sus métodos.
super(texto)Llama al constructor de Tarea, pasándole texto — así this.texto y this.completada se configuran igual que en la clase padre, sin repetir código.
this.fechaLimite = ...Después de super(), agregas lo que es EXCLUSIVO de TareaUrgente.

⚠️ super() siempre va primero

Si tu clase hija tiene constructor, la primera línea DEBE ser super(...) — antes de usar this para cualquier otra cosa. JavaScript te va a dar error si lo olvidas.

PARTE 3 — Sobrescribir un método
La clase hija puede reemplazar el comportamiento del padre
JSclass Tarea { describir() { return `Tarea: ${this.texto}`; } } class TareaUrgente extends Tarea { describir() { return `🔥 URGENTE — ${this.texto}`; } }
Parte¿Qué hace?
Mismo nombre de métodoAl definir describir() otra vez en TareaUrgente, REEMPLAZA la versión del padre — solo para instancias de TareaUrgente.
Las instancias de TareaSiguen usando la versión original — sobrescribir en la hija no afecta al padre.

💡 ¿Por qué es útil?

Te deja reutilizar la mayoría del comportamiento (todo lo que NO redefines) y cambiar solo lo que necesita ser distinto — en vez de escribir la clase completa desde cero.
